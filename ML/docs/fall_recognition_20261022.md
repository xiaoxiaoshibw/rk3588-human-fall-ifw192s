# 离线跌倒候选识别：因果输入、弱监督与真实人员留出

接续用户“持续开发直到完成跌倒识别”，本轮明确授权公开数据下载和本地训练，不部署、不采集。证据根为 `docs/evidence/2026-10-22_fall_candidate/`；现场生产版本和 `confirmed` 不变。

## 1. 本地识别链

原始 `points.bin` → 现有完整检测/跟踪/几何链 → 当前实测锁定目标行 → 逐帧 XYZ 特征 → 10–30 帧因果上下文 → 二分类窗口分数 → 连续窗口投票 → `ml_fall_candidate` 事件。

`fall_candidate_runtime.py` 接收当前目标的实际点，不另外找最大簇，不使用预测点。身份、时间 epoch、动作代际、选择版本和标定都绑定到缓存；非法帧、非实测状态、时间重复/倒退/断档打断连续窗口。换目标/代际/标定清空事件历史；同目标观测空缺打断票数但保留尚未恢复的事件锁存，避免同一事件反复发出。

固定候选规则是分数 ≥0.8 连续 3 个有效窗口；分数 ≤0.2 连续 5 个窗口才释放。窗口高度重叠，3 票不是 3 个独立统计样本；也没有把票数换算为真实跌倒持续时间。事件绑定模型和配置 SHA、源时间及完整目标上下文，不能将两个模型或配置的事件混为一个。

推理只依赖 stdlib+NumPy，支持已有 RF 数值导出和新增 114→64→16→1 MLP 数值导出。拒绝错误标签映射、错误 schema、模型 SHA 不符、非法数值与未声明格式。实验事件始终 `physically_verified=false`、`confirmed_enabled=false`，不会写回原几何/跌倒状态。

## 2. 为什么不直接把序列标签当逐帧跌倒

现有公开标签只表明整段动作类别。正片段里可能先站立、再下降、最后倒地；把全部短窗口标为跌倒会强迫模型把准备动作也视为阳性。

主模型采用多实例学习：每个完整片段是一个 bag，训练损失只监督该 bag 的最大窗口 logit。正 bag 需要某个窗口提供阳性证据；负 bag 约束所有窗口。训练不产生伪逐帧 GT，也不声称最大分数窗口就是实际跌倒起点。归一化只拟合训练人员/组窗口；固定 seed42、AdamW 0.001/weight decay0.01、40 轮、batch16 bags，不看留出选轮。

同网络监督对照保持输入、网络、优化器、seed、分组和轮数不变，只将 bag-max 损失换成逐窗口继承标签的 BCE，并在每个 bag 内平均。该对照保留为失败证据，不作为部署模型。

## 3. 合成集实际结果

原包 900 序列、65,473 个实际入模帧，所有成员重读后与原逐序列内容 SHA 一致；14 个同帧副本不重复入组且未删除。451 条 fall、449 条 nonfall。原 5 折按 18 个父动作目录隔离，**不是人员隔离**；底层动画谱系和近重复仍 UNKNOWN。非跌倒包括饮水、跑、坐、深蹲、站立、走、伸展等目录，不只有走动。

| 实验 | 检出 fall /451 | 触发的 nonfall /449 | 性质 |
|---|---:|---:|---|
| 旧完整序列 RF，固定 30 帧滑窗 | 349 | 0 | 不重训，存在输入分布变化 |
| 旧 RF，积累上下文、最多 256 帧 | 447 | 0 | 失败后的探索性对照，非新独立验证 |
| 专门短窗 RF | 437 | 112 | 漏检14条，误触发较多，保留 |
| 同网络逐窗监督 MLP | 451 | 193 | 弱标签监督对照，未采用 |
| **bag-max MIL** | **450** | **12** | 固定事件规则下漏1条、误触发12条 |

这些是“一个完整片段是否至少出现一个候选”的统计，不是逐帧 accuracy、跌倒起点召回或每小时误报率。旧完整序列分类 99.67% 不等于在线候选成绩。多因素跨模型比较不单独归因；监督方式的影响由同网络对照支持，仍限于这套合成数据。

NumPy 与 PyTorch 在全部 57,373 个合成留出窗口上最大概率差 1.79e-7，0.2/0.5/0.8 三个阈值的全部判断一致。运行器已在禁止导入 torch/sklearn/joblib 的独立进程中加载与推理；原生板端 Python3.8/NumPy1.17 执行和性能仍 UNKNOWN。

## 4. 真实 LiDAR 实验协议

使用 [LaserAct v1.1](https://raphaelmemmesheimer.github.io/laseract/) 作者公开 person 包及核心标签/人员划分。主传感器 Velodyne；作者的人体裁剪来自相机机器提取，是 actor 点集输入，不是独立点级人体真值；交互片段可能含多名 actor。仅精确动作名 Falling 为正，其余48类动作（包括 Lying、Stumbling）为负。

官方人员划分是5人训练1430条、4人测试911条，Falling训练16条、测试14条；训练正例12条来自同一人，必须单列逐人和逐动作统计。点数不足、空裁剪、缺流和时间断档保留在审计中；不可观测正例不能从总14条分母中删除。

训练前登记见 `PREREGISTRATION_REAL.json`。主模型是 bag-max MIL，RF 是固定对照；不按测试结果选阈值/epoch。完整 person 包已下载 4,602,081,280 B，并匹配作者 SHA `2c2229a943cd02d2c5a73e2a27ec5083ee9f04ad313bdd248f113db7dedf2644`。旧部分包和本轮第一份下载均保留，完成包为 `data/downloads/fall_recognition_20261022/laseract_person_r2.tar`。

真实结果如下，分母保留全部14条 Falling；非跌倒误触发只在可观测输入上统计，未知片段不算正确负例。

| 视图/模型 | 检出 Falling /14 | 可观测 Falling | 非跌倒触发/可观测非跌倒 | 说明 |
|---|---:|---:|---:|---|
| Velodyne RF | 0 | 12 | 0/889 | 均值分类可认出6条，但固定事件规则下未触发 |
| **Velodyne MIL 主实验** | **8** | **12** | **1/889** | 初始官方人员留出结果；全分母召回57.14%，候选precision8/9 |
| Cepton MIL | 6 | 11 | 2/886 | 后续同事件视图探索，不是新增独立测试 |
| Livox三包聚合 MIL | 7 | 13 | 1/893 | 后续同事件视图探索，不是新增独立测试 |

不能用99%以上的总体accuracy宣布成功：正例少且类分布极不平衡。主实验漏掉6条，其中2条没有满足连续有效观测的窗口，另4条有输入但未触发；唯一假阳性是 `S12A20T02` 的 Lying。P05的6条Falling全部检出，P04为2/5，P06为0/2，P09为0/1，人员差异明显。完整记录见 `laseract_mil/fold_xsub_sequences.json` 和 `LASERACT_PRIMARY_FAILURES.json`。

Livox原始流是30Hz扫描包，作者建议合并3包形成完整模式。单包路径在全部训练正例上连续有效帧最多仅2帧，因此首次训练明确停止，没有训练一个单类“成功模型”。修复后按 `(0,3),(3,6),…` 只合并已经消费的实际源包，用最后一包时间戳；源包点数、时间和跨度均入账，包内长断档仍UNKNOWN，不造点、不跨缺口拼人。回归验证追加未来包不会改变先前聚合帧。此修复改善输入契约，不等于证明Livox迁移到IFW192S。

训练侧校准另用官方训练5人逐人留出，外部4人从规则选择中完全排除。固定0.8/3票时，训练LOPO仅检出3/16条Falling；21组预设规则都未满足本次研究预先设定的“每人可观测非跌倒片段触发≤1%”预算。这个预算不是项目验收门或现场安全标准。程序返回 `NO_SUPPORTED_RULE`、不发布校准规则，原模型/规则保持；没有拿测试错误挑一套好看的阈值。四个官方测试人员在后续已观察，未来复测须标探索性。

以上说明**离线候选链已实现，但可靠跌倒识别目标尚未达成**。不能通过补零、放松事件阈值或删除未知正例补齐缺失的真实观测与泛化证据。

## 5. 复现与使用

所有输出/模型目录必须换成新路径，不覆盖历史证据或旧模型。

```powershell
python -B -W error -m unittest discover -s ML/src -p test_*.py
python -B -W error ML/src/train_fall_mil.py --input docs/evidence/2026-10-22_fall_candidate/synthetic_causal_cache --output docs/evidence/<new-run>/fit --models ML/models/<new-model> --epochs 40
python -B -W error ML/src/replay_fall_candidate.py --session data/sessions/cap_20261018_110029 --manifest ML/models/fall_mil_20261022/fold_0.json --output docs/evidence/<new-run>/replay
```

应用侧调用 `FallCandidateRuntime(manifest).push(actual_target_xyz, source_timestamp, identity, generation, calibration, observed=...)`；其中 observed 仅在当前目标锁定、不是预测且有实际点时为 true。所有绑定来自同一帧现有跟踪结果，不能把另一个人的历史或关节 GT 移入输入。训练期 PyTorch/sklearn 依赖留在 PC。

目前缺少与 IFW192S 录制绑定的独立动作/跌倒真值，传感器轴/物理标定与原生板端性能也未验证。公开集动作分类和本地软件回放通过不能补齐这些证据，IFW192S真实跌倒效果保持 UNKNOWN；本轮没有部署或采集。

最终回归：34项ML、705项核心、69项capture均 `-B -W error` 通过。多个模型对原始386帧完整回放，完整result/baseline SHA均为 `6aa6629066956d9949e4188d8c31b1ea69ed6214d0b4a112b1c8924359a21017`；10帧最小上下文的模型有249个就绪窗口。原始点行、目标跟踪、区域/姿态与原跌倒状态保持，不拿旁路没有触发来证明真实误报率为0。旧权重与生产源码SHA检查保持；模型、日志、失败、校准拒绝和源码绑定均留在本轮证据中。
