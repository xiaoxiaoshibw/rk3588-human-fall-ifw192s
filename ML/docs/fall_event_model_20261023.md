# 事件时序模型离线接口与未训练数值验证

本轮把事件缓存、PC端GRU、纯NumPy逐帧运行时和原始会话回放接通。**没有执行训练或优化器更新，没有可用的新跌倒模型效果结论。** 所有新增权重均为固定seed的随机初始化数值夹具，manifest明确标记 `untrained_validation_fixture`，运行时禁止其发出候选。

## 输入与监督

- 输入8项：地面相对质心高度、主轴倾角、垂直跨度、垂直速度、点数、实际dt、observed、valid。点数先log1p，再用训练人员有效测量的均值/尺度归一化。原缓存仍为NaN+mask；网络入口使用均值位置和8个独立可用性位，共16通道。缺失不能冒充实测零值；Inf/复数/不一致mask拒绝。
- 缓存新增首次接触 `event_impact`、certainty和时钟不确定度，全部事件时间采用 `LiDAR秒=视频秒+offset`。旧缓存缺少这些字段时，拟合预检要求重建。
- 正例损失只覆盖 confirmed、observable 的跌倒开始至首次接触，区间两端按时钟不确定度内缩；已明确标注的非跌倒动作才给负例。事件后的倒地静止、片段其余部分和不确定标注不自动变负例。连续段最初0.5s只作上下文，不计算损失。
- 不能使用的事件仍保留在逐事件audit；不用于损失不等于从独立评测分母删除。正式评测仍由 `evaluate_fall_events.py` 对全部confirmed真值事件算端到端召回。

## 数值与因果状态

`train_event_model.py` 的PC模型是单层8隐元GRU加线性头；`event_model_numpy.py` 只依赖stdlib+NumPy。门次序与候选计算按[PyTorch官方GRUCell定义](https://docs.pytorch.org/docs/2.14/generated/torch.nn.GRUCell.html)实现，reset作用于含偏置的整个隐藏候选项。

人员/动作代次/标定改变均重置隐藏状态和事件绑定；断档、非递增时间、无观测和坏输入清除时序上下文。UNKNOWN不证明恢复，不用断档拼接保持时间。输入依赖当前和历史帧，不读未来帧。默认预热0.5s、最大断档0.5s、模型历史2s；高/低阈值0.8/0.2，纯时序模式候选保持0.3s、恢复保持0.5s，均以秒计算。

manifest显式选择 `geometry_gate`（几何新候选与近期有效模型分数相结合）或 `temporal_only`。预热期间的分数不进入门控历史；事件ID绑定模型、流和运行序号。任何模式均不启用confirmed告警。单元检查中的常数分数替身只验证控制分支，不是训练后的探测器。

## 预检与尚未运行的拟合入口

`train_event_model.py --index <index.json> --output <new-dir>` 默认只预检。index列出非空且互不相交的train/validation/test人员ID及缓存路径；逐文件检查来源SHA、重复会话/内容，训练数组检查掩码、连续段和时钟。人员隔离资格仍是metadata-declared，不冒称独立身份核验。预检只加载train数组用于监督与归一化，held-out记录仅读元数据及文件SHA。

模块另含显式 `--train` 拟合入口：固定种子、固定最终epoch、2s截断反传但保留同段因果隐藏状态，不跨无效段。**该分支本轮未运行，优化器/收敛/真实模型质量均未验证。** 本轮不因此宣布M5完成。实际拟合、固定人员测试集上的几何/模型/组合对照仍待执行。

`fall_candidate_runtime.load_candidate_runtime`按manifest选择新任务；旧RF/MIL类的AST与前件一致。`replay_fall_candidate.py`统一传入显式地面，新旁路不写入原感知输出。

## 已验证的证据

机器产物：`docs/evidence/2026-10-23_fall_event_model/`，最终产物在 `verified/`，汇总 `CHECKS.json`。早期夹具导入名称错误及修复前产物保留，未覆盖历史证据。

- ML136、核心705、capture69、标定2项均 `-B -W error` 通过。包括float64/float32导出、NaN掩码、时钟/人员/标定断开、模型SHA篡改、未知标签保留和人员泄漏拒绝。
- 3个解析合成人员的几何账本→注释→缓存→CLI预检接通；训练侧4个明确正例帧、9个明确负例帧，保留2个事件，仅软件夹具，不是真实训练数据充分性证明。
- 随机初始化GRU512步、4次重置：当前Python3.12/NumPy1.26与隔离本地Python3.8.10/NumPy1.17.4对PyTorch参考最大概率差均1.11e-16、隐藏差2.22e-16；纯NumPy运行时未导入torch。另有float32导出按1e-6容差通过。不是ARM/ROS或板端性能结论。
- 同一41帧解析合成账本的缓存编码与逐帧运行时编码，在两个NumPy版本均逐值核对通过，避免训练/推理的dt、缺测和特征次序漂移。
- IFW原始386帧：未训练新旁路253帧有诊断分数、候选0（受状态强制禁止），旧MIL旁路249个就绪窗口。两者开关前后完整输出SHA均 `6aa6629066956d9949e4188d8c31b1ea69ed6214d0b4a112b1c8924359a21017`。不能把随机分数/禁止发报的0候选当成效果或低误报。
- 新旁路PC计时p50约0.421ms/p95约0.685ms，只是这次PC回放的局部开销，不可外推板端吞吐。514个既有生产路径SHA保持。
