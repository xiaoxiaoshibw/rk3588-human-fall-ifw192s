2026-10-23 原始深度续作：70 段 PNG16 原始链与来源核对已完成，底部四分之一地面输入变体及遮蔽角度后的测量连续性修复形成 28/30 参考窗命中、1/40 日常触发的开发结果；它使用标称内参，不是目标域或独立人员成绩。细节见 [原始深度记录](../ML/docs/urfall_raw_depth_20261023.md)。M3–M6 和物理资格尚未完成，不以此标记总目标完成。

本计划接在 [ML/docs/fall_observation_20261022.md](../ML/docs/fall_observation_20261022.md) 之后。那一轮查明：公开集 LaserAct 的 30 条 Falling 里 26 条整段不含下降过程，测试 14 条里只有 1 条能看到直立姿态，所以「8/14」测的是卧姿而不是跌倒。本计划解决的是**证据从哪来、怎么处理、怎么判、代码怎么改**，顺序不可颠倒：先让事件可观测，再谈模型。

## 0. 目标与判定

在 IFW192S 上做出可判定的跌倒识别，验收口径是**事件级**，不是窗口或帧级：

| 指标 | 口径 | 目标（待真实数据验证，不是承诺） |
|---|---|---|
| 端到端事件召回（主指标） | 分母 = 全部已确认真值跌倒事件，包括掉锁/不可观测事件 | ≥ 0.80 |
| 可观测子集召回（诊断） | 依据独立观测记录，不能依据几何阈值或模型输出筛选 | 与主指标同时报告 |
| 误报率 | 非跌倒长时活动，次/小时 | ≤ 1.0（先给量级，再谈收紧） |
| 检出延迟 | 事件起点 → 首次报警 | ≤ 1.5 s |
| 人员泛化 | 留出人员逐人报告，不用总体均值隐藏整人漏检 | 有留出人员全部漏检时不得宣称泛化通过 |

不可观测和掉锁事件保留在端到端分母，并给出原因、占比。另报独立观测子集的条件召回。原始雷达可见、提取器成功、几何规则成立分别记录；不能把“没有通过几何阈值”解释为“传感器没有看到人”。未知真值与 probable/rejected 单列，不能当负例。

## 1. 数据从哪里来

三条腿，用途严格分开：**自采是唯一能作为效果证据的来源**，公开集只用于开发与回归，合成集只用于预训练和压力测试。

### 1.1 自采（IFW192S，唯一验收来源）

协议见 [FALL_CAPTURE_PROTOCOL.md](FALL_CAPTURE_PROTOCOL.md)。规模下限：

- 受试者 **≥ 10 人**（身高 1.50–1.90 m，含至少 2 名体型差异明显者），每人独立编号，采集时只记编号不记姓名。
- 受保护的表演跌倒事件 **≥ 60 次**：每人前倒/左侧/右侧/后倒/坐椅前滑/扶墙滑落各 1 次，共 6 次；10 人合计前倒 10、侧倒 20、后倒 10、椅滑 10、墙滑 10。是否适合执行由现场负责人确定；辅助接住事件单列，不能冒充完整落地。
- 易混负例 **≥ 200 段**：主动躺下、快速坐下、弯腰捡物、蹲下起立、跪姿、系鞋带、伏地、爬行、搬重物、转身急停。
- 日常长时活动 **≥ 20 h**（多人、多时段、含进出画面、空场、遮挡），用于估计每小时误报；要给出可信区间，建议 ≥ 60 h。
- 每段都产出 `fall_events_v1` 标注（见 §3），事件表与视频同步（拍手对齐，偏移和不确定度写进标注）。

视频只做人/时/动作的真值，不作为模型输入；现场没有人体点级 GT，这一点不因本计划改变。

### 1.2 公开集（开发期与回归，不作验收）

| 来源 | 现状 | 用途 | 限制 |
|---|---|---|---|
| LaserAct | 已有（person 包 + core 包） | 完整片段做下降回归，其余保留为事件上下文未知/卧姿表征 | 不把 Falling 改成负例；片段标签不足以建立端到端事件真值 |
| UR Fall Detection | 已核实页面与许可（CC BY-NC-SA 4.0）：70 段（30 跌倒 + 40 日常），Kinect 深度 + RGB + 加速度，**逐帧姿态标签（-1/0/1，含"正在跌倒"过渡帧）** | 用它验证几何链与事件起点检测（depth→点云） | 深度相机不是 LiDAR；受试者少；机房环境 |
| 合成动画集 | 已有 900 段（451 fall） | 预训练、长尾、压力测试 | 动画谱系 UNKNOWN，不是真人 |
| MM-Fi | 已有 | 动作分类对照 | 无跌倒类 |

任何新的点云/深度跌倒集，先做格式/真值/时间检查，再跑几何诊断。诊断失败的输入仍入账，不能据此删除真实困难事件：

```powershell
python -B -W error ML/src/fall_dataset_gate.py --clips <clips_dir> --manifest <manifest.csv> --out <out_dir>
```

几何诊断判「当前特征是否呈现直立→中间姿态→低姿态」：主轴与已声明 +z ≤30°、随后 ≥65° 且跨度 ≤1.10 m；必须同一连续段且有中间姿态。`NEVER_UPRIGHT` 只是规则没有找到直立证据，不证明物理不可见。不能据此改变真值、评测分母或筛掉失败采集；这组阈值不保证排除所有双人裁剪。

### 1.3 合成（用真实背景 + 合成人体）

在 IFW192S 的真实场景点云里注入合成刚体下跌/蹲下（已有 `fall_fast_walking` 等做法），用于：极小样本下的形状先验、边界压力测试、以及"模型是否只学了低姿态"的诊断。**不作为效果证据**，报告里必须与真人事件分开。

## 2. 数据处理链

```
采集(REST/record_session) → data/sessions/<sid>/{meta.json, points.bin}
  → 现有检测/跟踪/几何链 → 锁定目标逐帧点集（实测行，非预测）
  → 逐帧证据：重力/地面、质心高度、姿态角、形状、观测质量
  → 事件候选（连续证据 + 真实 dt） → 与 fall_events_v1 对齐 → 训练/评测缓存
```

关键约定：

- **时间用秒不用帧**。今天已测出「30 帧」在 7 Hz/10 Hz 上分别是 4.3 s/3.0 s；所有窗口、保持时长、延迟都以秒和真实时间戳计算，丢帧按时间断档处理。
- **观测质量显式入账**。`observed`（实测锁定且非预测）、点数、断档、来源行号保留；缺测量用 NaN + mask，不补造零值。时序证据在断档处打断；同目标已锁存事件不因缺测而当作恢复。
- **坐标系**：`geometry.yaml` 是拟合参数而非实测平面；运行时须绑定显式地面/重力工件与坐标。缺标定输出 UNKNOWN，不从未来帧拟合。后续若增加地面拟合，必须显式预热并保存适用域、残差及物理资格。
- **事件对齐**：约定 `LiDAR秒 = 视频秒 + offset_s`，保存偏移和实测不确定度；拍手必须在两路中可定位，否则不能假定 ±0.15 s。超过 0.2 s 的段不能提供已确认的精确时序成绩。

缓存格式沿用现有习惯（`frames.npz` + `INPUT.json` + `MEMBERS.json`，逐成员 SHA），每个缓存绑定源会话 SHA、标注 SHA、代码 SHA。

## 3. 如何观测（评测协议）

1. **单位是事件**。一次跌倒 = 一个事件；躺在地上 30 s 仍是一个事件。
2. **分母分两层**：主指标 `all_events` 保留全部已确认真值事件；`observable_events` 仅作诊断，必须有独立于算法规则的观测依据。UNKNOWN 真值单列，不把规则失败重命名为不可观测。
3. **误报按小时**：只用显式标注的非跌倒监测区间做分母；UNKNOWN 监测时段保留在总时长，同时报告观测覆盖率，防止掉锁降低误报。短负片段触发比例与长时误报分列。95% Poisson 区间仅作事件率描述，不能忽略同人/场景相关性。
4. **划分**：人员隔离，固定写进 `PREREGISTRATION`；同一人的不同 take 不跨训练/测试。先冻结划分与阈值选择规则，再看测试结果。
5. **对照**：固定划分下跑四组——只改算法 / 只加数据 / 同时改 / 都不改（基线），用来判断收益归因。
6. **禁止**：用测试集调阈值；把"未观测"当负例；把窗口票数当独立样本；用合成或公开集的分数替代现场效果。
7. **事件匹配**：报警和真值一对一，允许范围为 `[t_start, t_impact + 1.5 s]`，按报警时间和最早截止事件匹配；同窗多余报警单列 duplicate。起点后 ≤1.5 s 的及时检出另报，不能与任意时刻命中混淆。匹配参数在测试前冻结。
8. **预算**：几何基线低位保持 0.3 s、下降证据最长 2.0 s、断档阈值 0.5 s、恢复 0.5 s，均为未验证开发起点。1.5 s 总延迟必须包括采样、保持、队列和计算；PC 推理耗时不等于端到端或板端延迟。

## 4. 代码改动

### 4.1 架构调整（先改结构，再换网络）

现有链路是「每帧 19 维统计 → 114 维窗口特征 → 小型 MLP → 连续窗口投票」，它把「发生了什么」压成「这 30 帧像不像跌倒」，窗口还按帧数计。计划改成三层，每层可单独验证：

```
逐帧证据（秒制）: 重力/地面 → 质心高度 h(t)、姿态角 θ(t)、形状、观测质量 obs(t)
        ↓
因果事件头: 小型 1D 因果卷积 / GRU，输入 [h, θ, 形状, dt, obs]，输出单帧「正在下降」概率
        ↓
事件锁存: 下降 + 低位保持 + 观测连续 → 事件；恢复/离地 → 释放；身份/代际/标定变化清空
```

理由：审计证明「低姿态」与「跌倒」在静态特征上同分布，只有把**过程**（高度下降、姿态翻转、保持、恢复）显式建进去才有区分度；这些量是几何的，可以先不依赖神经网络验证（M2 就用它们对 UR Fall 求事件起点）。

现在**不上**大点云网络：正例只有 60 条量级、场景单一，先上大模型只会把场景记住。等 M4 数据到位，再把点云 backbone 作为挑战者，与几何链在同一人员留出划分上对照。

## 6. 风险与诚实边界

- **表演跌倒 ≠ 真实跌倒**：受试者会保护自己、速度更慢、落地更可控。所有自采事件必须标 `staged`，结论只能写到"表演跌倒"。
- **人数仍是最硬的约束**：10 人是下限，能到 15+ 再谈泛化；单人多次重复不算独立样本。
- **深度相机 ≠ LiDAR**：UR Fall 只能验证几何链的正确性，不能外推成绩。
- **长时误报估计成本高**：20 h 只能给量级，1 次/小时以下的差异需要上百小时。
- **时钟对齐**：误差来自可定位的双路证据，不能仅因使用拍手就假定 ±0.15 s。
- **不可观测**：现场遮挡、低位贴地、贴墙都可能让目标点集消失；真值事件仍进端到端分母，输入缺失原因单列，不当负例。

以上任一项目前都没有真实数据支撑，因此 IFW192S 的真实跌倒效果、物理有效性与板端性能继续保持 **UNKNOWN**；本计划只定义怎样把它们变成已知。
