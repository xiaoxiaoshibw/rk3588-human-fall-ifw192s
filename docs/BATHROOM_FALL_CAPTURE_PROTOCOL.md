# 浴室跌倒采集协议（IFW192S 小场景变体）

日期：2026-10-23  
定位：**[FALL_CAPTURE_PROTOCOL.md](FALL_CAPTURE_PROTOCOL.md) 的浴室专用变体**。通用伦理、安全、命名、标注 schema、采后 15 分钟检查仍按母协议；本文只写浴室小场景的差异。  
性质：现场执行设计，不授权 agent 连接设备或组织采集；所有动作必须由现场负责人和保护人员确认安全后执行。

---

## 0. 为什么浴室要单独一份

浴室不是“把大房间协议缩小”。它的关键变量完全不同：

| 维度 | 大房间（母协议） | 浴室（本文） |
|---|---|---|
| 距离 | 2–8 m，越远越稀 | **0.5–3 m，越近越密**；2 m 约 2,000+ 点，3 m 约 1,000 点 |
| 视角 | 侧视/斜视，人体完整 | 角落俯视/斜俯视；马桶、浴缸、浴帘、玻璃隔断会挡 |
| 背景 | 空场模板基本够 | **浴帘开/关、浴垫、毛巾、湿地面、蒸汽**都会变；单一模板不够 |
| 主要误报 | 家具、走动 | **坐马桶、蹲下洗、跪着擦、浴帘飘动、毛巾掉落、开门** |
| 主要漏检 | 远距碎片 | **被马桶/浴缸/浴帘挡住、只露腿、贴地、玻璃/镜面** |
| 事件定义 | 跌倒过程 | **跌倒 + 长时间不起（long lie）** 才是浴室的核心风险 |
| 隐私 | 需要告知 | **极高**；优先只用点云，视频只做本地 GT |
| 硬件 | 室内干燥 | **水、蒸汽、冷凝、溅水**；传感器是否 IP 防护、装在哪，必须先确认 |

**一句话：浴室是这台雷达的“强项场景”（近、密、单人、固定布局），但也是“遮挡/环境/隐私”最难的场景。** 算法要围绕“可见部分 + 长时间不起”设计，而不是追求完整骨架。

## 1. 场景与安装

### 1.1 房间记录（每次采集必填）

- 房间尺寸（长×宽×高）、门的位置/开向、马桶/洗手台/浴缸/淋浴区/地漏位置。
- 浴帘（布/塑料）、玻璃隔断（透明/磨砂）、镜子、浴垫、毛巾架、置物架。
- 地面材质（瓷砖/防滑砖/石材）、坡度、是否湿滑。
- 传感器安装：高度、朝向（yaw）、俯仰（pitch）、roll、到各 fixture 的距离；用卷尺 + 水平仪记录实测值。
- 网络/电源：是否有网口/ PoE；线缆是否在溅水区。

### 1.2 传感器位姿（试点三选一，先固定一种）

| 方案 | 位置 | 优点 | 缺点 |
|---|---|---|---|
| **A（推荐）** | 高处角落，2.0–2.4 m，朝房间中心，俯角 20–30° | 覆盖全室；2–3 m 密度高；避开淋浴溅水 | 马桶/浴缸可能挡下半身 |
| B | 天花板中心，2.4–2.6 m，垂直向下 | 俯视无遮挡；地面接触清楚 | 躺姿透视缩短；浴缸内不可见 |
| C | 门上方，2.0 m，朝内 | 安装方便；进出可见 | 门开/关遮挡；浴帘后不可见 |

- **不要装在淋浴正上方/溅水区**；IFW192S 的防护等级需向厂商确认，未确认前按“不防水”处理。
- 传感器镜头/窗口若结露，先擦干并记录；冷凝会直接抬高无效回波。
- 每个位姿至少采一次 **空浴室 5 min**（门关、帘开/关各一次），用于背景/无效区标定。

### 1.3 环境状态矩阵（每个状态都要有“空场 + 有人”）

| 状态 | 取值 | 为什么必须采 |
|---|---|---|
| 地面 | 干 / 湿（洒水） | 湿地面反光/回波变化 |
| 淋浴 | 关 / 开（5/10/15 min） | 水花、蒸汽、冷凝 |
| 浴帘 | 全开 / 半开 / 全关 | 遮挡 + 帘子飘动误报 |
| 玻璃隔断 | 无 / 透明 / 磨砂 | 透射/反射/无回波 |
| 镜子 | 有 / 无 | 镜面鬼影/无效区 |
| 浴垫 | 有 / 无 | 贴地小目标 |
| 毛巾 | 挂好 / 掉在地上 | 误报源 |
| 门 | 关 / 开 | 遮挡 + 进出 |
| 灯 | 开 / 关 | 对雷达无直接影响，但对视频 GT 有影响 |

试点不必全组合（会爆炸）；先做 **干/湿 × 帘开/关 × 淋浴关/开** 的核心 8 组，其余在正式批补齐。

## 2. 动作清单（每人 6 次跌倒）

> 浴室跌倒不要求真实头部/髋部撞击。使用防滑垫、保护垫、保护员；能模拟就模拟，不能安全执行的动作改用假人/垫上模拟并标 `simulated=true`。**不要求在浴缸内真实跌倒。**

| # | 动作 | 场景 | 说明 |
|---|---|---|---|
| 1 | 前滑倒 | 淋浴区/湿地面 | 站立→向前滑倒，手撑垫 |
| 2 | 后滑倒 | 淋浴区/湿地面 | 站立→向后坐倒/躺倒，保护员接住 |
| 3 | 侧倒 | 浴缸边/跨门槛 | 侧向失去平衡，倒向垫子 |
| 4 | 坐马桶时晕厥/前倾 | 马桶 | 坐姿→向前/侧倒；与“正常坐”区分 |
| 5 | 起身/转身时倒地 | 洗手台/毛巾架 | 转身伸手→侧/后倒 |
| 6 | 出浴缸/跨门槛绊倒 | 浴缸边/门口 | 抬腿→绊倒；可用假人替代真实浴缸内动作 |

每次跌倒后：

- **保持躺姿 5 s**（最低）；
- 再做一个 **30 s 长躺**（每个受试者至少 2 次）；
- 条件允许再做 **2 min 长躺**（每个受试者至少 1 次）；
- 然后起身、出画。

> “长躺”不是第 7 个事件，是同一事件的持续时间；标注里写 `long_lie_s`。

### 2.1 负例（每人 20 段，浴室专用）

| 类别 | 动作 | 次数/人 |
|---|---|---:|
| 马桶 | 正常坐下、坐 30 s、坐 5 min、起身 | 4 |
| 洗漱 | 弯腰洗脸、低头刷牙、伸手拿杯子 | 3 |
| 清洁 | 蹲下擦地、跪着擦浴缸、弯腰捡肥皂 | 3 |
| 淋浴 | 站着洗头、抬腿洗脚、转身关水 | 3 |
| 进出 | 跨门槛、开门/关门、掀浴帘 | 3 |
| 贴地/小目标 | 浴垫被踢、毛巾掉落、捡毛巾 | 2 |
| 遮挡 | 站在浴帘后、只露腿、半身被马桶挡 | 2 |
| **合计** | | **20** |

其中“坐马桶 5 min”是**最重要的长时负例**：它和“长躺”在高度上接近，是误报的主要来源。

### 2.2 空场/环境负例（不占每人次数）

- 空浴室 5 min × 2（帘开/关）；
- 淋浴开 5/10/15 min，无人；
- 浴帘被风吹/被开门气流带动 30 s；
- 毛巾掉落、浴垫被踢、门开合各 10 次；
- 湿地面 + 反光/水洼。

这些用来估“无人误报”和“环境变化误报”，不能算人体负例。

## 3. 每段采集流程

1. **空场前缀 10 s**：门关、帘的状态按本次矩阵固定；记录时间范围。
2. 受试者入画，站立 **10 s**（锁定 + 直立参照）。
3. 执行动作（跌倒或负例）。
4. 跌倒：保持躺姿 **5 s**；长躺段按 30 s/2 min 执行。
5. 起身、出画；结束录制。
6. 每段有效时长 **≥30 s**；长躺段 ≥60 s。
7. 同一动作的失败/重采**另起 take**，首次记录保留，不能只留成功版。

采集顺序建议：先空场/环境 → 负例 → 跌倒；跌倒从“垫上模拟”开始，最后做真实滑倒（受保护）。

---

## 4. 安全与隐私

- 受试者 18–45 岁、无心血管/骨关节/腰椎病史；不招老年人、孕妇、有跌倒史者。
- 防滑垫、保护垫、保护员位置由现场负责人确认；浴室湿滑，先铺垫再洒水。
- 浴缸内动作只用假人或垫上模拟；不做无保护的浴缸边真实跌落。
- 视频只用于事件时间 GT：**本地存储、不外传、不入仓库**；能不用就不用，优先操作员按钮 + 双路可见动作对齐。
- 点云也不等于匿名：体型/动作仍可识别；需知情同意与访问控制。
- 传感器若不在 IP 防护范围，必须装在溅水区外；线缆做防水弯。

## 5. 标注（`fall_events_v1` 扩展）

在母协议 schema 上，浴室段增加以下字段（不改变必填字段）：

```json
{
  "schema": "fall_events_v1",
  "session": "cap_20261101_093000",
  "subject": "S03",
  "scene": "bathroom",
  "sensor_pose": {"height_m": 2.2, "yaw_deg": 45, "pitch_deg": -25, "mount": "corner_A"},
  "environment": {"floor": "wet", "shower": "on_10min", "curtain": "half", "glass": "frosted",
                  "mirror": true, "mat": true, "door": "closed", "light": "on"},
  "events": [
    {"id": "e01", "kind": "fall", "t_start": 6.2, "t_impact": 6.9, "t_end": 36.9,
     "posture_end": "lying", "direction": "backward", "fixture": "shower",
     "long_lie_s": 30.0, "occlusion": "none", "assisted": true,
     "simulated": false, "certainty": "confirmed", "observable": true}
  ]
}
```

- `fixture`：shower / bathtub / toilet / sink / threshold / floor。
- `occlusion`：none / partial_fixture / curtain / glass / legs_only。
- `assisted` / `simulated` 必须如实写，不能把接住/假人当完整落地。
- 长躺事件的 `t_end` 是起身时刻，不是落地时刻。

## 6. 采后 15 分钟

1. 跑 `python -B -W error ML/src/fall_annotation.py --annotation <json>` 校验。
2. 导出目标点集，跑 `fall_dataset_gate.py`；记录 `OK/NEVER_UPRIGHT/NEVER_LOW/EVENT_IN_GAP/TOO_SHORT`。
3. 检查无效回波率、深度边缘比例、目标点集是否被马桶/浴帘截断。
4. 记录同步误差（视频/按钮 vs 雷达），>0.2 s 的段不能当精确时序 GT。
5. 记录丢帧/掉锁、镜头结露、溅水、帘子晃动。
6. 失败/重采/模拟全部入账。

## 7. 规模

| 批次 | 人数 | 跌倒事件 | 负例 | 目的 |
|---|---:|---:|---:|---|
| **浴室试点** | **3** | **18**（3×6） | 60（3×20） | 验证安装/遮挡/长躺/标注/同步 |
| 浴室正式 | 8–10 | 48–60 | 160–200 | 人员留出、场景分层 |
| 长时日常 | — | — | — | **20 h 全屋日常**（含浴室进出），不是“在浴室站 20 h” |

> 浴室单位时间 occupancy 低，20 h 墙钟里真正有人在浴室的时间很少。长时误报要同时报：
> - **每墙钟小时**（与全屋指标对齐）；
> - **每浴室使用小时/每次使用**（更贴近产品体验）。
> 只报前者会低估“每次洗澡被误报”的体感。

## 8. 评测口径（浴室版）

| 指标 | 定义 | 备注 |
|---|---|---|
| 事件召回 | 分母 = 全部已确认跌倒事件；漏检/不可观测单列 | 主指标 |
| 长躺召回 | 跌倒后 ≥30 s 未起身的事件中被报警的比例 | 浴室核心 |
| 报警延迟 | 事件起点/落地 → 首次报警 | 目标 ≤1.5 s；长躺可另设 ≤30 s |
| 误报/墙钟小时 | 非跌倒时段的报警 / 墙钟小时 | 与全屋对齐 |
| 误报/浴室使用小时 | 同上 / 浴室有人小时 | 产品体验 |
| 误报/次 | 每次浴室使用触发次数 | 最直观 |
| 分层 | fixture、遮挡、帘/玻璃、干湿、蒸汽、位姿、人员 | 每层单独报 |

重点分层：**马桶长坐 vs 长躺**、**浴帘后 vs 帘开**、**玻璃隔断后 vs 无玻璃**、**湿地面 vs 干**、**淋浴蒸汽 0/10 min**。

## 9. 对算法/前端的直接影响

1. **背景不能只有一份**：至少维护“帘开/帘关”两套逐射线背景；浴垫/毛巾变化用前景残差 + 小目标过滤，不要直接吸收进背景。
2. **fixture mask**：马桶/浴缸/洗手台是静态的，但人坐/趴在上面时会被一起挡住；不能简单把 fixture 区域全排除，否则坐马桶/浴缸边跌倒会消失。
3. **玻璃/镜面**：先测回波；透明玻璃可能无回波，镜面可能有鬼影。无效区显式标记，不做“补点”。
4. **蒸汽/水**：记录有效回波率随淋浴时间的变化；若 10 min 后有效格掉到阈值以下，报警降级为 `degraded`，不硬报。
5. **贴地/遮挡**：只露腿/半身时，高度来自可见部分；事件判据用“低位 + 长时间无恢复”，不要强求完整人体 PCA。
6. **长躺状态机**：低姿态 + 无恢复 ≥30 s → `long_lie_suspected`；坐马桶 5 min 是主要负例，必须用“位置在 toilet + 有周期性小动作/上身直立”区分，不能只看高度。
7. **隐私**：不引入 RGB 作为在线输入；视频只做离线 GT。

### 9.1 时序层：几何特征 + 小 HMM（先于大模型）

固定浴室不需要海量数据，但需要“测量 → 状态”的时序模型。推荐先做 5 状态因果 HMM，而不是直接上点云深度网络：

| 状态 | 含义 |
|---|---|
| `upright` | 站立/直立 |
| `sitting` | 坐马桶、坐椅、低但非躺 |
| `descending` | 高度快速下降 |
| `lying` | 贴地/躺倒 |
| `recovering` | 起身过程 |

- 观测：目标 `height_p90`、`height_span`、垂直速度、PCA 倾角（缺失单独一档）；全部来自跟踪后的实测几何，不来自原始点云。
- 先验：可以手设转移/发射概率，不训练也能跑；`fit_hmm` 只做转移/发射计数 + Laplace 平滑，适合 18 事件/60 负例的小样本。
- 因果：只用当前和过去帧；断档/遮挡不补零，输出 `unknown` 或 `degraded`。
- 关键防误报：**轨迹出生时就是低姿态，不算跌倒**（`low_unconfirmed`）；可见点比例 <25% 或点数 <100 时只预测不确认；坐马桶/蹲下由 `sitting` 状态吸收。
- 跌倒候选 = `descending → lying` 且持续 ≥0.3 s；长躺 = `lying` 持续 ≥30 s（试点可先用 5 s 演示）。仍不是 `confirmed`。

Demo 已实现该层：`pc_apps/bathroom_demo/fall_hmm.py`。真实 386 帧无跌倒会话上 HMM 0 次跌倒/0 次长躺；合成胶囊跌倒上第 35 帧 `fall_suspected`、第 85 帧 `long_lie_suspected`（demo 的 5 s 阈值）。这是软件/几何验证，不是浴室效果。

**为什么仍要真实数据：** Bagalà 等用 13 个已发表加速度跌倒算法在 **29 次真实跌倒**上评测，敏感度仅 57.0%±27.3%（最高 82.8%），而模拟跌倒上的成绩明显更高；一天监测的误报为 3–85 次。小 HMM 能降低数据量，但不能消除“真实事件 + 长时日常”的验证缺口。[PLOS ONE 2012](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0037062)

## 10. 能证明/不能证明

- **能证明**：浴室安装下，雷达能否稳定看到人、能否区分“长躺 vs 坐马桶/蹲下/擦地”、报警延迟和误报量级。
- **不能证明**：真实老年人跌倒、真实浴室长期可靠性、其他浴室布局/材质/传感器位姿的泛化。
- 3 人 × 6 次只是**试点**：够发现流程/遮挡/标注问题，不够写“泛化通过”。正式批至少 8–10 人，且人员留出。
- 没有视频/事件 GT 的段，只能做软件/几何诊断，不能算召回。
