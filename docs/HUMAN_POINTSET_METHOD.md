# 单雷达 + RK3588 的人体点范围实施路线

更新：2026-10-19。服从 PROJECT_WORKFLOW，不新增人工标注或复核前置条件。

**最终产品硬约束：只有一个 LiDAR 和一块 RK3588 开发板。** 人体判断、点集提取、跟踪、区域/姿态和跌倒判断必须在板端仅使用雷达数据运行，不依赖相机、PC、云端 agent 或人工点击。2026-10-19 用户澄清后，本路线取代此前把相机融合列为产品方向的建议。已有 RGB 记录仅作可选离线开发辅助，相机标定不再是产品待办或开工前提。

## 能由 agent 完成到什么程度

agent 在开发期读取原始点云、多视角和连续帧，独立于显示框提出人体大致范围，记录较可信核心、歧义边缘与原始来源行，帮助实现和验证板端算法。用户不需要逐点标注；产品运行时不调用 agent。已经检查的相机录像可以作为辅助材料，但没有录像的雷达会话同样必须能开发、回放和运行。

这种判断是 AI 弱标签，允许工程使用和诊断，但不是独立人体真值。相同点云上的几何算法、agent 判读及根据其结果调整的参数不能互相认证准确率。静止人体与家具可能具有相似单帧几何，需要评估雷达自身的形状、表面、序列和人体语义判别能力；单凭连通、尺寸或运动不能保证区分。可见表面之外的身体点没有被传感器测到，不能补造。

## 产品运行链与开发顺序

运行链是：雷达点云 → 有效性/时间/地面检查 → 候选与因果历史 → 雷达人体判别/唯一获取 → 同一目标的实际来源点 → 跟踪、区域/姿态和疑似跌倒。RK3588 负责全部计算，NPU 只是可选计算资源；现有 RGB YOLO 不能直接充当雷达人体分类器。

先在现有 stdlib + NumPy 共享核心改候选历史、成员归属和静止保持，用已有 RAW 场景与 AI 弱标签做开发对照。形状、竖向密度分布、局部表面结构和运动历史可作为互补证据，但不把直立身高/窄框变成排除坐姿、低姿态的入口硬门。

针对开机时人已经静止、多目标、人与家具粘连保留明确反例。如果规则证据不足，另行评估只输入雷达点云/深度表示的人体分类或分割能力，并验证其 RK3588 兼容性、真实输入域和完整延迟；不能把板上已有图像模型当作这一步已完成。当前模型训练、下载和 HR-09 仍按仓库既有明确授权边界执行，本次硬件澄清本身不触发训练或部署。

## 三个问题分别怎么处理

### 目标点是否属于人

先把“几何点集”“雷达人体判别依据”“边界可信度”分开输出。使用 RAW 来源行保持所有消费者一致；agent 多视点判读只生成带依据的弱标签。板端以当前实际点、候选形状/结构和因果历史形成判别，不能把最大簇或唯一运动簇直接命名为人。

从有空间/时间支撑的身体核心向相容成员扩展，分别检查身体碎裂和家具粘连，逐帧记录增删来源行。一个连通组件不天然等于一个人；分离的手脚也不能仅因不连通永久排除。边界争议保留不确定性，不能靠缩显示框或固定百分位裁边宣告点集已纯净。

已有 RGB 检测仅证明旧录像上图像模型能执行，不构成产品传感器需求，也不证明雷达成员正确。没有相机记录、外参或相机在线服务，均不得成为雷达处理链的阻塞条件。

### 无显式空场时的候选竞争

当前代码无 background 时不扣除静态几何；获取器遇到多个合格候选每帧清空累计。因此延长获取时间或强选最大簇不能消除根因。

新增的可见性变化 cue 为后续共享获取策略提供因果证据。正确策略是：保留初始占据为 unknown；重复较远返回到当前较近返回、连续唯一关联和实际位移可支持动态几何获取；人体语义只能由经验证的雷达判别证据提供。两个运动目标、分裂粘连或关联不唯一继续拒绝。已获得目标停止移动后，由同一身份下的实际空间观测维持，不把它纳入在线背景。开机时已经静止的人必须有单独覆盖，不能要求先走动才算支持静止人体。

方法依据：[PCL 空间变化检测文档](https://pointclouds.org/documentation/tutorials/octree_change.html)说明变化检测针对空间差异；[Moving Object Segmentation in 3D LiDAR Data](https://arxiv.org/abs/2105.08971)也明确将运动/静态分割与语义类别分割分开。因此不能把范围变化单独升级为人体分类。

这个 cue 还未接入生产获取器。接入必须统一 current、FallNodeCore 和 ReplayPipeline，保留显式背景对照；记录 selection_basis、未知竞争数、实际源行。断流、时间倒退、标定改变清空历史；预测不能提供运动证据。传感器自身运动也会导致范围变化，需先用 IMU/静态结构检查或拒绝，不能把整幅变化解释成多个人。

### 无背景变化获取的边界

共享获取器新增两个默认关闭的实验门：`change_gate` 用“唯一持续运动历史”作为获取线索，`history_hold_gate` 锁定后只接受同一 history id 的实际观测。无背景 386 帧中，仅变化门在 f122 锁定、264 locked，但退出后 12 帧误锁静态家具；变化门+历史保持门在 f122 锁定、240 locked / 24 occluded，所有已观测帧与显式背景参考目标 100% 重叠、退出后 0 帧误锁家具，代价是目标与家具合并/分裂后 f365 起只能预测。显式背景加两个门仍 267 locked / 12 occluded，核心输出不变。结论：运动/变化只能作为几何获取辅助，不能命名人体；移动家具同样可能被获取，严格历史保持会牺牲合并/碎裂时的可见帧。该模式未采用为默认，证据 `docs/evidence/2026-10-19_change_acquisition/`。

### 固定背景能做什么、不能做什么

固定背景是“场景解释”而不是“人体识别”。同一主会话 A/B：用声明空场 0–49 帧建背景，190–330 帧参考目标 141/141 全部保留；改用人已在场的 140–189 帧建背景后，参考目标平均只保留 3.66%，0/141 帧超过 50%，平均前景约 122 点。更危险的是残留的 48–59 点碎片仍可能 100% 落在参考目标行内，按“候选大部分是目标”会把碎片误当完整人。人在背景学习期间在场会被吸收；家具移动、背景变化或未知空场会产生假前景；多人/家具移动时仍有竞争。因此固定背景可作为显式空场开发对照、前景隔离和候选提取，不能单独命名人体，也不能解决开机即静止或未知空场。证据 `docs/evidence/2026-10-19_fixed_background_boundary/`。

### 区域跨场景稳定性

首先固定可靠目标成员，再检查每区空间支撑和 PCA 退化。当前左右正负号连续不能解决两团点混在同一区、侧轴交换或低姿态域外问题。后续在共享区域入口增加：每区唯一空间支撑、主/横轴特征值间隔、跨帧关联冲突、点数与跨度突变原因；不通过平滑坐标伪造稳定。

回归使用已有雷达会话，覆盖初始静止、进入后静止、行走、低姿态、家具、竞争与遮挡；已有联合会话也只需其雷达输入即可参与。不同会话必须各自绑定地面，不套当前主会话变换。两段联合会话没有现成绑定地面，因此本轮只运行 RAW 视图/变化 cue，**没有声称完成跨场景区域验证**。旧弱标签可作诊断但含聚类/未来帧信息，不能输入在线策略或当独立评测。

## 2026-10-19 首个候选历史增量与规则失效边界

共享 `core/candidate_history.py` 已接入 current、FallNodeCore 和 ReplayPipeline 的自动路径。历史以实际 RAW/source 点支撑关联，记录 session、时间、epoch、坐标、地面内容 SHA、帧序号和来源行；`candidate_id` 仍只在本帧有效。只保留上一帧观测状态，连续时累计跨度/观测数/位移；断流、非法时间和绑定变化清空。初始静止候选始终 unknown，不在线吸收为背景。地面上下文换代现在立即清除获取状态，status API 不必等下一帧才失效。

每帧保存 PCA 表面线性/平面性/散布、固定物理高度分层、来源行、支撑进入/消失行和未解决谱系。跨帧行号不是物理点 ID；支撑变化也不是已经确认从人体增删了成员。同帧基线/候选目标来源行另外逐帧比较。默认保留全部实际候选点，不剪手脚、不缩显示框、不按百分位制造纯净目标。板端状态只发布摘要，完整行账本供离线开发。

实验 `support_history_guard` 将分裂/合并谱系直接用于拒绝获取与保持，完整386帧显式背景回放却从267帧实测退化为0：人体进入时的小片点云连通同样产生多前驱。继续累计冲突又会永久拒绝身体重新连通。这是具体规则失败，不能用测试通过或加更严阈值掩盖。该模式只保留为显式失败实验，默认 `evidence_only`；无背景仍竞争拒绝。历史证据不能当人体分类器。失败源码、完整回放和实际成员对照均在 `docs/evidence/2026-10-19_candidate_history/`。

RAW 场景中，f140–165与f180–330支持进入后静止/原地动作；f101–120和f340–373支持进入/离开。f372/373只剩低处局部可见点，不能称为真实蹲姿/跌倒。开机即静止真人、真实完整遮挡、真实双人竞争和真实低姿态仍缺覆盖；合成测试只验证相应软件契约。静态远端碎片与人形簇的跨度/细长程度非常接近，单靠尺寸、PCA、持续性或运动不足以可靠命名人体。

本轮继续补齐成员账本：合并/分裂时增删行改为对全部直接前驱的支撑并集计算，并记录 `compared_history_ids`；显式背景 280 条、无背景 3766 条历史记录的成员字段变化，核心获取/跟踪/区域/姿态/跌倒输出逐值不变。可分性检查用显式背景目标作开发参考（不是人体 GT）：266 个有参考帧、2338 个竞争候选观测；229 个竞争观测能通过宽松的类目标形状条件，单特征池化最高 AUC 0.963（scattering）但逐帧 top-1 最高 244/266。更窄的 1500–5000 点、scattering ≤0.05、≥5 高度层规则命中 256 个目标帧，却有 6 个非目标命中（5 个在显式目标出现前、1 个在 f369 仅 36.9% 目标重叠）并漏掉 11 个入场/退场目标帧；其绝对点数下限会排除更远/更小的静止人体。该规则未部署，避免把单会话阈值当人体分类器。完整数据、规则搜索和不可泛化边界见 `docs/evidence/2026-10-19_novelty_acquisition/`。

## 雷达专用语义分割的具体可行性（设计，尚未实现或验证）

根据上述真实反例，下一条值得检验的路线是当前帧逐点语义分割，加既有因果历史。仅做整簇人/家具二分类，无法拆开人椅粘连，也无法找回前级已排除的身体碎片。这里的“可行”是实现与测量路径明确，不是已有精度、转换成功或实时保证；本轮没有训练、下载权重、转换模型或开启HR-09。

| 候选路线 | 一手依据与本项目取舍 |
| --- | --- |
| PointNet风格小型逐点网络 | 官方分割代码以固定点数XYZ输入、逐点卷积、全局池化和特征拼接输出点标签，适合先检验固定图转换。局部结构能力有限；原版T-Net/矩阵运算仍需逐图验证，删T-Net属于新模型设计。[官方实现](https://github.com/charlesq34/pointnet/blob/master/models/pointnet_seg.py) |
| SalsaNext风格距离图 | 作者网络采用二维卷积等结构，投影代码维护点与像素映射。IFW192S扫描分布、视场和同像素多点与车载旋转雷达不同，不能直接套预训练结论；碰撞点不能无条件共享标签。[作者网络](https://github.com/TiagoCortinhal/SalsaNext/blob/master/train/tasks/semantic/modules/SalsaNext.py)、[投影实现](https://github.com/TiagoCortinhal/SalsaNext/blob/master/train/common/laserscan.py) |
| PointNet++ / LiDARCap | 层级局部结构或姿态研究可借鉴，但官方实现含自定义采样/邻域算子。它们不能证明无背景自动找人和完整成员分割已经解决，也不能假定直接进入RKNN。[PointNet++](https://github.com/charlesq34/pointnet2)、[LiDARCap论文](https://openaccess.thecvf.com/content/CVPR2022/html/Li_LiDARCap_Long-Range_Marker-Less_3D_Human_Motion_Capture_With_LiDAR_Point_CVPR_2022_paper.html) |

建议先验证PointNet风格逐点网络的输入/输出契约与可转换性，再决定是否需要距离图或局部结构网络。接口草案：

- 当前帧自动空间分块并保留上下文，覆盖全部实际搜索域点；不先用“站立人体门”裁掉手脚或低姿态。固定2048/4096点只是实验起点，超额确定性分块、不足padding加validity mask，每点保留source_row和覆盖记录，padding不进入目标。
- XYZ、米制尺度、同一地面高度和距离作为起点特征；intensity的距离/材质归一尚未验证，ring和已压为float32的点时间不先当可靠语义输入。单帧分支必须能处理上电已经静止的人；过去帧只辅助稳定。
- 输出每点human/other分数，同时对不确定、域外和无输出保留unknown。保存模型/预处理SHA、实际行及增删原因，所有下游消费同一实际成员；预测不补点、不作姿态/跌倒证据。
- 分块、来源行映射和后处理保留在stdlib＋NumPy核心；RKNN推理另设显式运行时适配器。不能给纯核心自动增加PyTorch、CUDA或图像模型依赖。

RKNN Toolkit2官方支持RK3588，但算子支持不等于纯NPU或实时保证。必须固定实际compiler/runtime/driver版本，对Conv/ReduceMax/Concat及T-Net等实际图验证转换与执行分配；官方固定版算子表与新变更记录也不完全相同。[官方仓库](https://github.com/airockchip/rknn-toolkit2)、[v2.3.2算子表](https://github.com/airockchip/rknn-toolkit2/blob/v2.3.2/doc/RKNNToolKit2_OP_Support-2.3.2.md)、[变更记录](https://github.com/airockchip/rknn-toolkit2/blob/master/CHANGELOG.md)

延迟测量需要覆盖分块次数、拷贝、NPU/CPU混合执行、来源点反投影、历史、区域与发布年龄/队列，并分别记录冷启动和稳态。INT8对细小肢体、罕见低姿态和接触边界的影响需逐点核对。现有图像模型耗时不能外推，独立离线ReplayPipeline耗时也不能代表完整板端实时链。

现有386帧与f160/f341保守核心弱标签不足以评价完整分割，包络外未标点不能自动作负类，同源弱标签不能变独立GT。开发数据需覆盖家具空场、开机静止、进入后静止、行走、坐/蹲/躺、遮挡、接触和多人竞争，按会话/人员/场景隔离评测，避免邻帧泄漏；样本量由覆盖与学习曲线决定。公开雷达数据只能用于表示与域差异研究，不能替代IFW192S本机验证。[SemanticKITTI官方说明](https://semantic-kitti.org/dataset)、[SLOPER4D作者库及许可](https://github.com/climbingdaily/SLOPER4D)
