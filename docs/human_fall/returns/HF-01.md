## 契约与实现

- 输入：`/innolidar_points`（必需，sensor_msgs/PointCloud2）、`/inno_imu`、`/device_status`（辅助）。输出：`/human_fall/health`（std_msgs/String，schema_version=1，严格 JSON，禁 NaN/Inf，无效值 null）。不创建相机/CameraInfo/图像/第二雷达/TF 输入。
- 单位/坐标系：几何单位 m/s/rad（m/s²）；点云 frame=`innolidar`；IMU 原始值原样输出、`units:"unknown"`，不换算 g/deg/s，orientation 全零/非单位/非有限判不可用，covariance 全零只记 `orientation_covariance_zero`（不据此判测量无效）；`abnormal_flag` 原样、语义 `unknown`。
- 时间域：`source_time_domain=device_stamp_s_unanchored`（原点未锚定，非 UTC）；接收侧独立记录节点单调钟；源 stamp 分 `first/ok/repeated/regressed/forward_jump/invalid`，`repeated/regressed/forward_jump` 递增 `time_epoch` 并记 reason；`normalized_stamp_s=null`，`sync` 两个标志 false。
- 依赖版本：板上 Python 3.8.10 / NumPy 1.17.4 / ROS Noetic（容器 `slam-localization`）；本地预检 Python 3.12.10 / NumPy 1.26.4。无新增 pip 包。
- 新增阈值（`config/default.yaml`，可配置）：cloud_stale 0.6 s（≈5.8 个点云周期）、imu_stale 0.3 s（≈68 条）、device_stale 0.6 s、max_forward_jump 30 s、publish_period 0.5 s；依据 HF-00 实测频率（9.65/227/9.65 Hz）留出冗余，未声称性能门槛。
- 复用：`human_follow_calibration.xyz_from_cloud`（含填充行/大小端处理）；`rosbag record` 与 `rosbag.Bag` 再读；既有 `save_json` 原子写模式（本包内一份，无跨包运行时耦合硬依赖——缺失时降级为 `cloud_decode_failed` 并继续报告布局/时间）。避免：OpenCV/MediaPipe/RKNN、新消息包、TF 依赖、UI。

- Windows 侧只做编辑/静态检查/纯函数测试；ROS 构建与采集全部在授权容器完成。
- 构建把 CATKIN_WHITELIST_PACKAGES 持久化为 `inno_lidar_ros;human_follow_calibration;human_fall_detection`（原值 + 本包），未重启雷达服务、未改网口/自启/厂商库/远端驱动源码。
