# HF-11 第 2 轮 SUBMITTED 补充（线格式 / 帧 / 协议门控修复）

依据 `docs/human_fall/HF11_WIRE_FRAME_FIXES.md` 闭合 Codex 对 actual `human_fall.js` 的 5 项具体问题；原活动页面/驱动未改，仍为预览。

## 修复项
1. **出站 ros1 String 缺 4 字节长度**：新增纯函数 `HF.packClientMessage(channelId, text) = opcode 0x01 + channel u32 LE + uint32 LE 字符串长度 + UTF-8 JSON`，页面请求统一走该函数。实测帧头
   `1,1,0,0,0,188,0,0,0,123,34,115,99`（opcode=1, channel=1, len=188, 紧跟 `{"s…`），bridge 反序列化成功。
2. **帧对齐（非 seq-only）**：记录呈现点云的原始 `header.seq/secs/nsecs` 与接收时刻；仅当候选/状态 `source` 的 `seq+stamp_secs+stamp_nsecs` 与当前呈现帧完全一致才叠框；`pcPrevSeq=null` 不再视为对齐；无呈现帧/无匹配一律不叠并显示“等待匹配/过期”。有界 8 帧候选缓存；跨 `session`/`time_epoch` 清缓存/候选框/目标框/待选；目标框同规则，不用当前 seq 给旧 source 叠绿框。
3. **schema/有限性门控**：候选、`state`、`event`、`ack` 各自独立校验 `schema_version`/`kind`/`session`、有限三轴/bbox、`fall_status/track_status/observability` 枚举；非法/未知只显示 `unknown` 并隐藏受影响框/位置，不删除既有事件；迟到 `state` 不回滚更新的 `selection_version`/`time_epoch`。
4. **namespace 可配**：`?prefix=` 与 `?points=`（默认生产 `/human_fall/`、`/innolidar_points`），预览可对接验证命名空间；banner 显示当前前缀并在 `verify` 时标明“合成/验证输入（非真实人体）”。
5. **UI 措辞**：请求通道显示“可用/不可用”，不向用户裸露 `clientPublish` 字样；IMU 保留原始数值并标“原始值，单位待核验”，异常 255 显示“含义未知”且不判红；位置标“可见点云中心 · 雷达坐标 innolidar（未标定世界坐标）”。
