## 契约与实现

- 输入/输出：本单新增 Python 纯模块，不改 ROS 话题/schema。`timebase` 快照内部带 `kind:"timebase" schema_version:1`、`clock_domain`（`monotonic`/`message_time`）、`time_epoch`、`source_time_domain`、`normalized_stamp_s`、`sync`、逐路 `stamp_secs/stamp_nsecs/source_stamp_s/time_received_s/status/age`、`unit_mismatch_suspected`、reason codes；全部经 `finite_or_none`，严格 JSON 无 NaN/Inf。冻结字段/语义未变，无需 schema_version 提升；DRAFT 样本用显式兼容读取路径（`stamp_from_health_block`）。
- 时间域：源 stamp 仍为 `device_stamp_s_unanchored`（未锚定，非 UTC）。仅记录证据支持的转换：`clock_fit` 明确 `transport_fit_only`；物理偏移只有 `apply_sync_evidence("vendor_protocol"/"controlled_common_event")` 才记录，拟合/近似 stamp/同 frame_id 一律 `ValueError` 拒绝。单位错配（尺度比或速率比 >1e6）直接拒绝配对。
- IMU 语义：单位/轴向/偏置逐项 `unknown`→`verified` 需命名证据；六轴有限性与姿态有效性分开；`orientation` 全零/非单位/非有限/`covariance[0]=-1` 判不可用且不伪造。设备运动状态在验证前恒 `unknown`，即使 IMU 静止也不单独证明设备未平移（`static_background_usable` 同时要求地面有效、背景残差有效、运动已验证为 static），异常要求现场重新初始化。
- 依赖/参数：标准库 + 既有 NumPy/unittest 与 `sensor_health`；阈值（匹配容差、缓存大小、晚到超时、重力/静止容差）为函数入参默认值，未改配置文件；无新增第三方依赖。
- 驱动实现：`publish_manager.cpp` 增加 `#include <cmath>` 与静态 `deviceStampToRos(double, uint32_t&, uint32_t&)`；三处转换使用（点云 header、DeviceStatus、Imu）。数值在 fraction 舍入到 1e9 时 `nsec-=1e9, ++sec`；NaN/Inf/负值/超 `uint32` 范围输出 `(0,0)`（消费者按 invalid 处理，不回填旧值）。IMU 的 `orientation_covariance` 显式清零后首元素置 `-1.0`（ROS 约定“不提供姿态”）；六轴测量原样透传（有限性由健康层检查），不因姿态标志掩盖测量。ROS1/ROS2 条件分支结构与用户拼写修复均保留。
