## 2. Range Image 映射原理与验证（实验 A）

### 2.1 原理：不是 `reshape(192,256)`

IFW192S 的方向表是 **192 行 × 256 列 = 49,152 个方向**：

- 方位（azimuth）：每行 256 列，`+77.2° → -77.2°` 单调**递减**，列间中位步长 **0.5°**；
- 俯仰（elevation）：行间中位步长 **0.1°**，范围 `-47.8°…+47.8°`，但**同一 ring 内俯仰随列变化 11.7°**（不是等角扫描网格，用“行=俯仰角”的等角假设会错）。

映射规则（与 `ScanGrid.decode` 一致，本轮用独立实现复核）：

1. `ring` 字段直接给出行号 `r`（实测 0…191 全覆盖）；
2. 由实测点算 `az = atan2(y, x)`，在该行 `azimuth[r, :]` 中取最近列 `c`；
3. 必须同时满足 `|az_table[r,c]-az| ≤ 0.02°` 且 `|el_table[r,c]-el| ≤ 0.02°`，否则判为“方向未知”并**拒绝**（不猜、不插值）；
4. 同一格出现多点时按“最近回波优先，同距离取最小帧内行号”确定性取一，其余行进入 `duplicate_rows` 审计；
5. 空像素记为 `NaN`，**绝不是 0 m**；另有 `valid` 布尔掩码与 `source_rows`（栅格 → 原始点行号）供反投影使用。

### 2.3 无效点、丢失点、重复投影的处理

- **无效点**：实测每帧约 12,005 点是全零（`x=y=z=0`，`ring` 仍有效）。它们被排除在测量外，图上留空白（不是 0 m）。这也是 24.5% 无效像素率的来源。
- **重复投影**：两段会话 512 帧中**没有出现**同格多点（设备每射线单回波）。因此“确定性规则”在本数据上未被触发；代码路径仍在（同一格按最近回波取一），但**冲突率 0% 属于本数据集的事实，不是对所有场景的保证**。
- **帧内时间**：会话把逐点 `timestamp` 存成 **float32**。在 D1 的 689,790 s 量级上 float32 分辨率 = **62.5 ms**，一帧只有 **2 个唯一时间值**；D2（217,559 s）分辨率 15.625 ms、7–8 个唯一值。帧跨度只能测到 0.0625–0.125 s。结论：**离线文件不足以做逐点运动去畸变**（不能把 9.65 Hz 当固定采样、也不能恢复帧内扫描顺序时间）；`header.stamp` 与首点时间差 −0.028 s（D1 f53）/ −0.0005 s（D2 f220），帧级时间可用。

### 2.4 与旧近似的差异（本轮复核）

旧近似投影曾在 386 帧中每帧出现 4 对射线冲突、丢 34–36 点；本轮严格查表实现**0 冲突**，与 10-23 轮结论一致。本轮不再重复该消融。

## 3. 三条人体识别路线对照（实验 B）

### 3.1 受控条件（三条路线输入完全相同）

为避免“分割差异”和“表示差异”混在一起，三条路线共用**同一前景掩码**：

- 距离图 `range_m` + `valid`；
- 前景 = `valid & |bg-Δ|>0.30 m & 0.1 m ≤ r ≤ 8.0 m`，再做 `denoise(min_neighbours=2)`；
- 背景：**D2 用因果空场前缀**（前 50 帧是仓库既有实验中“显式开发空场前缀”的声明，`RayBackground`，min_observations=10）；**D1 无空场前缀，用整段逐射线 p98 非因果背景**（与 10-23 轮 `session_compare` 同一做法）。这一点是 D1 结论的**硬限制**，第 8 节再列。
- 分类门限对 B0/B2 **完全相同**（固定先验，未在任何标注上调参）：点数 ≥25，高度中位 0.10–1.95 m，最高点 ≤2.20 m，水平跨度 ≤1.30 m → `PERSON`，否则 `NON_PERSON`；几何缺失 → `UNKNOWN`。
- B1 用**纯 2D 先验**（不接触 3D）：行跨度 ≥10、列跨度 ≥8、像素 ≥25、距离 ≤6 m。
- 三条路线各用**同一套**最近质心关联器（门 0.7 m/帧、丢失 3 帧删除），因此 ID 切换差异来自表示本身。

三条路线定义：

- **B0**：`build_snapshot`（现有 3D 体素/水平格聚类 + 现有几何特征）+ 3D 门限。
- **B1**：`label_components`（距离图 8 邻域 + 深度连续性）+ 2D 门限。
- **B2**：`label_components` 的 ROI → `source_rows` → 真实 3D 点 → `rebuild_candidate`（现有几何）+ 与 B0 相同的 3D 门限（即 2D+3D 融合）。

### 3.3 读数与判读（必须区分“检测失败”与“前级无候选”）

1. **D1 的 9 个无候选帧（f117–f125，t=12.13–12.96 s）三条路线完全相同**：前景只剩 5–22 点。相机在该段显示人体已在画面左缘、接近离开视场，而雷达 8 m/±77° 窗内已无有效点。这属于**前级无观测**（前级候选缺失），不是分类器失败。
2. **B2 的 52 个“多人体”帧不是两个人，而是同一个人的身体被切开**：例如 f61（t=6.32 s，躺卧）前景 707 点被切成 4 块（39/560/34/61 点），其中 3 块只有 6–14 像素宽，仍通过 3D 门限被判 `PERSON`；B0 在同一帧给出 1 个 701 点簇。B2 的主块丢掉 10–22% 的人体点（躺卧段 495–756 vs B0 635–815），高度中位仍然一致（0.24–0.40 m），但**点云几何的稳定性下降**，对后续 PCA/纵横比特征不利。
3. **B2 与 B0 在“哪块是人体”上高度一致（IoU P50 0.993）**，说明 2D 分割没有“看得更准”，只是把同一目标切得更碎。
4. **D2 上 B2 覆盖率高（0.774 vs 0.342）不代表更好**：该会话前景主体是一根约 3.2 m 高的静态结构（图 05 右），B0 把整团聚成一个簇 → `too_tall` 拒绝（合理）；B2 把它切成 1.17 m 高的碎片 → 判 `PERSON`（**过分割造成的假人体**）。B2 与 B0 的人体点集 IoU 中位数 = **0.000**，即两边认定的“人体”大半不是同一批点。
5. **B1（纯 2D 先验）不可用**：D1 每帧 1.79 个人体候选、D2 每帧 3.11 个、人体候选点数中位 24 点。距离图上的行/列像素跨度**不含距离尺度**，同一姿势在 1 m 与 4 m 处的像素跨度差 4 倍，纯 2D 阈值无法稳定判人。
6. **延迟**：B2 比 B0 慢 0.6 ms（P50）/ 快 1 ms（P95，D1），D2 上慢 1.6 ms（P50）。2D 分组本身很便宜（1.08–2.18 ms），代价主要在“逐 ROI 反投影重建几何”；延迟不是否决理由，识别质量才是。

**G1 = INCONCLUSIVE（判定自我修正，2026-10-24）**

原先写作 FAIL 的依据不足，已撤回。可支持的与不可支持的分别如下：

**可支持（与门限无关的实测事实）**
- 本版 2D 分割（8 邻域 + `|Δr| ≤ max(5 cm, 1.2%·r)`）确实会把人体切成多块：f61 前景 707 点被切成 39/560/34/61 四块；
- 纯 2D 像素先验不含距离尺度（D1 人体候选点数中位 139、D2 24），不可直接判人；
- 延迟与内存不是障碍（B2 7.18/9.53 ms、151 MB）。

**不可支持（因此不能判 FAIL）**
1. “每帧人体候选数偏离 1”偏向合并：B0 的 0.25 m 聚类把整片前景聚成一个 blob（f30 前景 5357 点→单候选 5349 点），单人场景天然得满分，该指标测的是“过合并 vs 过分割”，不是识别质量；
2. B2 的罚分主要来自本轮自设的“≥25 点”门限（生产 `preferred_cluster_points` 为 80，且人脸/躯干的最小支撑本应随距离归一化），不是 2D 表示本身；
3. B0 不是生产链：D1 无空场前缀，本轮用逐射线 p98 前景替代了生产体素背景 + 空场契约；
4. 无人工 GT，召回/误检率 NOT_EVALUABLE；D2 里“静态高结构被切成人体碎片”是看图推断，非真值；
5. 样本为 1 个会话、1 名受试者、12.96 s，且背景非因果。

### 3.4 相机参考的边界

## 4. 时序姿态与跌倒分析（实验 C）

### 4.1 数据核查：不具备训练条件

- 22 份有 meta 的会话 `human_annotations` 全空；`data/annotations/` 不存在；没有 `fall_events_v1`。
- 唯一有相机可核对的会话 D1 是**主动动作序列**：t≈0–3.1 s 站立行走（远离雷达）、3.4–5.5 s 弯腰下跪、5.5–7.1 s 侧躺、7.6–9.2 s 起身走回、9.3–13.0 s 行走并走出视场。**没有任何一次真实跌倒**。
- 站立/行走/坐下/弯腰/主动躺下这些**正例动作**只在 D1 里出现一次（单人、单场景、无重复），真正跌倒与“跌倒后持续静止”**样本数 = 0**；被遮挡/不完整人体只有边缘入画片段（第 4.4 节）。
- 因此：**不做训练、不报准确率/F1**，判定 `TRAINING_BLOCKED_INSUFFICIENT_GT`，只做特征可分性与定性可视化。

### 4.2 T0（现有 `fall_state.py`）在同一段真实数据上的结果

126 帧、默认参数（`mode_verified=false`、`allow_confirmed=false`，confirmed 关闭）：

| 状态 | 帧数 | 首次出现 |
|---|---|---|
| unknown | 42 | 1.348 s |
| low_posture_unclassified | 34 | 0.000 s |
| descending | 2 | 4.769 s |
| **suspected** | **25** | **6.427 s**（持续到 8.92 s） |
| recovering | 23 | 9.330 s |
| confirmed / events | 0 / `[]` | — |

即：**现有状态机在这一次“主动躺下”上给出了 2.5 s 的 suspected 报警**。按相机参考，这段是“先跪再躺”的受控动作，不是跌倒 → 至少在这一段上属于**误报**（严格说：没有人工 GT，不能称为已确认误报，只能称为“与目视动作不符的报警”）。

### 4.3 T1（2D ROI + 3D 几何的时序特征）实测值

从距离图 ROI 反投影后逐帧计算（保留真实时间戳，不用固定帧率）：

| 特征 | 实测 | 说明 |
|---|---|---|
| 高度中位（站立） | 1.17 m | 最高点 1.86 m |
| 高度中位（躺卧） | 0.24–0.40 m | 最高点 0.45–0.65 m |
| **动作内最大下降速度**（4.5–7.0 s） | **0.562 m/s** | 全段最大 0.768 m/s 出现在 t≈12.0 s（人走出视场、只剩局部点，属伪值） |
| **1.0 m → 0.5 m 用时** | **1.24 s** | 受控下蹲/下跪的典型时长 |
| **跪姿平台（0.35–0.70 m 持续）** | **1.97 s** | 躺下之前先有明确中间姿态 |
| 低位持续 | 4.35 s | 6.4–9.3 s 高度一直 ≤0.7 m |
| 躺卧段水平跨度 | 1.15–1.17 m（峰值） | ≥0.6 m，满足现有 `lying_min_extent_m` |
| 距离图面积 | 495–756 px（躺卧）vs 3,900–5,300 px（站立） | 面积比 ≈ 0.13 |
| 阶段划分（T1 label） | insufficient 11 / upright 55 / descending 2 / low_kneel 38 / low_lying 11 / no_observation 9 | 6.84–7.90 s 为 low_lying |

**可分性判读（仅特征层面）**：真实的快速跌倒会出现“帧间高度骤降 + 短时到达地面 + 无中间姿态”，而本段实测是 **0.562 m/s、1.24 s 过渡、1.97 s 跪姿平台**——与“快速跌倒”的先验阈值（1.2 m/s，本轮仅作对照用的设计先验，**未用任何真实跌倒验证**）相差 2 倍以上。也就是说：**区分“主动躺下”和“快速跌倒”的信息确实存在于 2D+3D 时序特征里**，现有 T0 之所以误报，是它的下降判据只有 `rate ≥ 0.35 m/s + drop ≥ 0.35 m`，本段 0.46–0.56 m/s 恰好过线。

**但这不等于“能识别跌倒”**：数据集里没有一次真实跌倒，阈值 1.2 m/s / 0.5 s 也是设计先验而非数据结论。**G2 = BLOCKED**（训练与独立评测不具备条件），可分性只到“特征可观测、方向明确”这一步。

### 4.4 观测质量与伪影（必须与真实姿态区分）

- t=0–1.3 s：人从画面左缘走进雷达视场，前景只有 54–430 点（仅下半身），高度中位 0.26–0.52 m → T0 判 `low_posture_unclassified`、T1 判 `low_kneel`。这是**局部观测伪影**，不是人蹲下。T1 的 `insufficient_observation`（点数/面积 <300）只挡住了前 11 帧，挡不住“点足够多但只见下半身”的情况。
- t=12.0 s 之后：人离开视场，前景 5–22 点，三条路线均无候选（正确拒识）。
- 结论：**“人体不完整”是当前数据与算法的真实难点**，任何只按高度/面积判姿态的规则都会在入画/出画时给出错误姿态。

## 6. 尚存的技术问题

1. **没有人工 GT**（最根本）：22 份有 meta 的会话 `human_annotations` 全空，无 `data/annotations`，无 `fall_events_v1`。所有召回率/误检率/准确率都只能是 NOT_EVALUABLE。
2. **D1 的背景是非因果的**（整段 p98），只用于对照实验；D2 用的是“声明的 50 帧空场前缀”，但该前缀是否真为空场没有独立证据，且 D2 前景主体是静态高结构而非人体——两段数据都不能替代生产 W1 的因果空场契约。
3. **B0 的背景被替换**：本轮给 3D 路线喂的是“逐射线 p98 前景点”，而不是生产 `build_snapshot` 的体素背景（D1 没有空场前缀），因此 B0 是“现有候选生成 + 现有几何”，**不是生产节点端到端**。
4. **2D 分割的过分割无解**：8 邻域深度连通 + 深度阈值会在人体表面出现深度跳变处断成多块；本轮固定的 3D 门限挡不住 6–14 像素的碎片。需要“跨帧碎片合并”或“最小支撑面积随距离归一化”，但那是新算法，需单独设计与验证。
5. **逐点时间戳精度不足**（float32，62.5 ms @ D1）：无法做运动去畸变，快速跌倒时的帧内几何会被拉长/压缩。
6. **部分观测伪影**：入画/出画/遮挡时，高度中位与面积指标失真，现有 T0/T1 都会给出错误低位判断。
7. **板端未测**：RK3588 上的实际耗时、内存、RKNN 兼容性全部 UNKNOWN（本轮未授权部署，板上也没有 `librknn*`/`/dev/rknpu*`，见 `hardware_inventory.md`）。

## 8. 最终推荐路线与下一阶段最小任务

**推荐**：**以 3D 聚类为人体候选的主干，2D 距离图作为“验证/精化”而非“替代”**。

依据（全部来自本轮实测）：

1. 2D 分割在结构边缘与深度跳变处过分割，直接当候选生成器会把 1 个人拆成 2–4 块（D1 52/126 帧），或把静态高结构切出“人形碎片”（D2）。
2. 但 2D 距离图在**边界质量**上有不可替代的优势：它是按扫描方向排列的规整栅格，同一个物体的像素是连通的，天然适合做**轮廓/面积/宽高比**这类几何不变量——本轮 T1 的“面积 495–756 px vs 3,900–5,300 px”“水平跨度 1.15 m”就是从 2D ROI 上稳定算出来的。
3. 因此下一步不是“用 2D 取代 3D”，而是“3D 定候选与轨迹，2D 定轮廓与时序形状”，并用**碎片合并 + 距离归一化面积**补上本轮暴露的过分割缺口。

**下一阶段最小任务（建议，需另行授权）**：

1. **数据**：为现有会话补人工标注（至少 1 段真实跌倒 + 主动躺下/坐下/弯腰各 ≥3 段），或换取新的独立真值路径；这是所有 G1/G2 结论的前置条件。
2. **算法**：给 2D 分量加**跨帧/跨邻域合并**（用现有 `merge_components` 的保守 3D 距离判据，门限沿用 0.06 m / 1.5×0.0087×range），并把“最小点数”改成“随距离归一化的最小像素面积”，重跑本轮同一套 B0/B1/B2 对照（同一前景、同一门限）。
3. **评价**：在有标注后按会话/场景划分 train/val/test，禁止相邻帧跨集合；主指标是事件级召回 + 每小时误报，而不是帧级“有没有候选”。
4. **板端**：只有在前两项有结论后，再申请一次 RK3588 纯 CPU 的原生（Python 3.8.10 / NumPy 1.17.4）性能实测；NPU 另行评估。

### 10.4 关键代码（最小复现片段）

**(a) 独立复核“点 → 栅格”映射（不依赖 ScanGrid）**

```python
az_tab, el_tab = loadtxt(az_csv, delimiter=','), loadtxt(el_csv, delimiter=',')
good = isfinite(xyz).all(1) & (norm(xyz) > 0.1) & (ring < 192)
az = degrees(arctan2(y, x)); el = degrees(arctan2(z, hypot(x, y)))
for r in unique(ring[good]):                      # 每行单独取最近列
    row = az_tab[r]; flip = row[0] < row[-1]
    key, table = (az[m], row) if flip else (-az[m], -row)
    right = clip(searchsorted(table, key), 1, len(table) - 1); left = right - 1
    col[m] = where(abs(table[left]-key) <= abs(table[right]-key), left, right)
ok = (abs(az_tab[r, col] - az) <= 0.02) & (abs(el_tab[r, col] - el) <= 0.02)
# 输出：matched=100%，max|Δaz|=0.0100°，max|Δel|=0.0100°，冲突 0
```
