# HF-CONSOLE-02 · 真人倒地演示修复与控制台入口

本轮保留 pointset/r01 的八段动作入口，并把 real_fall/r04 真实录制回放作为独立卡片加进总控制台。桌面快捷方式仍指向 `Console_Pointset.exe`，已按该规格重建并通过冻结启动检查；发布 ZIP 同时包含 `Console.exe` 与 `Console_Pointset.exe`。

## 视觉与算法诊断

这段演示的主要瓶颈是稀疏点云下的几何不稳定和数据/时间链路。原录制约每 0.105 秒一帧（约 9.6 Hz）；实时页面旧剖析中，帧读取与 JSON 处理的 P95 约 58 ms、整次更新约 130 ms，而绘制约 2 ms，未显示 GPU 绘制是主瓶颈。稀疏躯干点在侧躺/过渡姿态下使 PCA 轴不稳定或部位槽变空；原首段背景混入条纹；逐帧重建显示对象又增加浏览器更新负担。

real_fall/r04 已采用首段稳定帧的圈外背景残留图、移除了会削掉伸展肢体的站立 torso 半径裁剪、为弱轴设置有时限的方向参考、将点支撑测量与短时显示保持分开，并复用前端几何对象、按测量时钟播放、预取相邻帧和按需读取部位支撑点。显示平滑不改变跌倒事件逻辑。

实际截图对照显示：f10 原背景条纹不再连成明显的人体侧边，粗部位支撑从9槽增至12槽；但目标点从1352降至1208，少掉的144个点没有人工身份标签，不能断言全是家具。f47/f109/f118 原来分别为0/0/0个部位槽，新版为12/12/13个当前帧点支撑槽。END_A 的有效帧由88/164升至136/164、可用状态切换由32次降到17次、相邻帧原始位置跳变P95由0.759 m降到0.132 m。

背景建立使用开头0–4帧离线warmup，包含启动阶段内的帧信息；这不是整段实时因果背景更新。空场参考131958与配准来源仍有自参考限制，0事件不代表跨录制/长期误报率达标。

仍有明确回退：TOP_REGION显示跳变P95从0.123 m变成0.131 m；END_B有支撑帧从155降到120。与旧目标相比，新版总目标成员少12,965点，缺少人工人体/家具 GT，不能把移除点全部认定为背景。13槽仍是粗略点云区域，不是经验证的人体解剖关节。

## 倒地与机器学习判断

真实会话164帧、空场参考97帧。f72（7.460 s）保留唯一 `prototype_fall_alert`，事件明确为 `verified:false`；空场会话无锁定、无事件。它证明演示流程能从目标跟踪显示到候选告警，不证明跌倒识别准确率或空场长期误报率。人工事件区间、人体完整率、家具身份、关节位置和跨场景泛化仍未知。

目前不需要先加机器学习。更高优先级是获得完整人体/家具/关节人工标注，处理被背景模型吞掉或被目标提取删掉的点，并确认安装姿态与观测频率。ML姿态模型只能在有覆盖该雷达稀疏密度、角度、地面和家具域的数据后评估；它无法补回传感器没有观测到的点。已搜索的公开姿态路线仅作后续参考，本轮没有安装或训练模型。

## 控制台与核验

控制台首页现在有两个不同入口：“骨架与倒地检测”仍走 pointset/r01；“真人倒地回放”走 real_fall/r04。动态端口启动检查、源码检查和 `Console_Pointset.exe` 冻结启动检查均通过：r04 164帧、f72 13个有效槽、1个未验证事件；空场未观测、0事件。Headless Microsoft Edge 的真实壳页截图确认两个卡片分别打开各自服务，r04有两幅3D视图。两份 EXE 的 CArchive 内 `console.html` 均与源码逐字节相同；ZIP完整性检查通过，包含当前两个EXE、两个spec和当前README。

本轮没有运行单元测试套件，也没有打开 native WebView2 GUI 窗口；浏览器交互使用 headless Edge，冻结 EXE 通过无GUI启动模式验证。独立复审 NOT_RUN；解剖/身份真值与泛化 BLOCKED；设备/物理 NOT_RUN。状态为 SUBMITTED，不是 ACCEPTED。
