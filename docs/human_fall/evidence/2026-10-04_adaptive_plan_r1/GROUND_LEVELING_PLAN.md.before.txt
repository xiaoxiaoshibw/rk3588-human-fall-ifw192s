## 1. 目标与场景依据

用户说明并提供四张多视角截图：左侧是工位与椅子，中间是地面通道，右侧是台子，红框标注机器人。这些说明用于提出采样位置和排除对象，不能替代原始 XYZ、地面真值或安装测量。截图上的网格为显示参考，黑色空洞不能作为地面点。

阶段目标：识别可验证的地面，建立固定局部地面坐标，使离地高度、俯瞰视图、三维候选框、二维选择矩形和坐标读数一致；诊断当前背景/家具/机器人合并的大候选框，修复与地面及坐标直接有关的原因。

本阶段不承诺通用人体语义识别或骨骼。不把机器人、椅子等 unknown 几何候选改标 human；不以变小的框冒充人体识别完成。

## 2. 方法与引入决策

选定方法：**确认地面区域 → 空间均衡采样 → 候选阶段带法向约束的 RANSAC → 内点 SVD 精修并重新计算支持 → 独立帧组/区域验证 → 固定 ground_local 变换 → 在线有符号高度与可信区域监测**。

开源依据：

- [PCL 约束平面实现](https://github.com/PointCloudLibrary/pcl/blob/master/sample_consensus/include/pcl/sample_consensus/impl/sac_model_perpendicular_plane.hpp)：借鉴 isModelValid 在支持计数前检查法向夹角的机制。现有 NumPy ground.py 中移植这一方法，首版不新增 PCL 绑定或完整 C++ 节点。
- [PCL 法向估计说明](https://pointclouds.org/documentation/tutorials/normal_estimation.html)：复用现有内点 SVD，正确处理法向符号、退化与方向证据。
- [PCL 平面分割教程](https://pointclouds.org/documentation/tutorials/planar_segmentation.html)：RANSAC/距离支持作为可复现基线；教程阈值不直接作为本雷达参数。

选择改造已有实现，而非整库移入：现有算法/解析/契约已连接纯 Python 与 ROS，先补缺失约束和几何消费逻辑更容易验证。已有 NumPy、unittest、Three.js 足够覆盖首版计算与显示。若复制开源代码片段，执行者必须记录来源版本及保留原许可；方法借鉴与源码复制需分别说明。

本阶段暂不引入 Open3D、Patchwork++、LineFit、学习模型、IMU融合或 SLAM。单平面前提失败才带数据返回方案审查；现有 NumPy 原型耗时不满足预算时，先定位采样/迭代热点，再评估已有 Linux PCL C++ 隔离实现，不能未经审查随意换库。

完整调研及限制见 [方法审查](GROUND_LEVELING_METHOD_REVIEW.md)。该设计已经选定，具体 ROI、安装先验和数值门槛由 GL-00 提交证据并由 Codex 审核，不留给实现者边跑边改验收门槛。

## 4. 固定的几何与显示决定

- `ground_local` 是局部地面坐标，不是绝对地图/底盘坐标。源 frame、原始话题与时间标识保留。
- 单位 n 与 d 表示源系地面 `n·p+d=0`，向上方向需有依据。原点 `o=-d*n`；X为经确认的参考轴 a 在地面上的单位投影u，Y为 `v=n×u`，Z为n。
- `R=[u.T;v.T;n.T]`，`t=-R*o`，`p_ground=R*p_source+t`。地面Z=0，雷达原点Z=d。参考轴投影退化明确报错。
- 地面姿态来自测量，水平朝向/平面内原点来自约定；不能把派生记录写入已测外参字段后标 verified。
- 固定安装冻结变换，不能每帧重新配平导致目标和背景坐标漂移。坡地法向不等于重力竖直，本阶段限制平整室内。
- 原始模式显示源点云和源AABB；配平模式显示转换点云和由同一候选实际点重算的 ground AABB。二维框是当前三维框八角投影的外接矩形；选人仍发送原 snapshot/candidate_id，不发送裸像素坐标。
- 保留既有 source/reference 字段冻结语义；新的 ground 字段使用明确版本化兼容扩展，不把旧字段静默改名或改义。源/地面中心明确各自计算定义，不能把旋转后的源中位数混称地面点集中位数。
- 换标定使旧位置、快照和站姿基线资格失效；断流、未标定、范围外地面不能默认正常。
