# HF-05 网页选择后端、站姿基线与连续目标锁定
执行：OpenCode DeepSeek v4.1 Flash。依赖：HF-02～04。状态：WAIT_DEPENDENCY。

先读 ../DISPATCH.md 并读取 ponytail SKILL.md。首版不做人脸识别/外观 ReID，也不做长期身份库。

## 工作与代码
- core/association.py：在同一经过标定的三维参考系关联相邻时刻的点云候选，使用预测位置/速度门限及几何连续性；没有相机投影/图像框。人工确认目标为人，算法只保证可观测范围内的连续编号，不承诺语义/生物身份。
- core/tracking.py：人工选择初始编号或指定位置候选，保存会话 track_id。用已安装实现或简单匀速预测和距离门限关联；仅当前确有多目标需要时用简单最优匹配，避免提前引入跟踪框架。
- 站到卧时允许尺度变化，匹配优先连续位置和深度；簇拆分/合并、多人交叉、接近门限的双候选输出 ambiguous，禁止静默换人。
- 短时遮挡输出 occluded 与有限预测，预测位置不能作为跌倒观测。超时 lost；完全丢失/歧义后要求人工重新选择，并重置跌倒时序历史。
- 实现网页选择/解除/采集站姿基线的板端入口与 request_id 回执，CLI 可保留作调试。请求绑定 session/epoch/snapshot/candidate_id/选择版本；检查源帧新鲜度与多候选歧义，拒绝旧快照、重复/冲突命令，不能接到任意像素框就猜米制目标位置。
- 锁定后支持采集稳定站姿基线，由 RK3588 验证位置/尺度/质量，写独立目标基线版本并返回 pending/ready/failed；失败不伪造标定。位置/距离和框来自板端观测，预测位置显式标记。安装/地面标定与目标基线分别报告。
- 候选、选择回执和目标位置信息按 [WEBUI_SCOPE.md](../WEBUI_SCOPE.md) 的新增草案提交 Codex 冻结；网页本身由 HF-11 实现，本单用合成/CLI 请求与 ROS 回放验收后端。

## 验收
构造两人交叉、相邻/深度不同、进出 ROI、遮挡再出现、簇合并拆分、姿态突变、时间回退和丢流序列。验收断言必须确认不换人、预测不增加跌倒证据、重新选择不会接续上一人的动作历史。真机报告身份切换、有效锁定比例和歧义频次，人工核对编号。

补测旧候选快照/跨 epoch 请求、重复选择/迟到回执、解除/切人、站姿基线质量不足与版本一致性。后端状态是选择是否成功的唯一依据，网页重新连接不自动重放旧选择。

## 回传
