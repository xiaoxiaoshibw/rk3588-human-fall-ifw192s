# HF-10 Codex 回传审查与返工
执行：当前 Codex。依赖：用户指定工单后，按 [CLI 工单闭环](../CODEX_OPENCODE_WORKFLOW.md) 取得 OpenCode 回传与实际差异。状态：持续审查流程；HF-00 与 HF-01 已按范围验收，最新工单结论见 REVIEW_LOG.md。后续工单仍逐次审查。

## 输入
../RETURN_TEMPLATE.md 要求的 returns/HF-xx.md、patch/当前差异、测试原日志、设备/数据/模型/参数版本，以及 CLI session ID、运行日志和退出码。Codex 直接从共享工作区读取，不再要求用户手动转交；外部 AI 不能把自己的 SUBMITTED 当作审查通过。

## 审查
1. 开工前读取 ponytail SKILL.md、当前 AGENTS.md 与冻结契约，核对每项修改范围、是否覆盖用户改动、是否无理由添加依赖。
2. 追踪真实调用链和同类调用，检查接口/单位/轴向/变换方向/时钟域，及节点启动安装行为。
3. 重点找“倒地被候选过滤”“另一人接替锁定”“丢帧当跌倒”“把设备 IMU 当人体 IMU”“相对骨架当度量位置”“没有下降历史仍确认事件”等问题。
4. 对核心边界测试/事件表做独立复现；无需把文档任务当成实现全部测试。mock、离线和真机证据不能互相替代。
5. 验证旧接口兼容、驱动两种 ROS 条件分支、工作树差异来源；缺构建环境以未验证注明。
6. 审查盲测标签/分割与事件级统计、防重复计数、误报/小时分母、性能时钟条件、日志和配置对应哈希。

## 输出
更新 ../REVIEW_LOG.md：PASS（仅明确通过的部分）、REWORK（具体缺陷/复现/要求）、WAIT_DEVICE（无真机证据）。工单整体达到验收再标 ACCEPTED。返工要求包含原编号、文件/函数、失败触发、预期行为与复现命令，不泛泛“提高准确率”。

本轮已审查 Luna 静态报告，不代表外部 DeepSeek 代码已审查。最终总体验收必须有真实数据和端到端验证，不能凭计划文件关闭项目。
