## 6. 算法路线与错误处理

### 6.1 背景：已审核空场优先，严格冻结

- 固定雷达场景使用审核空场参考；背景与动作序列通过通过质量门的变换对齐，场景改变即过期。
- 复用已有 v2 的参考/在线优先规则，诊断同时保留现行 P 和冻结参考对照。有人序列不参与永久背景更新，站立和躺着不动都不能仅凭持续占据被删除。
- 参考未覆盖的体素是 UNKNOWN，而不是“必是人体”；单靠保留未知前景会增加家具点，后续需要实例分类和污染评估。
- 不使用整段动作片构造背景再评估同一片；若明确离线初始化需要前几帧，输出 warmup 状态、当时的人工先验与可用范围。
- 093958 无足够独立地面支持则拒绝配平；换算法也不能凭空生成地面证据。215607 的 SHA mismatch 先修来源绑定，再谈几何效果。

静立自吸收是背景策略问题。Ouster 的官方调参文档也明确延长 stationary/background 时间会保住静立对象，同时会保留搬动后的家具；本项目可借鉴这种取舍，但不照抄其传感器参数：[官方背景保留说明](https://docs.ouster.com/ouster-detect/tuning.html)。

### 6.2 地面：配平与“删地面点”分开

先使用现有 TLS/SVD/RANSAC 工作台与留出门，冻结审核地面；不全面实现 GL-A～I。区分拟合一致性、物理高度和可观测性。

身体高度使用 `h = n·p + d`（n 已单位化）；薄地面带由独立空场噪声分布标定。低位身体不能沿用统一 `z < 0.1m` 硬删除；与地面混叠的点可标 UNKNOWN，在目标级利用当前空间/时序支持，而不是编造成可靠人体。

Patchwork++ 仅在“确有地面、全局平面不足”的数据上作离线对照。缺地面、室内有限视场与旋转多线数据的域差异必须单独验证。

### 6.3 聚类：三维实例 + 污染向量

复用现有 XYZ 密度聚类，保留 XY 对照。只调一个预登记变量；当前帧为首选，必要时比较0.1/0.2/0.5秒因果窗（候选值，按真实时戳），统计拖影与延迟。窗口更长不是自动更好；不拿未来帧提高在线结果。

“运动吸引周边点”先拆成可测原因：背景泄漏、时窗拖影、坐标/配平误差、密度链式粘连、遮挡和可能的传感器伪点。没有证据不要下物理归因。

聚类独立性先输出各分量，不急着压成一个总分：已标非人污染、未知点率、人体覆盖、碎裂数、多人合并、邻簇距离、近背景比例、当前帧支持比例、track 切换。用已审核样本才能标定组合权重；一个“高独立性分数”不能掩盖家具污染或无人标签。

### 6.4 骨架与事件解耦

保留13槽区域骨架用于解释；结果分别声明 REGION_ESTIMATE、PART_PREDICTION、ANATOMICAL_JOINT，不统一叫“准确关节”。每个节点关联本帧源点、raw位置、display位置、有效/未知原因和预测年龄。

PCA 弱轴可使用有上限的历史方向辅助，但没有当前点支撑的节点不得计入测量召回；轴平滑和画面插值不进入物理精度或事件特征。

事件采用当前点集支持的地面相对高度分位数、体宽/展长、轴方向、下降速度、低姿态持续与恢复。用源时间戳实现 STANDING/MOVING/DESCENDING/LOW_POSTURE/RECOVERING/UNKNOWN；质差或遮挡先 UNKNOWN。快速坐下、主动躺下等硬负例进入评估。f72 仍是未核验 prototype 候选；事件标注和证据门通过前不打开 HF06 confirmed。

| [CVAT](https://github.com/cvat-ai/cvat) / [3D工具说明](https://docs.cvat.ai/v2.0.0/docs/manual/basics/3d-object-annotation-basics/) | 3D框、对象审阅与标注流程 | 当前优先已有源点标注页；只有多人协作确需统一管理再引入 CVAT。不能把3D框标注能力推断成逐点人体部位/解剖关节工具 |

选择顺序：已有冻结空场 + XYZ聚类 → 已有 XYZ-RF/PointNet公平对照 → 一个 PointNet++部位候选 → 必要时一个 Human3D/LiveHPS探针。没有本地审核数据就不要以开源演示视频替代验证。

## 8. 统一核心与生产回流：逐段替换，不大重写

优先复用 `src/human_fall_detection/core/` 的 ReplayPipeline、tracking、features、fall-state 作为最终生产主核心；它已有 ROS wrapper 分离及确定性离线入口。新增的纯算法保持板端 Python3.8/NumPy1.17 兼容。PC学习模型运行在隔离环境，通过版本化输出进入离线实验；不得无声把 PyTorch/scipy/sklearn 变成板端必需依赖。

迁移采用三步：

1. **统一 I/O 与评估**：封装现有 P、v2、pointset 输出到同一结果契约，先用同源索引和时戳对账。不要立即逐字翻译 JS 规则。
2. **移一个明确通过的组件**：先背景/前景，再聚类；小规模源行和边界例做跨实现契约回归，验证静立/躺下/家具/无输入/错时戳/重复点。历史实现作为冻结对照。
3. **页面只消费结果**：框、部位、测量/显示骨架、质量和事件来自同一离线结果；页面不重新检测。ROS wrapper 后续使用同一核心。把复制版本逐步转为只读基线，而不是一次删除全部历史代码。

现有 JS replay 与 Python production 分属不同实现，fusion v2 在 JS 启用不能等同于 Python 生产已经修复。HF-INTEGRATE-01 必须明确迁移和跨实现对账的范围。

建议唯一 runner 由现有运行器扩展，参数包含 manifest/config/output，输出 frame_results.jsonl、metrics.json、event_results.json、run_manifest.json、报告和困难帧图；不再为每次试验复制 server/app/track/skeleton。

生产候选模式默认关闭；开启需当前明确工单授权与验收。关闭模式下生产原行为保持。设备部署另列工单。

## 9. 评估口径与拟议退出门

以下是**新受限离线阶段的建议门**，不是现有 W03/GL/V2 验收表的修改。执行前用 CALIBRATION 集确认可行性并登记冻结；不得看测试集后下调门。现有 V2“静立保留≥95%”继续原表口径，其他指标补充审查。

| 评估项 | 计算 / 限制 | 建议退出门 |
|---|---|---|
| 源数据与绑定 | 所有派生点可追到 session/frame/raw index；SHA与坐标链一致 | 100%可追溯；不确定/重复索引明确处理；不匹配拒绝评分 |
| 静立/低姿态点保留 | 审核人体点中被保留的比例，按帧/部位/会话分别出数 | 审核可见人体点总体≥95%；低位身体单列；不能用长期预测凑保留 |
| 人体点纯度 | 审核完整身份窗口：保留簇的人体点/全部簇点；无法判定单列 | 完整审核窗口精度目标≥95%；部分标签只报告已标污染与未知率，不报纯度PASS |
| 人体发现 | 运行时所选簇；一对一GT匹配，阈值 CALIBRATION 冻结 | 受限单人审核可观测帧召回目标≥95%；遮挡/区外按预先定义分层，不事后排除失败帧 |
| 空场与家具 | 独立空场HOLDOUT与已审困难窗口；候选/人体确认/事件分开计 | 无错误人体确认或跌倒事件；候选数量和非人泄漏公开，V2原0候选门仍按原表复核 |
| 关联与合并 | 已审核身份的一对一逐帧匹配；家具身份切换、双人合并、碎裂 | 受限单人无家具身份接管；双人另列挑战门，不以单人通过替代 |
| 部位/骨架 | 可见审核点mIoU；region raw与display分开；关节误差只在独立关节GT上评 | 最小链不依赖关节PASS；ML候选按预登记收益与成本晋级；UNKNOWN保留 |
| 事件 | 事件一对一匹配及容差在CALIBRATION固定；事件召回、延迟、误报/审核负例小时 | 首版只验候选可解释与不重复；泛化门待多次真实正例和足够负例时长冻结 |
| 性能 | 相同设备、输入规模、时窗；P50/P95、内存、来源等待与处理延迟分开 | Windows只作离线性能记录；板端门留到HF-DEVICE-01 |

点保留 R=|预测∩审核人体|/|审核人体|；完整标签下点精度 P=|预测∩审核人体|/|预测|。无完整审核时未知点率 U=|预测中的未标身份点|/|预测|，不能把 1−U 自动当精度。

短空场0误报只能报告观察结果。例如零误报的粗略95%泊松上界约3/T（T为审核负例小时，且依赖适用假设），几分钟零误报不足以证明低每小时误报。单次跌倒检出也不能估稳定召回。

门槛都需指定适用场景、审核完备性与分母，不让“总体平均好看”遮住静立、遮挡和低姿态失败。

## 10. 流程修复与证据成本控制

建议未来登记时把验收**按声明范围分层**：

- `SOFTWARE_REVIEWED`：指定独审通过软件契约，输入/命令/结果可复现。
- `OFFLINE_QUALIFIED`：冻结的真实审核数据与适用范围内达门。
- `DEVICE_VALIDATED`：授权目标板实测。
- 整体 `ACCEPTED` 仍按原工单条件判断；前三者是补充资格字段，不能把历史 ACCEPTED 的含义改掉。

软件工单可在自身范围内闭环，不让设备NOT_RUN强迫算法重复返工；但原来要求设备的工单仍未ACCEPTED。新模式先审批登记为新表，不追溯改旧表。

每轮只保留一张当前验收表、一份 manifest、一份机器指标、一份报告、一个回传入口；同一证据由HF/HR交叉链接，不再复制图表成多份“当前版本”。WORKFLOW仅增加当前真实状态，不能回填不存在的历史审查。后台缺依赖时不得默默回退后继续报同一算法名称。

artifact 重建需要重跑真实计算并保存新ID，旧artifact只读；签名覆盖输入、参考图、变换、算法/配置与schema。全文件SHA变更导致STALE先通过现行规则正确重建；若要改成模块级行为指纹，另开契约变更评审，不能借“减少流程”跳过漂移防护。

每轮审查时确认 Git diff 文件清单与大文件；把模型、raw capture、EXE/ZIP、缓存和批量输出从源码提交中排除，证据存储只保清单/摘要/必要图。现有45d53b8保留，不自动改写历史。任何清理/重写/提交动作另按用户授权执行。

停止/改道条件：

1. artifact 重建后仍 DEGRADED：保存原因，继续隔离诊断，正式启用停止。
2. 缺少源会话：原会话复验BLOCKED，补录属于新数据集，不算恢复原证据。
3. 前景保住人体但污染不达门：只做实例分离/家具硬负例的一次定向返工，不重新长出新副本。
4. 同一候选连续两轮冻结难例无改善：暂停该候选，统一评估器下比较下一条路线；不继续微调测试集。
5. 学习方法没有GT或环境一天无法跑通：暂停ML旁路，继续已验证最小链。
6. 独审未完成：软件状态停在SUBMITTED/REVIEW_BLOCKED；不让writer自审替代。

最终交付应让用户能从一个页面定位：哪段数据、哪个人、哪些点、什么质量、何时开始下降、为何产生事件、哪个门没过。新的算法值得进入生产，是因为同一审核集上证据更好且接口可复用，而不是因为又多了一份demo。
