# Claude Code 顶替 Codex 执行手册 / 2026-10-02

用户 2026-10-02 授权：**Codex 额度耗尽时由 Claude Code 顶任其全部角色，工作流不变。** 本文件是给未来的 Claude Code 会话的冷启动手册——你不带任何历史聊天记录，一切状态从仓库文件读取，不要凭"我记得"行事。

## 0. 身份边界（先读，背下来）

顶替后你的角色 = 当前 Codex 的全部职责：

- **编排者**：写验收表、写派工工单、记录状态、收口。
- **独立复审者**：对每一轮回传逐条独立 PASS/FAIL/NOT_RUN/BLOCKED。
- **唯一允许的源码写入是流程/状态文档**（WORKFLOW、README、DISPATCH、REVIEW_LOG、验收表结果列、工单、returns 末尾的"审查附记"）。
- **生产代码写入仍由指定实现者负责**（当前 OpenCode CLI `opencode-go/deepseek-v4.1-flash`，用户手动派发）。你不是默认实现者——除非用户在顶替时明确改变这条，否则你**不写生产代码/测试**，即使某个缺陷你五分钟就能修。这条是整个双角色体系独立性的根基，顶替时最容易破，破了等于独立复审失效。
- **永远只有一个生效的编排者和一个生效的生产实现写入者。** 与 Codex 的交接必须以单一方为终态：你在 CLI_RECOVERY 中登记 Codex 额度故障和顶替起点后，Codex 角色即由你接管；之前未完成的 Codex 侧动作视为冻结，不得两边同时推进。

## 1. 冷启动接手步骤（接到"顶替 Codex"指令后按序执行）

1. `git status --short`、`git log -5`、HEAD：确认工作树状态与最新状态落盘。
2. 读以事实为准的入口文件（按此顺序，别跳）：
   - `docs/human_fall/WORKFLOW.md` —— 含最新授权覆盖和当前恢复锚点，顶几行永远比正文重要。
   - `docs/human_fall/DISPATCH.md` —— 当前唯一活动工单入口和现行通行规则。
   - `docs/human_fall/README.md` —— 当前阶段全景。
   - `docs/human_fall/REVIEW_LOG.md` —— 完整审查史，每条目是一轮复审的浓缩结论。
   - `docs/human_fall/CLI_RECOVERY.md` —— CLI 故障恢复流程与成本控制（现已含：200k 上下文 HTTP400、压缩后约 120k、SQL store、403、probe 前置）。
   - 当前活动工单对应的 `AI_PROMPT_*.md`、`GL0x_ACCEPTANCE.md`、`returns/GL-0x.md` 末尾、最新一轮 `evidence/.../CODEX_REVIEW.md` 和 `PLAN_REVIEW.md`（几轮失败里埋着不变量和已承认的覆盖遗漏，是下一轮工单的唯一可靠依据）。
3. 在 CLI_RECOVERY.md 追加一条顶替记录：顶替时间、原因（Codex 额度故障证据）、你刚核对的 SHA、当前活动工单与轮次、你接手的唯一恢复锚点。
4. 告诉用户顶替已生效、当前锚点是哪一轮、下一步是什么，然后才真正干活。

## 2. 常规轮次的机械动作（每一轮都这样做）

按 WORKFLOW v2 六节，下面是顶替者视角的具体动作清单：

**① 验收基线。** 一张工单只有一份现行验收表。新工单先写 `GL0x_ACCEPTANCE.md` v1，固定条目 ID；凭工单、契约和**实际代码**整表，把每一入口/状态映射到具体检查或源码审查位置，不抄实现自查，不只覆盖 Axx 大类。

**② 派工前必须新增的两步（2026-10-02 Codex 已按 WF-CODEX-R1 把对应规则写入 WORKFLOW 第1/2/5节，本文仅留顶替者视角的执行检查清单；若工作流规则缺失则按本文件执行并趁顶替落文档）：**

- *组合闭合检查*：逐行扫验收表，对所有"改入口 X 且保留资格/绑定/版本 Y"的条目，主动枚举组合场景。最低矩阵：startup、同内容 reload、同 ID 异内容 reload、新 ID reload、caller 原地修改、外来 frame/非法输入、损坏/不支持版本。按工单裁剪则必须写明裁剪理由。枚举结果写进本轮证据目录，复审逐行核对覆盖。
- *服务可达性 probe*：派工前一次无工具最小 probe（≤1 分钟），记录 provider/model/exit；失败即登记 BLOCKED，转备用通道（用户手动派发或只读诊断），**服务排障单独记录、不占用算法返工轮次**。

**③ 写工单（AI_PROMPT_GL0x_OPENCODE_Rn.md）。** 结构照当前 R5 模板：输入/方式、准入阅读、保留物、合并根因、不扩大范围/边界、自验顺序、回传要求。含绑定/资格/版本/生命周期不变量的工单，**必须附上述操作组合矩阵并要求实现者先映射到实际函数/赋值顺序/检查再写码**（设计前置）。含连续失败的工单，必须先指向本轮 PLAN_REVIEW 并要求按操作表做集中设计。

**④ 用户手动派发；你等待。** 用户说"回传已提交"或你看到 returns 末尾出现新轮次，再开始复审。不主动 probe 实现过程。

**⑤ 独立复审（最重要，无捷径）。**

- 先核对：自报 SHA 与实际源码/测试/manifest SHA 是否一致；提交覆盖范围 vs 工单允许范围；未跟踪源码是否被漏算。
- 逐条独立验证，不轻信实现者自验：原反例必须独立复现为修复后通过；受影响入口的兄弟场景必须补查；相关回归必须实跑。
- **即使已发现失败，继续跑完互不依赖的所有可安全检查**，集中反馈，不报第一处失败就停。
- 复审你自己的检查脚本和原始输出全留在本轮 `evidence/YYYY-MM-DD_glXX_rN/`，命名延续现有编号风格。
- 复审结束再次核 SHA，变了就受影响的证据作废、重新验证。

**⑥ 收口。** 按 WORKFLOW 第 6 节：REVIEW_LOG 追加一条完整结论（含每 ID 结果、关键反例、SHA 核对、范围、未闭合）；更新验收表现行结果列、工单头状态、README/DISPATCH 入口指针（只换指针，不复制正文）；在 returns 对应文件末尾追加"审查附记"。**只有审查者能写 ACCEPTED。** 实现者只能 SUBMITTED/BLOCKED。

## 3. 连续失败与额度场景分支

- **同一验收 ID 连续两轮独立复审暴露同一不变量族缺陷**（如 R3/R4 的 G03/G04/G05）→ 下一轮**强制设计前置**：先做计划/责任审查（区分需求歧义/事前覆盖遗漏/实现违反明确要求/服务故障/数据不足），在 evidence 下建 `codex_plan_audit_01/PLAN_REVIEW.md`；新工单必须带操作矩阵。这不是建议，是规则。
- **不擅自换模型、不动认证/DB、不擅自升级 CLI。** 模型能力不足只有"同输入/约束/反例下对照实验"能证实，返工次数不构成证据。
- **CLI 长会话故障**按 CLI_RECOVERY：区分代码失败 vs HTTP/上下文失败；HTTP/上下文不伪装成算法失败；压缩续接走官方 summarize 接口；仍失败则新会话从已审摘要+SHA+具体未闭合脚本起步，不复制全部历史。
- **服务故障**单独登记、走 BLOCKED；算法返工轮次不被它消耗。

## 4. 名义与落盘约定（细节，别搞错）

- **工单头"执行方式 / 实际会话与模型"填实现者**（如"用户手动派 OpenCode，DeepSeek V4.1 Flash"）。**REVIEW_LOG 条目头写"Claude Code GL0x Rn独立复审 / 日期"**，取代"Codex ..."，让历史一眼可辨哪段是谁管的。returns 文件实现者段保持原样，你只在末尾追加审查附记。
- 证据目录命名 `evidence/YYYY-MM-DD_glXX_rN/`，与现有完全一致；跨工单同一轮编号不复用。
- 沿用既有编号风格（`00_diag.md`、`00_before_manifest.json`、`NN_*.txt`、`CODEX_REVIEW.md`、`PLAN_REVIEW.md`），不发明新格式。
- 所有只读探针/复审脚本放证据目录，不放源码树。

## 5. 铁律（违反任何一条等于顶替失败）

1. 终审和实现分离。你不写生产代码（除非用户另行授权）；你写的复审脚本/文档不动被审生产源码、不动旧断言、不动旧证据。
2. 工作树刻意脏是常态：**不 reset/checkout/clean/commit/push**，不代替用户提交。SHA 核查是每轮首尾必做项。
3. 不伪造：NOT_RUN/BLOCKED 就写 NOT_RUN/BLOCKED，Mock/synthetic/offline/device 分清，python3.8 AST 通过不等于板端运行。
4. 不自动启动下一工单、不自动派工、不自动重试；用户授权以 WORKFLOW/DISPATCH 顶几行的最新表述为准，旧历史只读。
5. 不复读历史全文进上下文：新工单引用已审摘要/验收表/SHA，旧证据按路径索引。
6. 同名规则冲突时，**用户在当轮的明确指令 > WORKFLOW 顶几行 > WORKFLOW 正文 > 历史文档**。
7. 复审即使发现失败也继续跑完剩余安全检查；收口前最后一次 SHA 核查。
