## 设计决策（ponytail 最小化）

- **8901 复用，不开新端口**：save 挂 `human_replay_lib.py` 既有 ThreadingHTTPServer 一个 POST 路由，不新增 node annotate_save.js、不引入 flask。
- **并发保护用 .tmp 残留即锁**：不另建 `.meta.json.lock`，os.replace 本身就原子；tmp 存在即锁信号，简单且一次写入必然清。
- **14 字段快照比对，而非全量 deep-equal**：human_annotations 是变量，其他字段全冻；`bak` 强制保留一份，写后失效立即回滚。
- **undo 栈 20 层，无 redo**：evict 最老；`edit` op 撤操作 v1 记 no-op（yagni：gizmo 拖中 panel 显实时数字已可读，「回到拖动前」由用户再拖一次）。
- **轴锁实现用 TC.showX/Y/Z**：不拿 axis 锁进 lib，直接驱动 TC 的 3 个 handle 显隐。
- **TransformControls mount 时机**：selection 后才创建，delete/deselect 时 detach 清场；跟随 apply_view_preset 切相机时**不重建**（TC 的相机字段在 r127 上是只读字段——不切相机做 v1 接受；已知限制条目见下）。
- **B 模式内 R/T 重分发 gizmo、outer 模式仍走 HR-04 view reset/front_view**：README §5 与 HR-04 键位契约共享前提 = 编辑器场景；B 进 annotate、V 回 view，两个世界互不干扰。

## 已知限制 / YAGNI

- 切相机（apply_view_preset）时 TransformControls 不重建 camera：r127 上 TC 的 `camera` 字段认为只读；v1 接受；如需 v2 在 `apply_view_preset` 末尾加 detach+new 一套。
- undo 栈 op=edit 的 v1 实现是 no-op（ponytail 决策：拖到一半中途撤销不常见；del/add/finalize 已逆），登记 op:"edit" 但回滚不做精细 mesh 状态快照——可进 HR-05 R1 rework 范围若用户要求。
- 数值面板不改 label/input focus 时机——焦点在 input 时全局按 R/T/B 会切 gizmo 模式（已知小坑，属一级产品决策：input 失焦再按键）。
- del 走 window.confirm 阻塞式（v1 硬防误删）；不引入非模态 toast。
- 服务端不再传 sha256 回写 meta：sha 是临时验证字段，不写进 json body。

## 服务侧稳定性（额外自检）

- 所有输入参数（sid、annotations array、box 字段）单点校验 → 400 返回；不抛 http server 500 traceback 兜底。
- 异常路径在 try/except 中显式带题目信息返回，os.replace/backup 有兜底不爆路径。
- 服务侧测试覆盖 9 条 path（含幂等、409、404、400 sid/400 size/400 center/400 source/400 missing box）。
