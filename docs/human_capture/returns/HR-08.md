
**Top features**: y_p50 (0.106), cy (0.093), y_p90 (0.085), y_p10 (0.066), cz (0.037)...

**判定**: **v0 满通过** — LI-DATA 在自家域 RF 能抓 fall/nofall 的姿势区别， 且几乎完美。

## 三、v1 — 在我们 IFW192S 会话上 inference （跨域实验）

## 四、为什么跨域失败 （分析）

打印 IFW192S f30 与 LI-DATA fall 的特征 10/50/90 分位：

| 特征 | IFW192S f30 | LI-DATA fall |
|---|---|---|
| x_p10..p90 | 0.00..4.43 | -3.00..8.76 |
| y_p10..p90 | -1.65..2.36 | 1.67..9.79 |
| z_p10..p90 | -0.84..3.68 | -1.00..1.10 |

**坐标系完全不同**:
- LI-DATA 虚拟雷达贴地， z 从 -1 到 1， 主要范围内的动作都在 z 区间内；
- IFW192S 高装俯视 192 线， z 从 -1 到 4, 主要动作横跨这个区间；
- x/y 轴向也不同

**这种坐标系原定义差异不能用「交换 x/y」修复**, 也不能用 z-score 归一化挽救—— 因为**z 的有效范围不同也带不同的语义**。

## 五、最终判定 — HR-08 v0+v1 收官， **不开 v2** (PointNet)

**理由**:
1. v1 全部帧误判为 fall (100%), 跟空场真相相去甚远。 RF 的「特征跨域」失败暴露：**小型 ML 无希望**, 必须用 IFW192S 本地数据
2. **我们没有 IFW192S 的标记数据**。要有， 得先回到人工 box 标注或 AI 判读+再训练 — 是**新一轮几个月**的工作
3. PointNet 也不会解决这个问题——它用同样输入特征， 我的 LI-DATA + 用户自采数据域差对神经网络一样是**灾难**
4.  mitigation 都需要 **IFW192S 数据在标注环里**, 需要先返回 HCI/GL/HR-01..06 主线先把数据收集起来再考虑 ML

**所以**: HR-08 开工一周， 完整落地 v0+v1, 但**定谁走不通**——继续走 ML 也是 HR-09 大卡， 不值得继续。

## 七、教训 (写入 memory)

1. **任何 ML 路线的 v0 (域内 accuracy) 必要** — 但不够， 必须 v1 （跨域测试） 才能判定管线是否真行
2. **LI-DATA 跟 IFW192S 是不同几何场景** — 雷达贴地 vs 高装， 坐标系都不同
3. **先采数据再讨论 ML** — 我们的会话数量太少， 姿势太少； 先让 HR-05/HR-06..07 主线稳定收集 + AI-判读模式， 再回来用 v0+v1 重测 ML
4. **RandomForest 在小特征集上很强**: 98.6% acc 完整一遍跑完只花 2 分钟， 代码用 5 行， 比「先在 torch 造 PointNet」代价低 10 倍
