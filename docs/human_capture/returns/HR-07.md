# HR-07 回执 — 最终： 两次独立几何路线都失败 (limb_lib 6 代 + vd_limb_pose_pilot 移植）

## 一句话结论

**任何纯几何 (geometry) piston 通过 IFW192S 192 线 LiDAR 输出做"四肢识别+弯腰事件"都不可行**,
原因不是代码不行, 是**点云分变不出人 vs 家具**——这是雷达传感器分辨率天花板。
若非要 limb, 必须改以下**任一项**:
- 传感器升级 （换 intensity 高、ring 密度更高的 LiDAR)
- 加外部载体 （反光盘, IMU, 或者人工 box 先标）
- 走 LiDAR ML (LI-DATA + 网络） 而非纯几何

## 实测证据 (2026-10-03)

跑两轮互相独立的几何路线：

| 路线 | 来源 | 我们数据结果 | 合成 GT 结果 |
|---|---|---|---|
| `limb_lib.py` 6 代 | 我自己 0→6 代 | 21 个假弯腰事件 | 全 none （验证为家具锁死） |
| `limb_v2.py` (chan-dynamic + PCA state + conf) | vd_limb_pose_pilot 核心移植 | 76 帧假 bend, 10 假事件 | 0 事件, 5% match |

无论怎么改公式， 一致结果：**假弯腰事件都出现在家具间切换的时刻, 不在真弯腰发生处**。

## vd_limb_pose_pilot 对比 (05-pilot-report.md)

作者在它自家 iTA-MOVE 数据集上能跑， 因为：
- 数据集是 TUM 公布的， 接受者**是专业被测者**「人形 EXISTS + 动」
- 雷达帧率高 （可能 20Hz), 0.3m 帧间位移阈值在 50ms 内人能划出 0.3m —— 对被测者而言刻意
- 整个 report 里没有「误检到家具」的事件 ——说明他们场景里**静家具相对被测者不强**

我们的真实会话：
- 被测者静立 7s, 沙发/高柜件密度+外形跟人并列室内， iTA-MOVE 那种 clean 场景不成立
- 192 线 LiDAR IFW192S (16 线 ×12 发射你） 实际 evidence: ring=0..191
