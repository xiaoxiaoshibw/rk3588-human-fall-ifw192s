# HC-02 — 录制生命周期、自动停止、FIFO、非干扰实测

> 前置：HC-01（REST/状态机/store 已在板 8766 跑通）。
> 录音机 = 现成 `human_fall_detection/scripts/record_session.py`（D10），不重造。

## 范围（做什么）

- `core/recorder.py`：录制编排器。
  - `POST /api/v1/record/start` → `subprocess.Popen` 起 `record_session.py --until-interrupt --output-dir=<staging>`，登记 sessions.json 为 `recording`。
  - `POST /api/v1/record/stop` → 向前台录制进程组发 **SIGINT**（record_session 收到后自己校验、写 manifest、exit 130），随后置 `extracting`。
  - 看护循环（线程，1s 步）：
    - 录制时长 ≥ `max_duration_sec` → 自动 SIGINT；
    - 盘余量 ≤ `disk_floor_mb` → 自动 SIGINT（并 log 理由）；
    - 子进程意外死 → 状态置 `failed(reason)`。
  - 子进程退出后：解析 `record_session` 写的 `{sid}.manifest.json`（bag.size_bytes、summary.message_count、duration_s、sha256），回写 sessions.json，置 `extracting`，等 HC-03。
- `core/fifo.py`：后台清理线程。
  - 每 `fifo_interval_sec` 扫 sessions.json；
  - 总数 > `fifo_keep`：先删 `transferred=true` 的最老，再删其他非活跃状态（严禁删 recording/extracting/transferring）；
  - 盘余 < `disk_floor_mb`：无视 keep 上限，强清最老`transferred`，直到回到水位线上或无可清。
  - 删除 = 删 `{sid}.bag/.manifest.json/.reserve` 文件 + store 状态置 `purged`。
- `/api/v1/status` 的 `ros` 字段接真实探测（HC-01 留白 "unknown"）：用 `rosgraph` 试连 master（不引入新依赖，rospy 已在）。
- 单测（不依赖 roscore）：录制编排器起停（mock record_session）、超时/水位触发 SIGINT、子进程死了的兜底、FIFO 各优先级、FIFO 与水位互斥、状态机接线。

## 不做什么（防漂移）

- **不做 bag→bin 抽取**（HC-03）。本单停止后状态到 `extracting` 就停手。
- 不做 PC 下载（HR-01）。
- 不做网页 UI（HC-04），但 REST 端点先行以便 UI 只是调用方。
- **不动 record_session.py 本体**（它已验收）。发现它需要的东西一律以 CLI 参数喂。
- 不并发录制：全局锁，第二个 start 直接 409。
- 不做磁盘写速基准收集(归 HC-02 证据，不写新工具)：靠 manifest.summary 对账 + rostopic hz 实测。

## REST 增量（v1.1，加在既有路由上）

```
POST /api/v1/record/start  {}                       → 201 {session_id} | 409 已在录
POST /api/v1/record/stop   {}                       → 200 {session_id,transition:"extracting"} | 409 没在录
GET  /api/v1/record/current                         → 200 {session_id,elapsed_sec,...} | 204 无
（HC-01 的 /api/v1/sessions/* 原样保留）
```

## 配置追加（capture.yaml v1.1）

```
max_duration_sec: 300        # 单次录制硬上限；0=不限（对手动 stop）
max_idle_record_sec: 30      # 检测到无新消息时安全带（topic 卡死），HC-02 可后续
fifo_interval_sec: 30
record_script: /root/catkin_ws/src/human_fall_detection/scripts/record_session.py
record_config: null           # 可选，传给 --config；默认走 record_session 自带 DEFAULT_TOPICS
sigint_grace_sec: 15          # SIGINT 后给 record_session 写 manifest 的宽限
```

## 非干扰边界（铁律 -> 实测项）

| 项 | 保证 | 实测 |
|----|------|------|
| 驱动/HF/bridge 存活 | 录制只多一个 rosbag 订阅；roscpp 慢订阅者只自身丢帧很差时伤的是 bag | 录制中 `rosnode list`、`rostopic hz /innolidar_points`、HF 容器日志无异常 |
| 网络 | 录制全程不走 eth1 | 录制中 eth1 流量与录制前基线一致 |
| CPU | record_session 子进程单核内 | 录制中 `top -bn1` 抓 load |
| 掉帧 | bag 缓冲 1GB | manifest.summary.message_count vs topics 消息频率 × 实测时长 对账，缺帧 <2% |
