## 一、为什么立案

HR-08 关了, 但关的是「用别家雷达数据集跨域迁移」这条路, 不是 ML 本身。
2026-10-03 同日复测把结论钉死:

| 实验 | 设置 | 结果 |
|---|---|---|
| v0 域内 | LI-DATA 65487 帧 (fall=33095 / nofall=32392), RF 5-fold | **acc=0.999 F1=0.999** |
| v1 跨域 | 同模型推到 IFW192S 6 段会话 590 帧 | **fall=590/590 (0 nofall)** |
| 空场金标 | cap_20261002_223757 + 233210 (AI 判读空场 264 帧) | **❌ FAIL 264/264 全误判 fall, avg P(fall)=0.93** |
| 合成金标 | synth_bend_v1 (合成站立弯腰 190 帧, 应全 nofall) | **❌ FAIL 190/190 全判 fall, P=1.00** |

**结论只有一句**: 域差是数据层面的, 不是模型层面的。
PointNet/加大模型/调参都救不了——HR-08 用 4000 帧/类, 本次用全量 32500 帧/类, 跨域照样 0/264。
唯一正路是**用 IFW192S 自家带标签数据重训**。

## 三、数据采集计划 (用户现场执行, 本工单不开工)

用板上 `capture_server` (:8766) 录, 每段 100~200 帧 (≈10~20 s), 单一姿势为主:

| 类别 | 段数 | 内容要点 | 对应 HR-05 之前哪条 |
|---|---|---|---|
| stand | 2 | 静止站立, 位置专场内不同 | HR-07 同类 |
| walk | 2 | 场内走动, 横越雷达视场 | 同上 |
| sit | 2 | 坐沙发 / 坐椅子 / 起身 | hard negative vs fall |
| squat | 1 | 深蹲 + 起立 | 同上 |
| lying | 1 | 主动躺地板 (模拟"已跌倒相") | 帮模型分 fall 相 vs fall 过程 |
| fall | 2 | 真倒地动作 (安全方式) | **关键正例** |
| none | 2 | 空场 / 只有家具移动 | **关键负例** |

共 12 段, 预计现场 40~60 分钟。录完用 HR-01 `fetch.py` 拉回 PC, 落在 `captures/remote/cap_<日期>_<时间>/`。

> 说明: 100~200 帧/段 × 12 段 ≈ 1500~2000 帧, 是 RF 级别的起步量。
> v0′ 通过后若要升 v2 (torch/PointNet), 再扩到 ~50 段; 本工单不含 v2。

## 四、标注计划 (AI 判读, 未开工)

模板复用已打磨的 `render_frames.py` 链路 (HR-07 遗产, 在 `pc_apps/human_limb/`):

1. 每段会话渲染顶视拼图 (~10 帧/段, 抽稀)
2. AI 逐段读图, 输出 `<sid>/ai_labels.json`, 契约:
   ```json
   {"session_id": "cap_...", "labelled_by": "...", "posture_set": [...],
    "frames": {"0-99": {"posture": "stand", "x": 2.0, "y": -1.0, "r_xy": 0.7, "confidence": "high"}}}
   ```
3. **存在性闸**: posture 全 none 的会话 → 归入 `none` 类训练料或丢弃, **不得**当姿势样本
4. z-band 圆柱审计复核: 站/走/lying 段在其 (x,y,r_xy) ROI 内 z-max 应有区分 (站 >1.2, lying <0.5)

`frame_feature.py` 输出的是**整帧 51 维全局特征**, 含 ROI 无关项——所以如果一段会话有多物体, 直接整帧特征会把沙发也平均进去。开工时根据 AI 判读的 (x, y, r_xy) 把点云裁 ROI 再提特征, 这一步**是新代码**, 但不改 `frame_feature.py` 本身, 外层加个 `crop_roi(xyz, x, y, r)` 即可。

## 五、重训计划 (未开工)

```bash
cd pc_apps/human_ml
# 1) 新 loader: iter_sessions() 产 (xyz_roi_cropped, posture, session_id, frame_idx)
#    复用 fetch.py 的 28B stride 读取; posture 二值化: fall→1, 其它→0 (none/squat/sit 也=0)
# 2) 特征: extract_features 原样
# 3) 训练: train_rf_v0.py 入口原样, 数据源换 iter_sessions
python train_rf_v0.py --out ML/docs/rf_v1_ifw192s_report.md
# 4) 跨会话留一验证 (leave-one-session-out): 12 段 → 12 fold
```

**Train/val 切分铁律**: 以**会话**为 fold 单位, 不以帧——同会话相邻帧高度相关, 按帧切会虚高 acc。
