## 目标（原始）

参考 `pc_apps/human_replay` 离线 webui 模式，在 PC 侧用 NumPy 算法对采集会话
做实时人体四肢+躯干关键点识别，让用户连续弯腰两次可被实时标定。
**不烧 PCL 环境**——HR-06 conda 装到一半网络挡 pac 不补， 直接 NumPy 起步。

## 交付物（已写代码， 不再维护）

- `limb_lib.py` — 单帧检测核心： RANSAC 地 (z0 平地预设） → 三段带 (low/mid/high) 人形评分 / 网格密度单峰 → 躯干 PCA (axis 无关， 0..90° tilt) → 四肢 extrema 投票
- `limb_viewer.html` + `limb_server.py` (127.0.0.1:8902) — 会话面板 + 🎯 点 lock + ↻ 强制重跑

- `LimbTracker` — 跨帧 EMA (α=0.65, 0.15 s) + 突变保护 + 静态陷阱 + 用户 pin seed
- 单元测试 2 通过 （合成直立人 + 地面）

实测 (i7 本地）:

- 锁到正确目标时 bend 90° tilt 测到真实弯腰事件
- 但**无法稳定 lock 到人** — 见失败分析

## 失败分析（为什么 A 是正确选择）

场景： 17 秒室内会话， 含**多件家具 + 1 名被测者**：
- 沙发 `(1.0, 0.7)` — 柱形密度片段
- 高柜 `(2.10, -1.80)` ~ `(2.80, -1.48)` — 三段带特征与直立人完全相同
- 其他墙/挂物若干

6 代算法均无法稳定区分人 vs 柜：
1. **v1** 密度峰 + PCA → 永远锁密度最高的柜
2. **v2** 强制平地 + z-spread → 把弯腰人也滤掉了
3. **v3** 三段带人形评分 → 柜正好三段都有点， 分不出
4. **v4** 用户 pin (𝐱=1.0, 𝐲=0.7) → 用户看到的彩色团是沙发， 不是人
5. **v5** bg_subtract 跨 4s → 静立者被滤； 且 4s 内沙发即人有小动作
6. **v6** hint-only pin → 家具间振荡、假弯腰事件 21 个

判定： 想用 geometry 区分必须引入**额外维度**——temporal velocity、skin
intensity、颜色 / 反光盘， 或人工 box 先标。否则**这个场景的根本限制**改不了。

## 保留可复用的算法工件

沉淀在 `limb_lib.py`:
- **轴无关 torso tilt**: PCA 主轴 ± 等价， 报与天顶锐角 (0..90°) — 任何深蹲/
  弯腰/倒地测量都该用
- **LimbTracker::smooth 突变保护**: EMA 向量混合 |prev+cur|<0.2 时直接换新轴，
  避免 axis 对称翻转时被均线拉到 0
- **lock_seed ≠ ROI cage**: 用户 pin 当 hint 而非 constraint, 跨帧 tracking
  自己跑， 否则 tracker 会卡死在 24° 不动的柜上
- **HTML viewer + 点选 → server 写 limb_lock.json + 重跑 prepare** 流程可参考
  HR-05 annotation 链路
