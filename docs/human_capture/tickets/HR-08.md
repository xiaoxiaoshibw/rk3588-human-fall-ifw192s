# HR-08 — LiDAR ML 支线 （感知模型： 点云姿势分类）

> 用户拍板： 2026-10-03 "LiDAR ML 你这就当作支线开发了"
> 位置： `pc_apps/human_ml/`
> 上游： 关闭的 HR-07 (limb 几何失败） — HR-08 是它的重启替代

## 一、为什么走 ML

HR-07 失败根因： 纯几何无法区分人 vs 家具， 是 IFW192S 分辨率天花板。
ML 路线的优势： 网络自己从数据里学**人形模式**, 不需要我写规则。
**但**: LI-DATA 域差 （虚拟贴地雷达） 跟 IFW192S （真实俯装 192线） 不同， 不学但 ML 可以自学该差距。
**所以 HR-08 不是 PointNet 训练**, 是先做**小成本低风险信号实验**——证明ML 在我们的数据上**比几何好多少**。

## 二、 起步设计 (ponytail)

**三种渐进资源**:
1. **v0 （最小）**: 用已经装的 scikit-learn RandomForest/MLP 在 LI-DATA 上训练 姿势二分类 (fall/nofall) baseline → 看 RF 能拿多少 acc
2. **v1**: 用同样 RF + 特征工程在我们的 IFW192S 会话上 inference, 看跨域迁移 accuracy
3. **v2 （开工单）**: 若 v0+v1 显示 RF 大幅优于几何 （改善 >10%) 再用 torch 训练小网络 (PointNet-小型 / PointMLP) + 自造 IFW192S 数据

**HR-08 scope （本次工单）: 只做 v0 + v1** — 不超 2 天， 加最小依赖， 用 sklearn 已装。

## 三、 数据源分析

### LI-DATA (D:\Code\ldiar\LI-DATA)
- 900 个姿势序列， 65487 帧 CSV， 每帧 ~70-290 点
- 字段： `categoryID;partID;X;Y;Z;distance;X_noise;Y_noise;Z_noise;distance_noise;intensity;red;green;blue`
- fall vs nofall 二分类已能 data split
- **域差**: 虚拟 LiDAR **z≈0 贴地**, 跟 IFW192S **高装俯视**几何差异严重

### 我们 IFW192S 会话 (captures/remote/cap_20261002_*)
- 每帧 49k 点 (LI-DATA 是几十到几百）
- 俯装， 192 ring
- **没有姿势标签** 只有 ai_labels.json 一堆 none

## 四、 v0 训练料特征工程

特征 (per frame, 长度 ~50 dim, 简化 PointNet 喂给 tree):
- 基础 9 维： N points / z_range / xy_range / pts_mean_xyz / pts_std_xyz
- 分布 12 维： z/x/y 的 (10/25/50/75/90) 分位
- 地面分 5 维： 高度带 (<0.3 / 0.3..0.8 / 0.8..1.4 / 1.4..2.0 / >2.0) 点数比例
- 形状 12 维： PCA 三主特征值 / 圆柱评分 / 球形度 / 出 ratio 落地高度

**不用骨架， 不用跟踪** — 因为它贵。用全身分布形态当输入。

## 五、 v0 交付 (LI-DATA 上 RF baseline)

- 加载： `pc_apps/human_ml/lidata_load.py` → 读取 zip 里 CSV, 按次分割 fall/nofall
- 特征： `pc_apps/human_ml/frame_feature.py` → 每帧输出 50 维 feature
- 训练： `pc_apps/human_ml/train_rf_v0.py` → k=5 fold, RF(n_estimators=100, max_depth=20), 输出 acc / f1 / confusion matrix
- 报告： stdout + `ML/docs/rf_v0_report.md`

## 六、 v1 交付 （我们真实会话 inference)

- `pc_apps/human_ml/apply_v1.py` → 跑所有 captures/remote/cap_*/ 会话， 每帧 inference
- 输出 `<sid>/ml_labels.json`: per-frame `{"posture": "fall"/"nofall", "prob": 0.xx}`
- 跟 `ai_labels.json` （来自 AI 判读） **不比较直接 accuracy**——ai_labels 都是 none （空场） 而是看：
  1. **空场会话应该 100% 输出 nofall** — 空信号测一发
  2. **接下来重录的会话** 用 ai_labels.json 打分**正式验证**

## 七、边界 / 不做什么

- ❌ 没装 torch / PointNet / PointMLP — 那属于 v2 开工单
- ❌ 没写 board side inference 板端推理 (SLAM/推理 timing)
- ❌ 没改 `human_fall_detection/` 主链路 — HR-08 只懂 standalone
- ❌ 没重新标定 LI-DATA 域差 — 先用 RF 看特征能不能跨越域差拿分

## 八、验收 (R1..R6)

- R1: `pc_apps/human_ml/` 存在， 文件不超 6 个， 全 Py 3.12 stdlib+numpy+sklearn
- R2: lidata_load.py 能加载 LI-DATA 不报错， 输出 N fall/N nofall summary
- R3: train_rf_v0.py 训练后 acc >= 0.75 (LI-DATA fall/nofall 不算难的问题， 应该到 90%+)
- R4: apply_v1.py 对空场会话 cap_20261002_223757/233210 输出 100% nofall
- R5: 报告 `ML/docs/rf_v0_report.md` 含 metrics + 特征重要性 + 后续路线建议
- R6: 所有工卡文档 → `docs/human_capture/returns/HR-08.md`, 失败记忆 → memory/
