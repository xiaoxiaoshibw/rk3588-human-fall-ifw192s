# HC-03 — bag → meta.json + points.bin 抽取

> 前置：HC-02（板上有真 bag 可抽，cap_20261002_163621.bag）。
> 板上决策（2026-10-02 实测）：rosbag python 模块直接可用（无需 pip 装新东西），
> PointCloud2 字段表 26B/point，含 x,y,z,intensity,ring,timestamp，选择全部保留。

## 范围（做什么）

- `core/bag2session.py`：单次抽取函数，输入 bag 路径，输出 `meta.json + points.bin` 到会话子目录。
- 抽取时过滤 NaN/Inf（`is_dense=False` 必有），并把被滤掉的点数记账进 meta。
- 时间戳：rosbag 的 per-message `stamp`（bag 内时钟）+ PointCloud2 header.stamp（雷达上电秒，HF 同源声明）都写入 meta；per-point 时间戳保留在 points.bin。
- sha256(meta.json) + sha256(points.bin) 写回 store，state: `extracting → ready`。
- 由 capture_server 的 watcher 在 extracting 完成后**自动串联**到本抽取（同一台板内，无需手工触发）。
- 单测：用一个手工构造的小 bag 抽一次，核 meta 字段、点字节布局、NaN 过滤、
  frame_count、sha256、state 迁移。

## 不做什么

- 不做剪辑 / 不做标注（HR-02..05）。
- 不做 bag 压缩回灌、不做 lz4 重写（输入是 record_session 写的原始 bag，格式保持原样）。
- 不做跨包/多 bag 合并。
- 不动 record_session.py / 已有 bag。

## 格式定稿（README §2 打补丁）

`points.bin` 每点 **28 字节**，4 字节对齐：

```
offset  size  dtype        含义
 0      4     float32-LE   x (m)
 4      4     float32-LE   y (m)
 8      4     float32-LE   z (m)
12      4     float32-LE   intensity (0..255 float)
16      2     uint16-LE    ring (0..191, InnoLiDAR IFW192S 线数)
18      2     pad          0（保留给 flag，比如 ground/non-ground 位）
20      4     float32-LE   timestamp (秒，本帧相对时间，雷达 per-point)
24      4     pad          0（32 字节行余量，后续若加 label id 可用）
```

meta.json 的 `point_layout` 反映上述；`frames[i]` 的 `offset_points/count_points`
仍按"点"索引（字节偏移 = i × 28）。

每点相比 A(16B) 多 12B；50 帧 × 49K 点 ≈ 69 MB（vs 39 MB），可接受。
