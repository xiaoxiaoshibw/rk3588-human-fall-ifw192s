# HC-01 — capture_server 骨架与 REST 契约

> 计划见 ../../docs/human_capture/README.md §3。本单是整条支线的地基：
> 先把 HTTP 控制面和会话状态钉死，后续 HC-02..04 全在这上面长。

## 范围（做什么）

- ROS1 Python3 包 `src/human_capture/` 落地（package.xml/CMakeLists/launch/config）。
- `core/session_store.py`：会话元数据存取（sessions.json，原子写 + 锁）。
- `scripts/capture_server.py`：stdlib `http.server` 起 :8766，REST 契约见下。
- `config/capture.yaml`：端口、暂存目录、FIFO 上限等默认值。
- API 契约固化（后续单只加字段不改字段语义）。
- 单元测试：健康/状态/会话 CRUD/sessions.json 读写/原子写并发。

## 不做什么（防漂移）

- **不起 rosbag、不调 record_session.py**（HC-02）。
- 不做 bag→bin 抽取（HC-03）。
- 不做 FIFO 清理的实际删除动作（HC-02；本单仅状态字段到位）。
- 不做网页 UI（HC-04）。
- 不做任何文件下载/上传端点的实际传输（HR-01 消费会话状态即可，
  文件本体走 PC 侧 scp 拉取，不经 8766 数据面）。
- 不做鉴权（D2）。

## REST 契约（v1，冻结）

```
GET  /healthz                      → 200 {"ok":true,"service":"human_capture","version":"0.1.0"}
GET  /api/v1/status                → {"ros":"up|down","disk_free_mb":int,"sessions_total":int,
                                      "recording":bool,"uptime_sec":float}
GET  /api/v1/sessions              → {"sessions":[SessionSummary,...]}   # 按时间倒序
POST /api/v1/sessions              → 手动登记一个会话（录入器用），body=SessionMeta
GET  /api/v1/sessions/{id}         → SessionMeta 全量
PATCH /api/v1/sessions/{id}        → 状态机迁移 {"state":"...", "extra":{...}}（合法迁移才接受）
DELETE /api/v1/sessions/{id}       → 删除登记（不删文件本体，FIFO 才删文件）
```

SessionMeta 关键字段：`session_id, state, created_iso, duration_sec,
frame_count, bag_path, meta_json_path, points_bin_path, size_bytes,
source_bag_sha256, download_requested:bool, transferred:bool, error`。

状态机（README §8）：`recording → extracting → ready → transferring →
transferred → purged`，异常 `failed(reason)`。非法迁移 PATCH 返回 409。

错误格式统一：`{"error":{"code":"...","message":"..."}}`，HTTP 4xx/5xx。
