# HC-04 — 板端控制网页（REST 调用 + 状态可视化）

> 前置：HC-01..03 板上链路 recording→extracting→ready 已全通。
> 板端 8090 = 现有 index.html 实时预览（**不动**）；本单是**新页** `webui/human_capture/`。

## 范围（做什么）

- `webui/human_capture/index.html` `capture.js` `capture_lib.js` `capture_lib.test.js`。
- 状态栏：ROS 状态、盘余量、sessions 总数、是否录制中、ws 连接状态——全部来自 8766 REST。
- 录制控制台：状态徽章（recording/extracting/ready/failed）、当前会话 ID、
  elapsed 秒、frame_count（状态更新从 GET /api/v1/record/current 拉）、开始/停止按钮。
- 会话列表：时间倒序表，列 = session_id, state, duration_sec, frame_count,
  size_MB, transferred, created_iso, 操作（"触发下载"对 ready 的）。
- "触发下载"按钮 = PATCH extra `{download_requested:true}`，PC 侧 fetch.py 轮询取走。
  （HR-01 才真的下载，本单只是给 PC 打标记）
- 添加"查看实时预览"链接到 8090 那个旧页（iframe 不嵌，省维护）。
- **`capture_lib.js`** 抽出可测纯函数（fmt_bytes / fmt_duration / state 颜色映射 /
  会话行渲染数据），**node 可跑测试**。

## 不做什么（防漂移）

- **不嵌 3D 点云视图**——8090 旧页专门干这事，新页只做控制。HC-04 v2 再说。
- 不做刷新按钮（自动 1s 轮询 /status, 2s 轮询 /sessions）。
- 不做剪辑/标注。
- 不做鉴权 UI。

## 自动轮询契约

- `/api/v1/status` 每 1s
- `/api/v1/sessions` 每 2s
- `/api/v1/record/current` 仅 recording 时每 1s（否则不轮询）

按钮幂等：start 点击后禁用 2s；stop 同理。失败时把 server 的 `error.message` 显示出来。

## 部署

webui 静态目录容器内路径 `/root/catkin_ws/webui/human_capture/`，由既有 8090 python http.server 自动托管；URL: `http://192.168.3.125:8090/human_capture/`。不改 8090 服务本体。
