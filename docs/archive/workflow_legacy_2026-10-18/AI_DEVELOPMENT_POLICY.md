# HUMAN-FUSION：分阶段 AI 开发规范

本规范由根目录 AGENTS.md（Codex）和 CLAUDE.md（Claude Code）共同引用，适用于 HUMAN-FUSION / HFUS 人体检测跟踪、点云完整性与恢复、背景/前景/聚类、RF/XGBoost、深度与时序模型、Demo/回放/GT/评价。Ponytail 用于减少工程浪费，不能限制合理算法、实验规模、可观测性或证据保留。

## 开始任务时自动选择

先问：目标是在研究未知算法/效果，还是工程化已知方案？用一句话声明策略与依据，在工单现有回传中记录即可，不新增审批或逐改动报告。按目标和验收判断，不能仅按文件名、模型名或“优化”关键词分类。

| 任务目标 | 默认策略 |
|---|---|
| Bug 修复、保持行为的重构、重复接口合并、回放/标注/WebUI/Demo、已知行为性能优化 | ENGINEERING |
| 新点云特征、背景/前景/聚类研究、运动一致性、点集恢复、轨迹/时序算法、RF/XGBoost 特征消融与重训练、PointNet/PointNet++/深度网络实验、效果验证 | RESEARCH |
| 优化已有跟踪 | 保持输出与协议只改善耗时/结构：ENGINEERING；改变关联、身份保持或研究识别效果：RESEARCH |
| 合并已通过独立测试的算法、统一检测管线、清理已确认无效实验代码、部署前整理 | CONSOLIDATION |

混合任务按子任务分别选择，共用输入/评价协议；算法效果不确定时默认 RESEARCH。阶段目标改变时说明一次切换及证据即可，无需为切换另开工单。缺少独立验证时不得进入 CONSOLIDATION 宣称方案有效。部署前整理不等于部署授权。

## 三种策略

### ENGINEERING

优先复用已验证组件、成熟依赖和已有入口；避免重复实现、无需求抽象、同用途 Demo/实验框架和无意义代码膨胀。先追根因与受影响调用者，再做可维护的最小改动。性能优化要测耗时/内存，并核对输出等价性；改动数值语义则按 RESEARCH 验证。

不得为缩短代码删除必要测试、输入/边界检查、错误处理、诊断指标和标定参数。测试规模按实际失效风险和现行验收决定，不能机械缩成一个检查。

### RESEARCH

科学实验与可复现原则优先于 Ponytail 的精简建议，研究阶段不强制最小代码原则。允许候选算法独立实现、必要实验冗余、丰富中间结果；必须保留调试指标、特征分布、可视化和消融接口。基础加载/格式契约/评价工具尽量复用，不能为小实验另建同用途平台。

不能仅因实现复杂、代码量大、超出现有 51 维 RF 特征就否定合理方案；不能用 YAGNI 取消已要求的对照实验，或先做简版后要求用户再次提出完整需求。实验规模由科学问题、当前授权及明确资源约束决定，不由行数或“一个最小例子”决定。

读取实际安装的 scientific-toolkit-skill，按需读取相关科学模块。记录输入/源码/配置/模型版本或 SHA、单位/坐标/时间戳、种子、环境、命令、输出路径、假设和限制。冻结同源数据、分组划分、基线、匹配规则与评价分母；训练/调参/测试隔离，时序验证不得看未来。开发中看过的数据不得冒称独立测试；模型比较保留失败/退步和 UNKNOWN，不能只选最优窗口。对照/消融接口和必要中间产物与结论一起保留，禁止为整洁覆盖历史。

### CONSOLIDATION

已有方案通过独立测试后，重新采用 Ponytail 工程原则：合并重复功能、统一数据结构与模型接口、优化时间/内存，只删除经确认无效的代码。复用现有管线，不借整合重写正常模块。

先冻结输入、基线输出、配置、评价协议及数值容差依据，逐帧/源行/轨迹/事件核对行为，并重跑相关边界测试和效果指标。浮点容差必须预先有依据，不能放宽断言掩盖差异。未通过等价性验证不得改变已验证输出或删除对应实验实现；行为改变回到 RESEARCH。保留可重现入口、版本映射、结果和失败记录。等价性通过也不自动授权删除实验证据；历史证据保持只读，数据删除仍须原有清单和用户确认。

## 当前运动一致性研究约定

“利用人体点集时序运动一致性区分运动人体、静态家具和测量抖动”默认 RESEARCH。后续在已授权范围内研究，至少覆盖：

1. 点集质心与局部区域位移。
2. 多帧运动方向一致性。
3. 局部速度场与运动离散度。
4. 时序点集重叠与非刚性形变。
5. 静态家具点云抖动模型，区分扫描采样变化与真实位移。
6. 人体停止运动后的身份保持、冷启动静止与身份撤销边界。
7. 遮挡、稀疏扫描、扫描角度和可见性变化造成的伪运动。

可参考论文/开源实现，记录来源、适用条件及许可证；不受 51 维 RF 结构约束。用相同数据与评价协议比较当前基线和候选，覆盖行走/慢动/停止/遮挡/稀疏、静态家具与移动家具等反例；运动证据本身不等于人体语义。

评价至少报告人体召回率、家具误检率、身份切换、处理延迟及各运动状态表现。说明点/目标/轨迹/事件口径、GT 覆盖和匹配规则；在线因果结果与离线回填分列。没有足够 GT 的指标填 UNKNOWN 并说明缺口；对应验收状态按工单填 BLOCKED/NOT_RUN，不能以 0 或工程 PASS 替代。没有独立测试集不得宣称泛化提升；离线效果未验证不能推进生产部署。

## Skill 调用、优先级与连续执行

写入者仍须先读取实际 Ponytail SKILL.md，记录路径；RESEARCH 表示暂不采用其最小化建议，不表示创建新 Skill 模式。实际 Skill 仅声明 `lite/full/ultra`（默认 full），文本调用 `/ponytail lite|full|ultra`；停止词为 `stop ponytail` / `normal mode`，强度按其说明持续到切换或会话结束。这是 Skill 文本约定，不保证每个客户端都提供斜杠命令 UI。禁止虚构 `/ponytail research`、`--strategy`、自动路由配置或后台开关；无需修改全局 Skill 或增加管理框架。

本项目不把三策略固定映射为三强度；RESEARCH 也不等同于 lite。已加载 Skill 后，每个新任务仍重判项目策略，不能因其“ACTIVE EVERY RESPONSE”跨阶段盲用精简要求。本轮用户明确要求的研究完整性和本规范约束优先于 Skill 的最短代码/优先删除/极少文件/单个检查建议；Skill 自身也明确不可简化用户要求、边界校验及防数据丢失处理。

策略只决定优化原则。保留单生产 writer、HF/GL 与 HC/HR 各自当前入口和唯一验收表、数据/junction 安全、生产链及冻结配置约束；Python 板端兼容要求不变。PC 研究依赖不自动进入板端。已有深度学习封存、ML/HR-09 激活条件、训练/下载/采集/网络/驱动/模型切换/部署和 Git 写边界不因 RESEARCH 自动解除。本次规范优化不授权任何算法实施或恢复封存工作。

普通已授权研究可连续开展，不为策略分类新增确认流程；触及生产链、数据安全或明确授权/验收边界时，按原流程处理。工程检查与科学效果分别报告，不以代码行数、程序能运行或测试总数宣称感知改善。文档合并到现有工单回传并链接证据，禁止复制大量同内容报告；原要求的唯一验收表与逐 ID 状态仍保留。
