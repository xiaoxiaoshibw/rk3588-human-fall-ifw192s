# ADR-004：单业务服务、固定兼容端口与受控worker

日期：2026-10-24。状态：设计采用；A/B实际进程模型待R2。

## 决定与启动

A：C# Host进程拥有Qt事件循环、Application状态、Api监听器、Infrastructure和Gate。App只是QML/ViewModel组件。B：Qt C++ UI进程+C# headless Host进程；API与Gate仍由C#唯一拥有。不能在Qt和C#各自维护一份会话库/录制状态。

启动顺序：解析/校验配置（不创建输入根）→核对实例与写入根→绑定兼容端口→注册应用用例与只读资源→启动Qt/可交互视图→按用户意图执行用例。Qt初始化失败须关闭本进程监听器和worker，保留崩溃信息；API绑定失败不得随机改端口、停止旧进程或自动附着旧8901服务。测试可用随机端口，生产仅允许显式配置改端口。

旧Console可并行安装。默认端口只能有一个所有者，旧进程运行时新实例报告冲突并保持写入口不可用；显式改新实例端口后，旧书签仍指旧服务。旧joint_capture原随机端口与新兼容聚合入口逐页对照，不能仅修改新UI地址后宣布所有旧书签都可用。新联合页单独静态路径，`/`保持旧回放根页。

用户要求的是并行安装与默认端口不变，并未要求两个服务同时绑定8901。该物理占用约束不是额外的人工批准关：R7在8901可用时验证新服务默认行为，另测占用时的明确失败；不自动停旧服务，也不声称两个监听器可共用同一地址端口。

## Python桥与板端

权威fetch.py用于会话拉取，现有GT/配平/离线算法作为按需worker，不重写算法或板端状态机。桥脚本只新增在console_v2，明确Python路径、源文件SHA、参数/工作目录/输出清单，用结构化argv启动，不拼shell、不依赖cwd、不开控制台窗口。生产就绪前必须验证随包Python与NumPy依赖；R1不假称已打包。

worker写能力默认禁用：固定SHA、参数和staging目录都不是强制隔离。Gate的worker执行器在无已验证隔离能力时返回UnsupportedIsolation，不启动有数据/板端修改能力的worker，不能“先运行、发现越界再拒绝”。只读R2不依赖该能力，R6/R8功能因此仍未满足，不能靠设计说明报已通过。

启用前的必要条件是由受限执行身份/OS隔离或宿主完全接管IO，强制做到原始/旧数据根只读、仅本次staging目标可写、旧源码与store不能写、不能绕开已授权动作直接改变板端。若依赖宿主控制面的协议代理，它只接受绑定sid/操作序列/permit的请求，不是公开兼容Api；若依赖OS隔离，必须验证实际身份/文件/网络限制且不自动改驱动或网络设置。实现与能力证明尚未选定和完成，不能仅命名某Windows功能就宣称可用；权威fetch不为绕过隔离而重写。

启用测试必须包含固定SHA程序及依赖尝试越界写、链接逃逸、直接设备修改、权限检查失败、隔离建立失败时无子进程等负例；全部在临时输入/假板端下完成。强制条件无法提供时维持禁用，报告R6/R8功能阻断。隔离成立后下载才允许写应用拥有的staging新目录，最终晋级再由Gate核对SHA/冲突并拒绝覆盖。此为待验证前提，不是现有安全保证。

fetch可能在本地最终晋级前就把板端记为transferred；晋级失败时不能报同步成功、不能自动恢复板端状态。journal保存staging位置与远端已确认状态，后续只读查询并显示Indeterminate，需要显式恢复操作才可改变远端；v1 last_result不能提前置ok。这是R6注入失败测试项，不改fetch现有逻辑来隐藏问题。

新IBoardClient带幂等键；v1 start/stop原来代理空body，不能悄悄改变为另一个协议。v2录制用持久化操作键与状态查询去重；超时状态不明时不盲重发start/stop。下载可恢复任务状态不等于字节Range续传，当前源码未证明Range支持；R6必须验证，不可另造C#下载状态机或擅改板端来满足“续传”字样。

## B内部协议与关闭

仅B启用命名管道控制面：协议版本、消息类型、requestId、generation、长度上限、deadline、错误码；连接限定同一Windows用户并有每次启动随机会话凭据。schema不复用公共v1 JSON。共享内存顶点槽只读映射给UI，槽含generation/frame/count/stride/bytes与校验绑定；引用归还前不复用，UI崩溃后由服务回收已失去连接的租约。缓冲预算与背压不能因跨进程消失。

B中的可信用户确认由已绑定的Qt UI进程回执planId/manifestHash交给Host的ConfirmationBroker，再由Gate内部签token；该通路不复用公共HTTP，不允许外部脚本仅靠sid触发确认。若未验证Qt UI与headless Host的可信确认通路，则B只读，不能因服务本地运行就自动签token。这里限制正常应用边界，不声称抵御同用户对宿主/UI的代码注入。

UI关闭→停止接收新写意图→取消读/预取→完成或明确中断Gate事务→收敛worker/帧租约→停止API→释放Qt。C#服务崩溃时UI显示断开，不创建替代写实例；服务重启核对journal而非自动发设备补偿命令。子进程取消/超时不等于录制已停止。开发本轮不启停任何板端服务。
