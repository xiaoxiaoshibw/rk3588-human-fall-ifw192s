# ConsoleV2 开发与迭代

2026-10-25：用户明确将“控制台方便迭代”作为产品目标。开发时应能定位改动、快速看结果，并在离线固定输入上验证；发布包仍保留单文件要求。路线 B、旧 API 契约和数据安全边界继续有效。[架构](ARCHITECTURE.md)描述产品边界，[SPIKE](SPIKE.md)记录当前实际能力与未验证项。

## 当前就能用的入口

在仓库根运行，也可从任意工作目录用 dev.py 的完整路径运行。使用现有可携 SDK/Qt/GCC、PATH 上的 CMake 和 Python3.12/NumPy，不自动联网安装依赖。

```powershell
python -B -W error console_v2/dev.py build
python -B -W error console_v2/dev.py check
python -B -W error console_v2/dev.py run --count 500000 --duration 10
```

- `build`：增量编译 C# 与 Qt，刷新目录运行包中的 QtSpike.exe 和 Qt/QML 依赖。
- `check`：构建后复用真实三帧的全字段/XYZ差分及反例，再实际启动一次原生离线窗口，确认双方退出、自检与零板端调用。固定输入仍是 cap_20261018_110029，不把它扩张为未来全功能测试。
- `run`：构建后直接运行服务 DLL 和 Qt 目录包。默认真实三帧；`--count 50000|500000` 为有明确标签的合成压力，可用 `--session` 指定另一个满足 R2 格式的只读输入。

三种命令都不执行 publish，不重建 payload.zip、不改 package-single 中已测 exe。每次日志/报告独立保存到 `console_v2/.tools/spike-evidence/dev/<随机ID>/`，最终路径直接打印；失败返回非零并保留阶段日志。开发输出祖先目录含链接时拒绝；C#仍限制输出在明确的应用自有目录并拒绝覆盖。构建参数以 argv 传递，不依赖调用者 cwd。构建目录是可变开发产物，正式发布另用已记录的打包入口及新证据目录。

共享命令工具默认也生成全新的私有目录，不再默认写R2历史evidence；显式指向历史目录会拒绝，三份命令记录均独占创建。源码中的报告策略适用于当前开发DLL；R2已测单文件包保持原SHA，本轮没有重发或据此宣布R2剩余项通过。

QML 开发热重载已落地（2026-10-25，R5 界面开发模式的第一块提前实现）：`app_dev.py run --qml-file console_v2/app/native/Main.qml` 从磁盘加载，保存后约 0.3 秒只重建 QQmlApplicationEngine；Viewer、几何、管道与回放代次不动，坏文件存活、修好保存即恢复。`--smoke-reload` 提供正反例自检（正例退出 0、坏文件反例退出 2）。不带 `--qml-file` 仍走 qrc，发布路径不变。R2 残余验证照常进行，这个入口不代表 R3 数据层已完成。

## 一次改动应落在哪里

保持现有六个逻辑边界，用 feature 文件夹组织 Data/Replay/Capture/Leveling/Annotation；出现实际独立发布需求时才拆新程序集，不先搭通用插件系统。

| 想改的行为 | 产品中的主修改点 | 保留的验证入口 |
|---|---|---|
| 布局、配色、快捷键、空态 | QML 与对应 ViewModel；C++桥只做Qt绑定、事件和渲染 | 固定状态/错误状态预览与UI交互回归 |
| 点格式、会话索引、完整性 | Application端口与Infrastructure/Data；Domain保留纯模型 | 真实会话与合成反例、Python零容差差分 |
| 播放、暂停、seek、缓存 | Application回放用例与Infrastructure缓存 | 无UI的固定时钟、取消与完整回放 |
| 新算法/配平版本 | 独立算法适配器与版本配置；复用现有算法，输出统一展示数据 | 固定会话对照，记录版本/配置/来源SHA |
| 板端或下载 | Application用例与板端适配器 | 假板端断线/超时/状态反例；真实操作另遵守设备约束 |
| 旧HTTP兼容或新接口 | ConsoleV2.Api的DTO/映射；调用同一Application用例 | v1旧实现Golden；新能力只走/api/v2 |

上表是后续实现位置，当前仍只有 spike。页面不读会话文件、不解码点云、不编排算法；Qt和C#不各维护一份业务状态。算法适配不意味着已启用可写Python worker：未验证的写隔离保持禁用，不绕开 IMutationGate。

例如增加一种配平算法：先写适配器并在同一离线输入上保存版本化结果，再让现有报告/展示入口消费；只有出现新的用户操作或展示字段时才改UI。不能把算法执行和参数分支塞进主窗口，不能为新增能力改旧 v1 字段的名称、类型或 null 语义。

## 开发与发布分开验证

日常修改优先跑相关检查与一次离线端到端，记录关键输入和产物 SHA；需要渲染/时序证明时再跑对应固定基准。算法、协议、数据生命周期或渲染路径变化，要增加能暴露该行为差异的反例。编译成功和审核意见不能替代实际运行。

单文件打包、独立干净系统、冷启动及完整性能基准保留独立验证入口，不要求每次改文字/颜色都重发约97MB exe；涉及这些路径的改动则必须重新验证。用户指定的 OpenCode 用于只读代码审核，当前会话仍是唯一写入者，审核不代替测试或成为新增人工关卡。

当前尚未实现的产品能力不通过加接口/占位工程假装完成；R3→R9顺序、R2未验证项和API兼容冲突状态仍以PROJECT_STATE、ADR与实际证据为准。
