## 0. 优先补齐误获取和候选显示问题（2026-10-21，依据用户新截图）

这份计划必须同时解决“起初选错”和“锁住后掉锁”。此前对保持阶段碎片归并的设计不能单独保证消除误获取；以下工作放在归并修复之前，与其分开固定输入对照。

### 0.1 截图的可判定范围

用户截图的黄色 c000* d= 标签与 human_fall.js:830–838 的几何候选绘制一致；实际目标另按 track_id/跌倒状态绘制（:850–870），通常为 t000*。多个候选框不等于多个对象已被锁定。裁剪图没有目标状态栏、同帧 state、版本或时间，不能据此确定实际锁定对象，也不能把任意框内点认作人体/家具 GT。

先用可用的运行记录和已有录制，按同帧 points/candidates/state 核对实际 track_id、candidate/组合成员、获取时刻、各入口门理由、选取来源、标定/背景/profile 绑定。缺少截图对应数据时保留 UNKNOWN；不为核查自行开始原始采集、重冻结或部署。

### 0.2 误获取成为第一优先修复对象

当前初次获取使用几何、高度、近期实测中位中心变化和持续性，仍不是人体分类器。本轮在入口层构造固定 XYZ 的静态表面，仅改变可见 source_rows，竖向和水平两种成员漂移都在 1.6 s 被判 unique_height_and_motion 并获得 t0001。这是合成候选输入的软件反例，不是本截图原因已被复现，也不是完整场景/真人效果证据。

先处理可验证的错误运动证据：

- 分开解释真实空间位移与可见成员更替、点数/可见面变化造成的中心漂移；记录局部支撑位移一致性及其残差，不把同 history 或中位中心变化直接当对象运动。
- 检查冻结背景是否与当前来源、地面、profile 和场景适用；背景残留与设备/全场变化不得直接升级为目标运动。不用有人时段自动学习背景，也不靠重冻结掩盖误获取。
- 对首次获取和重获分别检查未解 split/merge 谱系、非目标历史、时钟和持续性窗口；不全局开启保持阶段严门来替代入口根因修复。
- 固定静物 XYZ、只改变可见成员的水平/竖向反例都须不再锁定；仅把运动投影到地面仍挡不住水平成员漂移，因此不能作为充分修复。
- 同时保留原 591 帧真人进入与固定 386 帧功能对照，防止用“一直不锁任何目标”消除误报；记录首次获取、拒绝、错误切换和漏获取变化。缺真实语义 GT 时不编造总体误锁率。
- 对真实移动且几何相近的非人体，现有几何仍可能不可区分；保留人体语义 UNKNOWN。此项不能通过框稳定或阈值过门宣称解决，不自行训练/下载模型或开启 HR-09。

### 0.3 显示与实际算法分别验证

正常使用突出实际跟踪目标，候选明确标为几何候选并可切换诊断层；手动选择保留候选交互。显示实际目标状态、当前实测/预测及拒绝原因，候选与目标保持同帧关联。

候选数量和拒绝理由继续可查。隐藏候选、改颜色、缩框只能改善理解，不能计为误锁修复；是否修好以核心的实际选取和来源点账本为准。

### 0.4 修订后的顺序

固定误获取与掉锁两组反例 → 统一三入口观测/行域契约 → 修入口假运动/误获取并保护正常进入 → 修保持碎片归并 → 组合后的完整场景、页面和性能回归 → 本地打包。入口与保持分别做消融，不能一次混改后只展示最好结果。

## 3. 拟采用的最小设计

### 3.1 仅在有支撑的保持阶段研究归并

第一版仅处理“上一有效帧已经实测锁定”的目标。首次获取、遮挡后无支撑恢复、长缺口、新身份获取不使用这条捷径；它们沿原有获取/恢复策略处理。

一次候选归并至少检查：

1. 时间、来源帧、session、epoch、地面/标定/坐标绑定有效且与前驱一致，旧支撑没有超期；先处理失效，再分析关系。
2. 原碎片唯一关联到此前实际选中的前驱，排除多前驱、已知非目标及其后代、截断谱系和原先未解决的粘连。不能把本次预期单前驱 split 与此前已污染谱系混在一起。
3. 当前行合法、唯一、处于本帧，来自已经通过输入过滤的候选；第一版不吸收被 min_cluster_points 拒绝的小噪簇、不补预测点。
4. 分别计算每片被前驱解释的支撑比例、前驱被并集覆盖的比例、新增/丢失支撑、片间间隙、并集包络和关联残差。不能只看最近中心或一项 overlap。
5. 如果多个组合都能成立，或仍有独立竞争候选，保留竞争证据；不得任选一个组合、默认吞入全部附近组件。
6. 具体空间/覆盖阈值先由固定正负对照测量确定，再写新命名变体；不凭这份计划猜数值，不修改冻结配置。

必须保留“两个物体从一开始就粘连、随后分开”的负例。仅靠几何历史无法普遍排除它；若拟用边界无法区分，不采用通用归并规则，不将人体/身份 UNKNOWN 改成已验证。缺真值不阻止继续改进可验证的软件契约。

### 3.2 分析、决定、提交一次

共享顺序为：输入与绑定检查 → 在旧状态上分析原组件支撑图 → 判断是否有唯一且合格的目标组合 → 从当前实测行重建组合候选 → 提交一次有效候选历史 → 原有 tracker 关联。

原始支撑图和被拒组合保留诊断。不得先 step 原碎片、再同时间戳 step 组合；不得 deepcopy 回滚状态或手改 history_id 来制造连续性。组合之后的新一帧必须针对组合的真实支撑重新分析。

### 3.3 成员与几何统一

- 组合成员是当前行的去重并集；中心、所有坐标域的框、高度分位数、跨度、PCA、距离均从这些点重算。不能平均碎片中心、拼框后保留旧高度。
- 从 lidar_candidates 现有特征/变换函数提取一个最小公共重建入口；由调用者提供当前已验证几何上下文，获取层不猜 reference/calibration 变换。
- 显式保留 evidence_indices 所属输入数组、source_rows 所属会话帧及 row_offset 的映射；current 的筛选子数组和 foreground 路径都要覆盖。
- 组合候选 ID 只标识本帧观测，确定性生成且不与原簇冲突；跨帧身份继续由历史和 tracker 维护，不能依赖候选排序或 ID 字符串。
- 保留原始簇 snapshot 与手动选择缓存；自动 state/返回 observed 表达组合测量，附 component_candidate_ids 及来源绑定。原始候选数量与组合数量分开解释，不隐式改 snapshot。
- 完整支撑图/逐行账本留在离线证据；板端消息只增加必要的紧凑归并信息，不能把整份点行历史塞进候选发布。

### 3.4 身份、基线和下游

node、ReplayPipeline、current 都消费同一权威实测观测。只有有效且 fresh、locked、非预测的结果能进入基线/特征/区域/跌倒。手动模式继续消费原始选择，不被自动归并隐式改变。

有证据的同一目标碎裂修复不应无故更换 track_id、selection_version 或 action_generation，也不能无故重采基线；真正失锁、换标定/epoch/身份时继续按现有规则失效。躺姿门、confirmed 开关和事件语义在本修复中保持原条件。
