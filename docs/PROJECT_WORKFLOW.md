# 项目工作流

**本文件是唯一有效的工作流。** 其它流程文档（`docs/human_fall/WORKFLOW.md`、`docs/human_capture/README.md` 的历史条目、`RETURN_TEMPLATE.md`、`CODEX_OPENCODE_WORKFLOW.md`、`docs/AI_DEVELOPMENT_POLICY.md`、`REVIEW_LOG.md`、`returns/`、`tickets/`）全部冻结为历史，不再指导新工作。

## 1. 一个项目，连续开发

- 没有工单号、没有验收表、没有回传、没有 SUBMITTED/ACCEPTED、没有“派工/授权/复审”链。
- 用户说做什么就连续做完：读代码 → 改 → 测 → 记录 → 报结果。缺信息先做不依赖它的部分，不来回问。
- 不把人工确认、人工标注、人工复核、独立审查当作前提；它们只能是可选的额外输入。
- 唯一写入者：当前会话的 agent。子代理只做只读分析或独立计算，不写生产代码、不充当“复审关”。

整条人体感知链的持续开发、调试与实验方法见 [DEVELOPMENT_DEBUGGING.md](DEVELOPMENT_DEBUGGING.md)，它服从本工作流，不是第二套管理流程。收到整体开发指令后，agent 自行串起输入盘点、对照、定位、修复、完整回归、集成和记录；不再要求用户逐缺陷派工或在每一步回复“继续”。

## 2. 两个常读文件

- `docs/PROJECT_STATE.md`：当前在做什么、入口在哪、怎么跑、已知阻塞。开工先读，收工更新。
- `docs/PROGRESS.md`：追加式日志，一条几行（日期 / 改了什么 / 跑了什么 / 结果 / 下一步）。不写散文、不复制证据。

## 3. 验证

- 改完必须跑：相关单元测试（`-W error`）+ 一次离线回放或端到端 + 关键 SHA。
- 测试数量不算完成；行为改变必须能逐帧/逐值对照。
- 跑不过、跑不了的写清楚，不粉饰、不写“应该没问题”。
- 没有 ground truth 的效果指标写 UNKNOWN；有数字必须指到证据文件。禁止编造准确率、召回率、告警数。
- 软件契约、已有场景几何行为、人体/物理效果分别下结论；测试通过、拒绝有原因、框变小都不能单独证明产品目标完成。
- 完整回归同时检查目标点集、跟踪、区域/姿态、页面和性能。新的 UNKNOWN 或大范围功能回退必须归因并持续处理，不能通过删统计、隐藏显示或混接不同目标的结果掩盖。
- 固定输入条件做算法对照，另保留旧功能对照。单轮可贯穿多个调用者修同一根因；多因素修改必须能区分影响，不按截图反复全局调阈值。

## 4. 证据

- 新证据放 `docs/evidence/<YYYY-MM-DD>_<topic>/`，只放机器产物：运行 JSON、逐帧账本、截图、测试日志、SHA。
- 不写验收表、不写回传、不写复审报告。结论写进 `PROGRESS.md` 和 `PROJECT_STATE.md`。
- 旧 `docs/*/evidence/`、`returns/`、`tickets/`、`REVIEW_LOG.md` 只读，不再新增条目。

## 5. 安全边界（红线，不是审批门）

以下操作默认不做，只有用户明确要求才做：

- `data/` 与 `captures/remote|leveled|registration` junction：不删、不移、不改名、不 `git add`。删除会话必须 sid/bytes/sha256 清单 + 用户明确同意。
- Git：不 commit / push / reset / checkout / clean。
- 设备：不部署、不采集、不启停板端服务、不改驱动/网络。
- 模型：不训练、不下载权重、不开 `ML/`（HR-09）。

不得把上面任何一条包装成“项目需要”绕过。

## 6. 质量底线（保留）

- 先读实际代码再改；不猜接口、不凭记忆写断言。
- 一个根因修一处，查完所有调用者；同类入口一次改完。
- 保留可复现入口、输入 SHA、失败记录；历史证据不覆盖、不回填。
- 板端代码保持 Python 3.8 + stdlib + NumPy；PC 依赖不自动进板端。
- 语义诚实：几何/软件通过不等于人体/物理有效；区域不是关节，候选不是人体。
- 实验运行先写新证据，不自动改默认。由 agent 在完整比较、集成检查和功能回退分析后自行采用合适的开发结果；这是工程判断，不是新增人工审批或复审关。
