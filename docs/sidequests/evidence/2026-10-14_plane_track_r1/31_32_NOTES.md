## B) 准实时演示 `rt_server.py` + `rt.html` → `32_RT_REPLAY.json`

- 整条管线（**检测前端 + 分簇 + 自由空间门 + KF/M-N + TBD 计分 + 发布**）按源帧真实 ≈10 Hz 喂帧。
- 启动时另跑一次批量 TBD（27 帧全量，1.5 s），结果与在线段一致：**TBD 可宣告发现帧 = 10**。
- 实测（本机，纯 Python+NumPy）：

| 指标 | 值 |
|---|---|
| compute（前端+在线，中位/p95/max） | **81.6 / 116.2 / 125.7 ms** |
| 发布延迟（中位/p95/max） | 81.9 / 134.3 / 135.9 ms |
| 晚启动（掉帧） | **6/27**（22%，p95 超 100 ms 预算的帧） |
| 客户端见帧 | 25/27（2 次 10 Hz 采样跳格） |
| 有目标帧（运动型确认轨） | 15 帧（ID4 帧 9–15 + ID3 帧 9–18） |

- **性能根因与修复（值得留档）**：原先"每帧 5.5 s"的直接原因是
  ① 空场占用格键**没去重**（238 万个重复键，查表全落缓存外）→ 去重后只剩 **14,415 个唯一格**；
  ② 每个候选簇对 **238 万空场点**求最近距离 → 换成 0.5 m 格 + `searchsorted` 的 `EmptyIndex`（0.7 ms/查询）；
  ③ 27 邻域查表对已命中的点重复计算 → 改成"命中即移出待查集合"。
  三项合计把前端从 **5.5 s/帧 → 54 ms/帧（100×）**，语义不变（候选数、TBD 声明帧完全一致）。
