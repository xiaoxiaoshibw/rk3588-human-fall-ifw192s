LiDAR 点云 → 跟踪开始 从 ROS /innolidar_points 输出开始，到 TargetTracker.select / update 为止的完整链路

ROS 点云→解码→时间基→前置六级门→ 聚类→候选→snapshot→获取器→跟踪开始
数据入口 / 输出 门禁 / 可能丢弃 故障 / 拒绝 数据结构 跟踪开始
01

ROS 点云输出 入口 publish_manager.cpp:102, 270

  • /innolidar_points → sensor_msgs/PointCloud2，height=1, width=N，is_dense 透传。
  • 字段编译期固定（POINT_TYPE XYZI_TIME）：x,y,z FLOAT32、intensity FLOAT32、ring UINT16、timestamp FLOAT64。
  • header.stamp 来自设备时间（按秒消费、非法归零、纳秒进位）；header.seq 抄设备 seq；frame_id=innolidar。
  • 同一次发布还发 /device_status；IMU 走独立线程与队列发 /inno_imu。
形状：N × point_step 字节
02

订阅与入队 回调零计算 human_fall_node.py:430, 550

  • queue_size=1（ROS 层只留最新一帧），buff_size=2^24（16 MiB）。
  • 回调里只做 queue.put((monotonic, msg, perf))：不解码、不算几何、不发布。
  • 旁路 on_imu / on_device 只做时间基与质量记账，不参与几何门禁。
形状：消息引用 + 接收时刻
03

最新帧队列 丢旧不排队 node_runtime.py:230-281

  • deque(maxlen=1)：计算慢时旧帧被覆盖，dropped += 1。
  • 被覆盖帧的 seq / stamp / frame_id / receive_s 记入 overwritten（≤128 条，溢出单独计数）。
  • take() 从右端取，永远是最新帧；队列长度不会增长。
形状：(receive_s, PointCloud2) × 1
04

陈旧门 0.6 s human_fall_node.py:578-585, 622-650

  • now − receive_s > cloud_stale_s (0.6 s) → 丢弃，只发状态，不产生候选/事件。
  • 计算结束后再查一次：慢计算不能把旧帧当新结果；此时候选、事件、位置全部抑制。
  • 原则：宁可丢帧，也不让延迟沿链路累积。
形状：丢弃 / 继续
05

解码为 (N,3) 行号保留 calibrate_human_follow.py:26 · human_fall_node.py:588

  • 零拷贝 np.dtype 视图 + strides=(row_step, point_step)，支持 organized 布局与行填充。
  • preserve_rows=True：非有限点置 NaN 但保留行，返回 (height·width, 3)。
  • 校验维度、步长、字段类型、offset 越界；失败 → points=None，核心仍产出无效帧诊断。
  • 这里传 min_range_m=0：距离门（0.8 m）在 snapshot 里统一做。
形状：(H·W, 3) float64，含 NaN 洞
06

时间基 epoch / freshness timebase.py:160-196, 230-246, 294-320

  • 每帧时间戳分类：first / ok / repeated / regressed / forward_jump / invalid。
  • repeated / regressed / forward_jump(>30 s) → time_epoch += 1，清空其它流时间历史。
  • invalid 不重建 epoch，保留上一个合法比较基线；source_stamp_s = None。
  • freshness 只看当前帧接收时间：本帧 receive 非法就是 stale，不借上一帧装新鲜。
  • 后续所有历史都绑定 (session, epoch, calibration, frame, ground_sha)。
形状：stamp_status + time_epoch + source_stamp_s
07

有效帧判定 frame_valid node_runtime.py:755-780

  • frame_valid = points is not None and stamp_status != "invalid"。
  • 有解码结果但时间戳非法：仍调用 build_snapshot（诊断/页面可见），但不登记快照、候选不进跟踪历史。
  • 解码失败（points=None）：没有 snapshot，只累加 invalid_frames。
  • 有效帧 → selection.register_snapshot(snapshot, receive)，供人工选择绑定 snapshot_id + epoch + calibration。
形状：snapshot 或 None
08

前置过滤：六级门 build_snapshot lidar_candidates.py:834-900

  1. 有限性：isfinite，同时记录 original_indices。
  2. 上限抽样：max_points=60000，等步长 stride，行号一起抽。
  3. 距离门：传感器原点欧氏距离 [0.8, 8.0] m。
  4. 去噪：0.1 m / 2（自身 + 26 邻域计数），刻意放在地面门之前。
  5. 地面源帧校验 + 高度门：[−0.3, 2.5] m（默认）/ [0.08, 2.5] m（现场）；源帧不匹配则不借用地平面。
  6. 冻结背景减除：0.1 m 体素占据表，只读，不在线学习。
无有效地面时：跳过高度门，坐标标记 raw_xy_uncalibrated，高度字段全部 null——绝不假设 z=0 是地面。
形状：(M, 3) + original_indices (M,)
09

★ 聚类入口 栅格连通 lidar_candidates.py:897-900

horizontal 默认 0.25 m

  • 投到地面切平面 (u,v)，无地面用原始 XY。
  • floor(/0.25) 落格，8 邻域 DFS。
  • 竖直叠着的头/肩/腿自然合成一簇。

spatial_3d 现场 0.05 m

  • floor(/0.05) 三维落格，26 邻域连通。
  • ≥1024 点走 2×2×2 块 + 8 位掩码优化，结果与逐格等价。
  • 能把紧贴的人/家具在高度上分开。
是“格元连通”，不是“距离球”：实际可连通距离取决于落格相位（水平最坏约 0.7 m，3D 最坏约 0.17 m）。参数含义是格子边长，不是聚类半径。
形状：list[ndarray[int64]]（过滤后数组下标）
10

单簇 → 候选 semantic = unknown lidar_candidates.py:918-935

  • < min_cluster_points (25 / 现场 30) → rejected_clusters，保留 evidence_indices，不算特征。
  • 特征：中位中心、AABB、距离、高度分位、水平稳健跨度、PCA 轴（含退化标记）。
  • 排序后编号 c0000...：本帧局部，跨帧同名不代表同一目标。
  • 中心用中位数（抗离群），不用均值。
形状：candidates[] + rejected_clusters[]
11

一帧 → 自描述 snapshot 可对账 lidar_candidates.py:916-1002

  • 顶层：session / time_epoch / snapshot_id / source / coordinate / calibration / ground / settings / quality。
  • snapshot_id = seq:<n> 或 recv:<t>；source 保留 seq、秒、纳秒、source_stamp_s、frame。
  • foreground_indices 与每个候选的 evidence_indices 都是源行号，但数组域不同。
  • 发布前 project_snapshot_for_ros 剥掉这三个大数组，算法缓存不被修改（node_runtime.py:138）。
形状：dict（含候选 + 行号账本 + 坐标/标定身份）
12

节点门禁 地面上下文 + 新鲜度 node_runtime.py:782-821, 939-963

  • 地面监控：degraded / recalibration_required / unknown，或源帧与地平面不匹配 → candidates = []。
  • valid = frame_valid and not ground_context_unavailable and freshness(now)=="fresh"。
  • 自动模式 valid=False → 获取器按 input_unavailable 重置并释放目标。
manual 分支：跳过 13–16，空候选直接喂 tracker.update，目标自然老化到 occluded。本图主线是自动模式。
形状：candidates[]（可能被清空）+ valid: bool
13

获取器：绑定与故障门 reset target_acquisition.py:192-215

  • binding = (session, epoch, calibration_id, frame_id, ground_sha256)。
  • 故障：input_unavailable / invalid_time / binding_changed / nonincreasing_time。
  • 任一故障 → reset()：清 pending、入口窗口、非目标记忆、恢复状态，并 tracker.release()。
  • gap = stamp − last_time，供后续持久性窗口判断连续性。
形状：fault → 提前返回；否则继续
14

因果历史 CandidateHistory 只留上一帧 candidate_history.py:82-109, 111-159, 161-254

  • 用真实点重算中心（median），支撑体素 0.1 m；元数据自己漂不能伪造运动。
  • 关联：支撑重叠 ≥10%；重叠不足且中心距 ≤0.1 m 时允许邻格容差；无支撑退回 0.5 m 中心门。
  • 唯一继承：1 前驱 + 1 后继 + 中心位移 ≤0.5 m → 沿用 history_id；否则新建 h...。
  • 多前驱/多后继 → support_conflict，不猜；谱系 ≤64，超出只标 lineage_truncated。
  • 断流 > max_gap_s (0.3) → 重置；成员增删对所有前驱并集比较。
形状：history ledger（history_id / source_rows / 支撑体素 / 谱系）
15

质量门 原因码 target_acquisition.py:94-117, 230-235

  • invalid_position / ground_unavailable / invalid_geometry
  • insufficient_support（<30 点）
  • extent_out_of_range（水平跨度不在 [0.1, 2.5] m）
  • height_out_of_range（顶部 >2.7 或底部 <−0.3 m）
  • insufficient_height_span（p90 − p10 < 0.15 m）
  • 历史测量失败 → invalid_source_support
每个候选都会得到 rejected[candidate_id] = reason；后续状态里能逐帧回答“为什么没选它”。
形状：rejected 映射
16

两条分支：持有 vs 获取 不猜 target_acquisition.py:238-347 / 119-190, 348-423

已经在跟 locked / occluded

  • 跳过入口身高/运动门，用关联保持。
  • 拒绝：已知非目标历史、0.5 m / 3 s 空间记忆、点数 >3× 且跨度 >2× 的合并。
  • 恢复：0.5–3.0 s 缺口、残差 ≤gate、连续 3 帧/0.2 s → 新身份 select。
  • 否则 tracker.update ★

还没锁 searching / acquiring

  • 高度 p90 ∈ [0.8, 2.2] m；必须有历史且谱系未截断。
  • 运动窗 1.2 s / ≥5 帧；端点中位位移 ≥0.3 m。
  • 可见性反证：原样残差 ≤0.1 m 或平移后不改善 → 拒。
  • 唯一候选；多个 → ambiguous，不按距离挑。
  • 持久 0.6 s / 5 帧 → tracker.select ★
可见性反证专门对付“固定物体只改可见成员”：中位中心动了，不等于物体真的动了。
形状：state = {status, reason, rejected, entry_gate, candidate_history}

★ 跟踪开始 TargetTracker tracking.py:162, 236-288

  • 首次：select('t0001', selection_source='automatic_acquisition')。
  • 恢复：select(..., 'verified_geometry_new_identity')，旧基线不继承。
  • 之后每帧：update(candidates, ...)。
  • 关联门 0.8 + 2.5·dt；近等距 <0.2 m → ambiguous；>3.0 s → lost；时钟回退 → lost。
  • dt 来自锁定那一刻固定的时钟域，中途不切换。
从这里往下：基线采集 → 特征 → 跌倒状态机（不在本图范围）。只有 locked && !position_predicted 的候选才算“实测”。
形状：track_state = {track_id, track_status, position_m, position_predicted, ...}
PointCloud2 字节→ (H·W,3) 含 NaN→ (M,3) + 行号→ clusters→ candidates→ snapshot→ history + quality→ track_state
读数口径：本图是自动模式（target_mode=automatic）主线；manual 模式在 12 之后直接进 tracker.update。 参数来自 perception.yaml 的 candidates / acquisition / tracking 段，现场变体为 perception_single_target_v1/v2.yaml。 所有 candidate_id / history_id / track_id 都带 semantic=unknown：几何连续不等于人体身份。
