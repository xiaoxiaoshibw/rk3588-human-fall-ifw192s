## 0. 结论摘要（先读）

1. **C4AH（ROI + scipy 连通）= 推荐的 C4 实现**：P95 从 **88.7ms → 13.2ms
   （6.7×）**，7 个有效会话对象级召回全部保持 **1.000**，精度指标与 C4A 相同。
2. **C4 的"100% 召回"在生产口径下基本不可用**（本轮最重要的负面发现）：
   GT 命中簇中 **92% 是 ≥2000 点的房间级大团**，而 ledger 实测这类候选
   生产接受率 **0/258 = 0%** → 纸面召回。
3. 纯提速项 **C4H（scipy.csgraph 替代 Python 并查集）** 经逐帧集合级证明
   与基线**完全等价**（15/15 帧 IDENTICAL），2.4× 加速零代价。
4. 拆大簇（C4G 系）能提高纯度但**代价是召回与候选数爆炸**；C4G2
   (r_split=0.25) 是分水岭：召回保 1.000、纯度 0.066→0.372、候选 ×3.8。

## 5. 生产可用性检验（W3C，最重要的负面结论）

C4 的召回在"生产可打分区"里剩多少？逐 GT 对象取最佳簇，按簇点数分桶：

| 变体 | GT 对象 | cov≥0.5 | rescue_ready(60–1999) | big_blob(≥2000) |
|---|---:|---:|---:|---:|
| C4_FROZEN | 510 | 510 | **41 (8%)** | **469 (92%)** |
| C4A_ROI | 510 | 510 | 25 (5%) | 485 (95%) |

对照生产事实（W1）：`n≥2000` 候选 258 个，RF 接受率 **0%**（prob≈0.0029）。
**即：C4 那 100% 的对象级召回中，92% 命中的是生产必拒的房间级大团。**
C4A_ROI 因切掉地板反而把更多 GT 推进更大的墙团里（rescue 8%→5%）。

**这不否定 C4 的方向（RAW 里信号确实完整），但量化了"从 C4 到可用候选"
之间缺失的一道工序**：A→B 拆簇（并保持拆后碎片 ≥60 点可进生产门）。

## 6. 逐变体判语

- **C4H_SCIPY_UF**：✅ 采纳。`tools` 内已用 `uf="scipy"` 开关实现；
  等价性：S3-near 15 帧 frozenset 级逐帧比对 15/15 IDENTICAL。
- **C4A_ROI**：✅ 提速 + 纯度双赢（P95 88.7→35.2ms，纯度 0.116→0.151）。
  但降低 rescue_ready（8%→5%）——ROI 究竟净正还是净负取决于下游 A→B 方案，
  本轮**并入 C4AH** 但登记该副作用。
- **C4AH**：✅✅ 本轮推荐实现。ROI 削减输入点数 + scipy 连通消除 Python
  热点，收益正交叠加：P95 **13.2ms**（6.7×），召回 1.000 保持。
  **板端预算参考**：RK3588 约台机 CPU 3-5× → 估 40-66ms，10Hz 预算内。
- **C4E_SLIDE**：⚠️ P50 8.8ms 最省，但纯度降至 0.096（静区复用把上帧
  大团的 bbox 固化，反而更容易吞入新来人点）。跨帧复用的收益被复杂度
  与精度损失抵消——**不推**，除非未来做真正的静态层分离。
- **C4F_KDCELL**：❌ 体素下采样丢结构，P95 反升到 231ms（numpy 分组
  开销超过收益）——"高效 3D 邻域"此路不通。
- **C4B_XY2D**：❌ 双重聚类开销，P95 120ms，无召回增益。
- **C4D_ADAPT / C4G / C4G2**：作为**权衡面**保留证据（纯度最高 0.625，
  代价召回 0.615 与候选 ×10）——它们是"若要拆大团要付多少"的量化边界。
