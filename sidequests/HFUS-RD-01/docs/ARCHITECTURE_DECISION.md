## 2. 唯一首选路线（PRIMARY）

### 架构

```
RAW 点云
   │
   ├──(配额)─────────────────────────────┐
   │                                     │
   ├──→ BG envelope (现有 ref_only) ──→ BG 输出（即 FG 点）
   │                                     │
   │   ┌────────────────────┐            │
   └─→ │ C4 提案层（valid ∪ FG 宽松 3D 欧氏 r=0.35 min=15） │ ←─┘
       └────────────────────┘
                │
                ↓ 候选点簇（含 raw 索引）
        ┌────────────────────┐
        │ M1_RF69 + sigmoid 校准 │ ← 树模型 + 扩维 + 校准后概率
        │  (备选: M2_XGB69)    │
        └────────────────────┘
                ↓ 软概率（不做硬 AND）
        ┌────────────────────┐
        │ Track 票窗（保持现有 3票窗 + lost=30）│
        └────────────────────┘
                ↓
            DISPLAY / ACK
```

### 理由

1. **C4 提案层**是唯一能恢复 BG 截断人 的提案；它**不否定** BG（BG
   仍用于加速/关联提示/hot-cell bank），而是**把提案的责任从 BG
   手中接回**。
2. **M1_RF69 + sigmoid 校准**解决**负类整洁率**：把 RF 过自信的
   p50=0.87 校准到有意义的概率，配合阈值在生产侧选择 FP/h 低量
   级。**XGBoost 作备选**（同数据平打，CPU 秒级优势）。
3. **不选 M3/M4 PointNet**：train 上与 M2 持平，工程成本高 10-100×，
   板端移植需 torch 或重写 NumPy（已知工作量）。
4. **不推 PointNet++/RandLA-Net 在当前数据规模下做主分类器**：
   见 CLASSIFIER_ABLATION §7。
5. **不重建 BG**：C5_CONS_BG 证明"更保守 BG"方向反向（GT 覆盖从
   0.813 → 0.532），即 UNKNOWN 支撑点实质是人体的合法点。

### 收益证据（会话级）

- 提案层从 84% 对象级覆盖 → 100%（reviewed 会话）。
- 跟踪层 confirm 延迟将由"帧缺失 driven" 大幅改善（S5 52 帧延
  迟的直接原因是 66% 帧无提案，C4 修复后 fuse 3 票窗从第 ~3 帧
  就能确认）。
- 分类器 P@0.5 从 0.402（M0）→ 预期 0.9+（M1/M2 + 校准，需 reviewed 负 例验）。

### 风险/已知上限

- **C4 计算成本**：Win CPU 130ms/帧 → 板端超 10Hz 预算，需优化
  （cell 化 r 降到 0.30 得 2-3× 加速；滑动窗 + 分块并行 得 3-5×）。
  **DEPLOY-BLOCKED**，板端实测 NOT_RUN。
- **C4 混簇上限**：家具近人位可能并簇（估 5-8%），需要跟踪层关联
  时再拆；本轮无"两人同簇"事例（S9 未判定）。
- **训练集偏差**：S1 家具会话对 M1 有 train 优势；泛化需 reviewed 负 例集
  重评（见 §4 最小标注清单）。
- **空场误报**：无"空旷房间（纯地板/墙）"会话 → `空场误报/小时`
  只有候选级上界（S1 家具 43k/h），事件级指标 BLOCKED。

## 3. 低风险备选方案（SAFETY）

如果 M1+sigmoid 校准 因 GT/部署原因推迟，可采用：
- **保留 M0_RF51，把硬 AND (n≥60 & prob≥0.55) 改为 prob 校准后软决
  策**：用 Platt sigmoid 在 S1 + reviewed 正 例子集校准 → 用同一个
  rf_person_v1.json （不改权重），仅改阈值映射。
  - 工作量：0 改代码，1 个外部校准 JSON + 运行时 apply。
  - 局限：不解决 BG 截断（续以 C4 才解决）；负例改善估计有限
    （M0 train AUPRC=0.986 vs M1 1.000，差 0.014 主要来自特征，
    部分来自校准）。

## 4. 不推荐方案（明了拒绝）

- ❌ 以 PointNet++ 替换 RF 作为主分类器（数据量不足；train 与 M2 持平）
- ❌ RandLA-Net 在当前 GT 下**直接实施**（D4 DATA_BLOCKED：reviewed 非人点=0）
- ❌ Cylinder3D / SPVCNN / PVKD（CUDA-only，CPU-only 不成立）
- ❌ 移植 S3DIS 预训练权重直推（无 person 类 + 三重域差）
- ❌ "更保守 BG"（C5 证明反向）
- ❌ 任何用 V1/V2/V3 软化身份硬门（表 D1_FUSION_ABLATION 显示 FP 暴
  涨而 r 不变）—— 这不是硬门问题。
