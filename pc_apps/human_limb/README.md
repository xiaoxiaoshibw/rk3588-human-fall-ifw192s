## 结论：v1 失败，不是调参问题，是场景根本限制

17 秒真实会话 (`cap_20261002_223757`) 实施， **6 代算法**全部失败：
1. v1 纯密度峰 + 躯干 PCA → 锁沙发
2. v2 强制平地 + z-spread 限制 → 锁衣柜
3. v3 三段带 (low/mid/high) 人形评分 → 柜的特征跟直立人完全一致
4. v4 用户 pin (1.0, 0.7) → 那位置是沙发不是人
5. v5 跨 4s 背景差分 → 静立 7 秒的人被滤掉
6. v6 hint-only pin → 家具间振荡， 伪弯腰事件 ≈ 21 个

**核心发现**:
- 场景里**至少有 2-3 个等高等密度的柱/面**（沙发、高柜、挂物）
- 真的人与静止高柜在 v1 维度 (z-range、xy-density、三带分布、PCA 形状） **完全同形**
- 想区分必须引入**额外维度**—— temporal velocity、外表颜色、或者外部标签
- 尝试了 temporal density 和 user pin 都不够， 前者 (=v5) 会滤掉静止者， 后者 (=v4) 取决于**用户停下来给一个 hint**——但 HR-06..07 的初衷是「实时识别， 不要人工干预」

## 教训： 哪些不要重复犯

| 反模式 | 症状 | 修法失败 |
|---|---|---|
| 「让密度最高的柱就是人」 | 锁到沙发/柜 | 三段带分布也救不了——柜恰好三段都有点 |
| 「加用户 pin 解决」 | 用户也指不准 | 顶视图 click 落到 z=0 平面， 拿到的是脚下 xy, 但那人另一帧站在别处 |
| 「动 → 人， 静 → 家具」 | 站着不动的人被滤 | 0.3 m 网格 + 4 s ref 差不够敏感 |
| 「跟踪锁解决一切」 | 锁死后永远出不去 | 跟踪只能信任第一个决策， 第一个错了跟踪就跟着错 |

## 下一步（如重启此支线， 先做这些再开干）
