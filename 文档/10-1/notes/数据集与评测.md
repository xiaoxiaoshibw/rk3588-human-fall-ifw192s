# 数据集与评测口径

## 可用公开数据集（与本项目相关度排序）

### 1. MM-Fi（多模态，含 LiDAR 点云）
- 论文：*MM-Fi: Multi-Modal Non-Intrusive 4D Human Dataset for Versatile Wireless Sensing*（NeurIPS 2023 D&B）
- 主页：https://ntu-aiot-lab.github.io/mm-fi
- 40 受试者 × 27 类日常 + 13 类康复动作；LiDAR 点云 + 毫米波 + WiFi CSI + RGB-D。
- 与本项目关系：**真正的 3D LiDAR 点云 HAR 数据集之一**（2509.23255 就用它）。但 **不含"跌倒"类别**，只可作"人体姿态在点云上的可分性"验证。
- 规模与许可需自查（使用前核对下载页条款）。

### 2. MiliPoint（毫米波，稀疏点云）
- 用于 2508.10469 的评测；毫米波雷达采集，约 50 类动作，点数远少于光学 LiDAR。
- 与本项目关系：稀疏点云的处理思路可参考，坐标尺度不可直接迁移。

### 3. UP-Fall Detection（多模态，含 RGB-D/深度点云）
- 论文：Martínez-Villaseñor et al., *UP-Fall Detection Dataset: A Multimodal Approach* (Sensors 2019)
- 11 类活动含 5 类跌倒；多视角 RGB + 2×Kinect 深度 + 可穿戴 IMU + 环境传感器。
- 与本项目关系：跌倒类**标注口径**（跌倒起始/触地/静止三段）值得我们对齐；点云是 Kinect 而非 LiDAR，不能直接训练迁移。

### 4. zahyravaldez/fusion-fall-detection-dataset（GitHub，2026）
- 已 clone：见 `../github/` 未放，但条目见 manifest。
- Hesai 3D LiDAR + 双 IMU + RGB 的**自建采集工具链**（不是大公开库，仅含一个示例跌倒），最大价值是其**采集/同步/标注/toolkit**——和我们 `evaluate_sessions.py` + JSONL 日志的工程思路可直接对照。

### 5. 本项目自采
- `captures/` 已有 PCAP（点云回归用，**不是**跌倒标注集）。
- 按 `docs/human_fall/README.md` §6：≥20 段有保护模拟跌倒 + ≥100 困难负例 + ≥2h 常规活动；按人×场次划分防泄漏；事件级标签人工核对。

## 评测指标口径（跨文献对齐）

| 指标 | 定义 | 我们现有输出对应 |
|---|---|---|
| 事件级召回率 | 检出跌倒事件数 / 实际跌倒事件数 | `evaluate_sessions.py` 事件统计 |
| 事件级精确率 | 检出中真跌倒占比 | 同上 |
| 误报率 | false alarms / hour | 按运行时长统计 |
| 漏报类型 | 分 slow-fall / 遮挡 / 半遮挡 等 | 人工标签打 type |
| 报警延迟 | 从"跌倒开始"到 confirmed 的时间 | 事件 JSON 里开始时间戳 |
| 有效观测时长 | 系统维持 lock 的时间占比 | follow/state 在线率 |

**逐帧 vs 逐事件**：文献里 metric 多为逐事件（event-level），帧级 F1 会高估（连帧正例）。`evaluate_sessions.py` 已是事件级 —— 保持。

**延迟计时**：单机单调时钟，`timebase.py` 已统一；不要用浏览器 wall-clock。

## Livox 项目给出的"已验证量级"

抄自 `github/Lidar-Based-Fall-Detection/F.Training Results/DGCNN_GRU_N0369_T020_S002/reports/metrics_summary.json`（跨 9 折）：
- fall 事件级 **precision 0.969 / recall 0.917 / F1 0.942** / balanced_acc 0.953 —— 该工作达到了"学术可发表"水平。
- **但**用了 DGCNN-GRU（深度学习 + GPU 训练 + Bootstrap 重采样），和我们"规则+RK3588 无 NPU"的路线不同。
- 对我们的意义：证明"DBSCAN 提人 + 时序建模"在 LiDAR 上**可行**；指标数值是我们的远期对标，不是当前门槛。
