# 方法对照：我们 core/ 模块 vs 文献/开源算法

> 用途：后来调算法时，按模块查这里，看"现在怎么做 → 别人怎么做 → 可换成什么"。
> core/ 模块命名对应 `src/human_fall_detection/core/*.py`。

## 总览表

| core/ 模块 | 当前做法 | 可借鉴来源 | 升级候选 |
|---|---|---|---|
| `lidar_candidates.py` | 几何包围盒、高度/宽深限制、候选输出 | Haselich 分块聚类 (hdl)、DBSCAN (Livox/ours) | Kidono 29 特征 + SVM 过滤 |
| `ground.py` | 地面高度估计 | TRAVEL (RA-L)、Patchwork、RANSAC 平面 | Patchwork++（同心环带） |
| `features.py` | 高度分位数、主轴、水平范围 | Kidono 特征集、拉普拉斯谱描述子 | 谱特征 + 滑窗统计 |
| `association.py` | 时间+位置+距离门限 GNN | Munkres/Hungarian GNN (hdl)、IMM | 标准 JPDA / GNN+卡尔曼门控 |
| `tracking.py` | 简单跟踪 + 丢失计帧 | 恒速 KF (hdl/kkl) | CV-模型 KF、IMM |
| `fall_state.py` | 时序状态机：下降过程 + 低姿态持续 | IMM mmWave (2311.08755)、mmFall 时序异常 | 保留状态机，用 KF 速度喂证据 |
| `baseline.py` | 站姿基线 JSON | —— | 不变，属于工程契约 |
| `calibration.py` | 外参/单位核验 | —— | 不变 |

## 按阶段细节

### 1. 候选提取（lidar_candidates）

**我们**：地面以上一定高度带内、宽/深限制内的连通区域。

**Haselich 2014（hdl_people_tracking 用）**：
- 把点云在 XY 平面分成 **网格块（cells）**，对每块内高度差聚类成"peaks"，再把相邻块相互兼容的峰值合并成 candidate。
- 优点：不用全图 DBSCAN，近似线性复杂度；天然输出包围盒。
- 源码：`github/hdl_people_tracking/include/hdl_people_detection/cluster_detector.hpp`。

**DBSCAN 实机调参（Livox Mid-360 项目）**：
- 在 3 m 量级室内场景、点径校正后，实测网格搜索最优 `eps=0.2, min_samples=10`，主簇平均 433 点、高度范围 0.98 m。
- 其"地面校正 + Z_level 归一 + 再 DBSCAN"顺序与我们一致，可作 sanity check。
- 配置已抄在 `github/Lidar-Based-Fall-Detection/D.Preprocessing/DBSCAN_Calibration_GC25_Z080/_metrics/best_dbscan_config.json`。

**升级路线**：先用我们现有候选 + Kidono 特征做 SVM 过滤误检（家具、门）；不达标再考虑换 Haselich 分块法。

### 2. 地面（ground）

**我们**：室内平整假设 + 局部高度估计。

**文献可选**：
- **Patchwork / Patchwork++**（RAL 2022）：同心环带区域地面拟合，对不平整和部分遮挡鲁棒。源码 https://github.com/url-kaist/Patchwork （我们没 clone，太大了）。
- **TRAVEL**（RAL 2024）：图表示的可通行/非地面分割，344★。若后续要在更杂乱室内区分"可躺的地面"与"家具"，可参考。
- **RANSAC 平面**（`ground_removal` 类小仓）足够室内平整场景，别过早换方法。

### 3. 特征（features）

**Kidono 2011 - 29 维行人特征**（hdl 实现见 `kidono_feature_extractor.hpp`）：
1. 点数
2. 最近距离
3. 3D 协方差 6 元素
4. 3D 惯性矩张量 6 元素
5. 3 个主成分把簇切 3 区，每区 2D 直方图（14×7 与 9×5）
6. 主成分方向切片特征（10 片）
7. 强度分布 25 bin

这套特征对"直立人 vs 倒地人 vs 家具"有判别力，且**全套用 NumPy 可实现**（协方差、eigh、直方图），是 features.py 最直接的扩充。

**拉普拉斯谱（2509.23255）**：
- ε-邻近图 → 拉普拉斯 → 特征值前 k 个 + 特征向量统计 → 滑窗均值方差。
- 对"姿态直立 vs 水平"本质上比协方差更敏感（图结构差异大）；单簇几百点 eigh 在 RK3588 可跑。
- **学习可选**：不强制分类器，可只取前几个特征值作为规则证据之一。

### 4. 关联（association）

**我们**：时间 + 三维位置/距离门限。

**hdl 做法**：恒速 KF 预测 → 马氏距离门控 → Munkres（匈牙利）全局最近邻 GNN。源码 `github/hdl_people_tracking/include/kkl/alg/{munkres.hpp, global_nearest_neighbor_association.hpp, kalman_filter.hpp}` —— **这是标准教科书实现，可直接对照我们的关联门限**。

**ablation 证据（2508.10469）**：在毫米波 HAR 上，关联（匈牙利）比 DBSCAN/KF 单独带来的提升更大；提示我们调参优先级 **先调 association，再调 clustering**。

**禁止自动换人**：我们的契约（ambiguous/lost 就停）与文献中追求"尽可能维持 track"的目标相反，**不要照抄** hdl 的"匹配不上也保留旧 track N 帧"策略，我们的契约更严。

### 5. 跟踪（tracking）

恒速 KF 足以：人体在 10 Hz 点云上位移 ~0.1-0.2 m/帧，CV 模型线性化良好。`kkl::alg::KalmanFilter` 是模板化 Eigen 实现，我们 Python 端 `tracking.py` 用 NumPy 写等价 3 维位置 + 3 维速度即可。状态向量建议 `[x,y,z,vx,vy,vz]`，观测 `[x,y,z]`（簇质心）。

### 6. 跌倒状态机（fall_state）

**我们**：站立跟踪 → 检测到快速下降（质心 z 速度 + 高度跌落幅度）→ 低姿态持续 N 帧 → confirmed。

**IMM mmWave 论文（2311.08755）验证这一分解**：
- 三模型：standing / falling(down) / fallen，用 IMM 在它们之间软切换。
- 关键结论：**分离"下降过程"与"倒地持续"两个证据窗口显著降低误报**（对蹲下/坐下的抑制）。
- 我们规则实现本质上是 IMM 的硬门限退化版 —— 可保留状态机，**把 KF 输出的垂直速度作为证据**喂给现有门限，而不是直接换 IMM 框架。

**mmFall 的异常检测（2003.02386）**：
- 变分 RNN-AE 只在正常动作上训练，跌倒 = 高重构误差。
- **意义**：如果我们后续收集不到足够跌倒样本（困难正例保护下难以多跌倒），可只在"站姿基线 + 正常走动"数据上训练这种单类模型。
- 需要 NumPy 实现 LSTM-VAE —— 工作量远超首版；仅作为远期候选。

## 调参优先级建议（按 ablation 与架构依赖推）

1. **ground 与背景扣除稳定性**（误检源头）
2. **association 门限**（多人和丢失的关键，文献证明收益最大）
3. **特征扩充到 Kidono 29 维**（投入产出比最高，仍是 NumPy）
4. **KF 替换当前简化跟踪**（为 fall_state 提供平滑速度证据）
5. **谱特征 / 学习模型** —— 仅当下一步要"不止跌倒、要姿态/活动分类"时考虑
