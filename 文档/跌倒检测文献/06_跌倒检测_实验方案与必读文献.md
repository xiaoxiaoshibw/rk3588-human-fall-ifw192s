## 1. 目标澄清与场景定义

在动手前，先把"跌倒检测"拆清楚，避免方案走偏：

### 1.1 任务定义（按 Lai 2026 §3.4 映射）

| 维度 | 你的方案 | 建议先想清楚 |
|---|---|---|
| **任务粒度** | 二分类（跌倒 vs 非跌倒）vs 多分类（跌倒 / 坐下 / 蹲下 / 躺卧……）| 多分类能减少"坐在地上"被误判为跌倒的情况（文献 S1 ST-GCN §1 提到）|
| **人数** | 单人 vs 多人 | 多人场景难度跃升，Lai 2026 §6 指出这是公开数据集的共同短板 |
| **环境** | 室内（家居 / 病房 / 卫生间）vs 室外 | 室内更可控，卫生间是高隐私需求场景，LiDAR 比摄像头更合适 |
| **人群** | 老年人 / 病人 / 普通成人 | 老年人步态更慢、姿态更复杂，建议先按"普通成人"做 baseline，再扩展 |
| **实时性** | 离线分析 vs 边缘实时告警 | 实时告警需 ≤500 ms 推理，端侧 NPU 部署 |

### 1.2 关键评估指标（基于 Lai 2026 §2 + 综述标准）

- **Recall（召回率）**：跌倒事件的"漏报率必须低"——漏报代价远高于误报（救命场景）。
- **Precision（精确率）**：避免"坐在地上"被误判为跌倒（误报打扰）。
- **F1 / F2-score**：兼顾 Precision 与 Recall，F2 更重视 Recall。
- **Alert Latency**：从跌倒发生到告警输出的延迟（毫秒）。
- **Daily False Alarm Rate**：每天误报次数（建议 ≤1 次/天）。

> **重要参考**：Lai 2026 Table 2 给出 LiDAR 活动识别准确率范围与 IMU/视频相当（52–98%），但**没有给跌倒专用指标**——意味着跌倒检测需要你自己复现评测。

## 5. 阶段 2：点云预处理

> **核心依据**：Lai 2026 §3.2 给出 16 篇检测论文的共识——**三步法**（顺序执行）。

### 5.1 第一步：背景减除（Background Subtraction）

**目的**：去掉静态家具、墙壁，保留人体动态点。

**方法**：
1. 采集"空房间"背景点云（无人在场时录 5–10 秒）。
2. 对每帧点云：保留距离背景 > 阈值（如 0.1 m）的点。
3. 进阶：用高斯混合模型（GMM）或 voxel hash 做动态背景建模。

**Python 实现（基于 Open3D）**：

```python
import open3d as o3d
import numpy as np

def background_subtraction(current_pc, background_pc, threshold=0.1):
    """Lai 2026 §3.2 第一步：去除静态背景"""
    # 建立背景 KD-Tree
    bg_tree = o3d.geometry.KDTreeFlann(background_pc)
    points = np.asarray(current_pc.points)
    mask = np.zeros(len(points), dtype=bool)
    for i, p in enumerate(points):
        [k, idx, dist] = bg_tree.search_radius_vector_3d(p, threshold)
        mask[i] = (k == 0)  # 背景中无近邻 → 保留为前景
    return current_pc.select_by_index(np.where(mask)[0])
```

**避坑**：
- 室内家具挪动后**需要重新采集背景**。
- 多人场景下"背景"不是静止的——背景减除会失效，此时改用**实例分割**（如 Lai 2026 提到的 DBSCAN 聚类）。

### 5.2 第二步：聚类（Clustering）

**目的**：把前景点云分成多个簇，每簇对应一个人。

**方法**：
- **DBSCAN**：密度聚类，最常用（ε = 0.2 m, min_samples = 50）。
- **Euclidean Clustering**：基于固定距离阈值的简单聚类。
- **Forest Path Cutting**（Krebs 2024）：多人跟踪专用。

**Python 实现（基于 sklearn + Open3D）**：

```python
from sklearn.cluster import DBSCAN

def cluster_persons(pc, eps=0.2, min_samples=50):
    """Lai 2026 §3.2 第二步：分簇"""
    points = np.asarray(pc.points)
    clustering = DBSCAN(eps=eps, min_samples=min_samples).fit(points)
    labels = clustering.labels_
    # 每个簇选最大簇作为单人点云
    unique_labels = set(labels) - {-1}
    clusters = [pc.select_by_index(np.where(labels == l)[0]) for l in unique_labels]
    return sorted(clusters, key=lambda c: len(c.points), reverse=True)
```

### 5.3 第三步：点云重采样（Point Cloud Resampling）

**目的**：把不同帧点云统一到固定点数（如 4096），便于喂神经网络。

**方法**：
- **随机降采样**：`random.sample(points, 4096)`
- **体素降采样**：`voxel_down_sample(voxel_size=0.02)`
- **最远点采样（FPS）**：PointNet++ 使用，质量更高

**Python 实现**：

```python
def resample_pc(pc, n_points=4096, method='fps'):
    """Lai 2026 §3.2 第三步 + TPAMI §6.1（大点云高效处理）"""
    points = np.asarray(pc.points)
    if len(points) >= n_points:
        if method == 'random':
            idx = np.random.choice(len(points), n_points, replace=False)
        elif method == 'fps':
            # 最远点采样（PointNet++ 用）
            idx = farthest_point_sample(points, n_points)
        else:
            idx = np.random.choice(len(points), n_points, replace=False)
    else:
        # 点数不足 → 重复采样
        idx = np.random.choice(len(points), n_points, replace=True)
    return pc.select_by_index(idx)
```

## 7. 阶段 4：评估与验证

### 7.1 评估指标

```python
from sklearn.metrics import classification_report, confusion_matrix

def evaluate(y_true, y_pred):
    print(classification_report(
        y_true, y_pred,
        target_names=['Non-Fall', 'Fall'],
        digits=4
    ))
    cm = confusion_matrix(y_true, y_pred)
    print("Confusion Matrix:")
    print(cm)
    
    # 跌倒召回率（关键指标）
    recall_fall = cm[1, 1] / (cm[1, 0] + cm[1, 1])
    precision_fall = cm[1, 1] / (cm[0, 1] + cm[1, 1])
    f2_fall = (5 * precision_fall * recall_fall) / (4 * precision_fall + recall_fall)
    
    print(f"\nFall Recall: {recall_fall:.4f}（越高越好，目标 >95%）")
    print(f"Fall Precision: {precision_fall:.4f}")
    print(f"Fall F2-Score: {f2_fall:.4f}")
```

### 7.2 验证协议

| 协议 | 描述 | 严格度 |
|---|---|---|
| **Subject-Dependent** | 同一被试既在训练又在测试集 | 低（容易过拟合）|
| **Subject-Independent** | 测试集被试完全不在训练集 | **高（推荐）** |
| **Cross-Scene** | 不同房间 / 不同家具布置 | 最高（接近真实部署）|

> **Lai 2026 §6 强调**：38 篇纳入研究中，多数在受控条件下采集，Subject-Independent 泛化是公开数据集的共同短板。你的实验**必须报告 Subject-Independent 结果**才有意义。

```
      ↓

│ 边缘 NPU   │ ← 推理（如 NVIDIA Jetson Orin / TI AWR2944 / 地平线 J5/J6）
└─────┬──────┘
      ↓
┌────────────┐
│ 告警网关   │ → 推送手机 APP / 拨打急救 / 通知家属
└────────────┘
```

### 8.2 实时性要求

- **告警延迟 ≤ 500 ms**：跌倒后 0.5 秒内必须识别并告警。
- **窗口推理时间 ≤ 100 ms**：3 秒窗口 @ 10 Hz = 30 帧，需要 < 100 ms 推理完成。
- **PointNet++ + biGRU 单帧推理**：NVIDIA Jetson Orin Nano ~30 ms（参考）。

### 8.3 存储与带宽

Lai 2026 §6 指出：~80,000 点/帧 × 10 Hz × 60 s ≈ 1 GB。

**优化策略**：
- **不下采样太多**：保持原始点云用于告警精度。
- **滑动窗口推理**：只保留最近 3 秒窗口的原始数据。
- **事件触发存储**：仅在检测到疑似跌倒时保存完整点云用于事后分析。

### 必读文献（部署）

- **Lai 2026 §6**：计算负担、边缘部署挑战的原始讨论。
- **TPAMI §6**：大规模点云高效处理（RandLA-Net 等）。

## 10. 常见坑与文献给出的缓解策略

### 10.1 跌倒检测特有的 5 大坑

| # | 坑 | 症状 | 文献缓解 |
|---|---|---|---|
| 1 | **数据不平衡** | 跌倒样本少，模型偏向"非跌倒" | 类别加权 Loss / SMOTE / Focal Loss |
| 2 | **背景干扰** | 家具挪动后误报 | Lai 2026 §3.2 背景减除 + 定期更新背景 |
| 3 | **遮挡** | 部分身体被家具遮挡 → 漏报 | Lai 2026 §3.5 噪声增强 + 多人算法（Forest Path Cutting）|
| 4 | **坐地 vs 跌倒** | 主动坐地被误判为跌倒 | 多分类（坐 / 蹲 / 躺 / 跌）|
| 5 | **Subject-Dependent 过拟合** | 同人测试 99%，跨人 60% | Lai 2026 §6.1 强调 Subject-Independent 协议 |

### 10.2 文献支持的解决方案

| 问题 | 方案 | 出处 |
|---|---|---|
| 数据增强（旋转 / 抖动 / 缩放）| Standard transforms | TPAMI §3.3 + Lai 2026 §3.5 |
| 噪声数据增强 | jitter 68.8 → 30.9 | Lai 2026 §3.5 |
| 多人跟踪 | Forest Path Cutting (Krebs 2024) | `05` §10.2 C1 |
| Subject-Independent 训练 | 严格按被试划分 5-fold | Lai 2026 §2.3 |
| 隐私保护 | LiDAR 不含面部纹理 | Lai 2026 §1 |

### 10.3 跌倒检测特有的工程坑

| 坑 | 原因 | 缓解 |
|---|---|---|
| **跌倒后姿势相同于躺卧** | 模型分不清"躺下"与"跌倒后躺" | 加入"前 1 秒姿态变化率"特征 |
| **老人步态慢，跌倒慢** | 模型对快速动作敏感 | 降低采样率到 5 Hz 或增加时间窗口 |
| **卫生间高隐私场景** | 摄像头被拒 | LiDAR 优势 |

## 11. 下一步建议

### 11.1 如果你打算做研究型论文（3–6 个月）

推荐路径：
1. **第 1–2 周**：读完 Lai 2026 + PointNet++ + ST-GCN，跑通 baseline。
2. **第 3–6 周**：自采或用公开 LiDAR 跌倒数据集，复现 PointNet++ + biGRU baseline。
3. **第 7–10 周**：引入 LiDAR + IMU 融合（LIP 范式）或 Transformer 时序。
4. **第 11–14 周**：在 Subject-Independent 协议下做对比实验。
5. **第 15–20 周**：补实验（多人场景、噪声鲁棒性、消融），写论文。

**潜在创新点**（基于 Lai 2026 §6 的 4 个研究缺口）：
1. **隐私保护联邦学习**（基于 FedDL [A1] 范式）：多个家庭 / 养老院协作训练，不上传原始点云。
2. **ISB 标准关节坐标系集成**（基于 Lai 2026 §6.2）：把跌倒检测的输出与正式生物力学对齐。
3. **多人场景鲁棒性**（基于 Lai 2026 §6.4）：多人同时活动时的跌倒检测。
4. **边缘部署轻量化**（基于 Lai 2026 §6.3）：把模型压到 Jetson Orin Nano 可跑。

### 11.2 如果你打算做产品型 Demo（1–2 个月）

最快路径：
1. **硬件**：Velodyne VLP-16 + NVIDIA Jetson Orin Nano
2. **数据**：用 LiFall 公开数据集训练，或录 50 段自采数据微调
3. **模型**：PointNet++ + LSTM 二分类
4. **告警**：检测到跌倒 → 通过 MQTT 推送手机 APP
5. **指标**：Recall > 95%，Latency < 500 ms

### 11.3 如果你想快速验证想法（1 周）

最快路径：
1. **数据**：下载 MM-Fi 或 LiFall（任一即可）
2. **模型**：直接用 PointNet++ GitHub 代码 + 自加 LSTM 头
3. **训练**：单 GPU 训练 2–4 小时
4. **验证**：跑测试集，看 Subject-Independent 准确率

> **预期结果**：根据 Lai 2026 §4，活动识别准确率应在 80–98% 范围，跌倒检测作为子任务可能略低（70–95%）。具体数字**必须自测**。
